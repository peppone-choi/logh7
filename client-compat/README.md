# LOGH7 성계 표시 호환 모듈

작성자: 최병호 · 2026-10-24

원본 CD 클라이언트의 임시 행성 표시를 서버에서 수신한 정적 거점 배치에 연결하는 x86 `dinput8.dll`이다. 원본 EXE와 데이터 파일은 수정하지 않는다. `DirectInput8Create`는 Windows 시스템 DLL로 전달한다. EXE의 SHA-256이 지정된 CD판과 다르면 게임 후킹을 거부한다.

현재는 기존 x86 MSVC 도구로 네이티브 호출 규약을 맞춘 C++ 호환 모듈이다. Rust 런처는 그대로 사용하며 Frida·Python이 제품 모듈의 실행 의존성으로 들어가지 않는다. 원본 주소에 결합된 초기 구현이므로 다른 클라이언트 버전으로 확장하기 전에 별도 확인이 필요하다.

```powershell
./client-compat/build.ps1 -OutDir E:\logh7\work\compat-build
./client-compat/install-copy.ps1 -ClientRoot E:\logh7\work\client-login-20261024\run-01\client -Dll E:\logh7\work\compat-build\dinput8.dll
```

기존 Visual Studio x86 C++ 도구를 사용한다. 새 도구 설치나 전역 설정 변경은 하지 않는다. 빌드 출력·설치는 저장소 `work/` 아래로 제한한다. 기존 입력 프록시가 있거나 대상 게임이 실행 중이면 설치를 중단한다. 변경 전 기존 프록시는 `exe/` 밖에 보존한다. 되돌릴 때 게임 종료 후 이 모듈을 `exe/` 밖으로 옮기고 기존 프록시가 있었다면 복원한다.

성계 도착·재접속 때 기존 성계 표시 모드를 사용하고, 그리드 표시에서도 가리킨 성계를 그린다. 표시 모드는 기존 미니맵 오른쪽 버튼으로 전환한다. 워프 목적지 선택 모드에서는 호환 배치를 숨겨 원래 입력을 유지한다. 정적 거점이 없으면 행성을 만들어 채우지 않는다. 최대 8개를 넘으면 잘라 그리지 않고 표시를 중단한다.

시설 스폿에서 재접속하면 수신한 현재 스폿 ID를 확인해 원래 시설 배경 모드로 복원한다. 방 이동·배경 파일 선택은 서버의 `0321` 시설 데이터와 원본 클라이언트 로더를 사용한다.

스폿 배경의 얼굴·이름·계급은 원래 인물 창 `00549480`과 얼굴 로더를 사용한다. 회의실 등은 최대 23칸에 표시하고, 로비·광장·공원·기함 부두·접견실 등은 원래 조건에 따라 배경 얼굴을 숨긴다. 이때 같은 스폿 인물 탭에서 확인할 수 있다. 호환 모듈은 공통 인물 수집기 `0054aa10`의 스폿 비교에 방 소유자 비교를 보완한다. 개인실의 소유자 검사도 스폿 ID와 소유자 ID를 비교하던 경로를 바로잡아, 같은 개인실에 방 주인이 있을 때 그 방의 인물을 표시한다. 다른 소유자의 개인실, 자기 자신, 각자 함내를 뜻하는 스폿 0의 인물은 배경과 명단에 섞지 않는다. 얼굴의 크기·배치·클릭 동작·원본 자산은 기존 경로를 유지한다. `evidence:manual`(W p.19의 표시 예외), `evidence:client`(창·표시 조건·비교)

우측 HUD는 현재 위치의 `0317` 그리드가 성계일 때 항성과 그 성계의 `031d` 거점을 표시한다. 지도에서 다른 성계를 가리켜도 현재 위치의 HUD는 바뀌지 않는다. 우주공간에서는 아이콘을 그리지 않으며 성계 진입·재접속 때 다시 표시한다. 거점은 수신 공전 반지름 순으로 배치한다. 원본 HUD의 궤도선 네 개를 넘는 거점 목록은 잘라 표시하지 않고 중단한다.

`senryaku_mainpanel.tga`의 원본 아이콘을 런타임에 읽으며 게임 이미지를 DLL에 넣지 않는다. 모델 번호에 따라 행성/요새 그림을 고른다. 궤도선의 원본 가로 좌표는 426·449·472·496이고 아이콘 중심을 이 선에 맞춘다. 아틀라스에 없는 모델 번호는 회색 실루엣으로 표시한다. 지원 모델의 좌표·변형과 미지원 번호의 처리도 빌드 때 검사한다.

맵의 3D 외형도 같은 `031d` 모델 번호를 CD의 저해상도 모델 표에서 조회한다. 기존 여덟 표시 슬롯을 원본 리소스 관리자를 통해 다시 연결하며, 미지원 번호를 다른 모델로 대체하지 않는다. 반지름·각도·직경은 서버 시드 값을 읽어 표시 축척으로 변환한다. 성계 표시를 전술 상태로 위장하지 않으며 게임 위치·자원·명령 결과를 메모리에서 조작하지 않는다.

HUD와 맵의 외형은 같은 서버 모델 번호를 사용하지만, 원작 서버의 각 행성별 타입 배정과 실제 궤도 값이 복원됐다는 뜻은 아니다. 타입 지정·출처 기록은 [월드 데이터 문서](../docs/protocol/world-navigation.md)를 따른다.

빌드는 다른 x86 실행 파일에서 후킹을 거부하는 검사도 실행한다. 실제 렌더링·입력 검사는 [비활성 데스크톱 실행 규칙](../docs/ops/background-client.md)에 따른다. 원본 게임 자산과 빌드 DLL은 커밋하지 않는다.

연료 보급도 원래 기함 카드의 버튼·확인 창·암호화 전송기를 사용한다. CD의 `004b49d0`은 스택 요청 레코드에서 인물 ID만 초기화하므로, 호환 모듈은 실행 중인 자기 기함 카드인지 확인하고 시간·대기·카드·CP 필드를 초기화해 기존 전송기에 넘긴다. 내부 선택자 `0x52`는 `0x0b02` 명령에 대응한다. 비용·완료 시각·항속은 서버가 결정한다. `evidence:client`

수신 `0b0c`는 기존 디코더가 검증한 유닛 ID·항속을 사용한다. CD 전략 수신기는 UI 이벤트만 전달하므로, 유닛 ID가 캐릭터의 기함 ID와 내장 기함 레코드 모두에 일치할 때만 내장 항속을 갱신한 뒤 원래 이벤트를 호출한다. 다른 위치·CP·함종을 바꾸지 않는다. 다른 EXE나 예상 명령 바이트가 아닌 경우 후킹을 거부한다. `evidence:client`

정보 아이콘의 ‘행성·요새’ 항목은 전용 행성 조회 화면을 연다. 기존 명령 대화창을 빌린 텍스트 나열은 제거했다. 원본 `wakusei_shousai_window.tga` 창틀과 네이티브 GUI 컨트롤을 사용하고, 미사용 슬롯 0x71이 비어 있을 때만 화면을 만든다. 왼쪽에서 성계를 이전/다음으로 탐색하고 선택한 성계의 거점을 궤도 순으로 선택한다. ‘현재 위치’로 자신의 성계를 다시 조회하며, 실제 캐릭터를 이동시키지 않는다. 오른쪽에서 개요·환경/내정·창고·시설/스폿·아군 배치 탭을 전환한다. 버튼과 정보 구획은 `wakusei_parts.tga`의 행성 전용 자산을 사용하며, 원본 한도 150개 아래인 장식 19개로 구성한다. 어두운 버튼 위에 흰 글자를 표시한다. 원본 자산 파일을 가공하거나 수정하지 않는다. 보유 CD의 정보 메뉴 분류 6은 상세 창 호출 없이 선택을 해제하므로, 이 배치는 재구성 설계이며 원래 CD의 행성 상세 화면 실행 코드를 복원했다고 주장하지 않는다. `evidence:client`(분기·자산·GUI API), `evidence:guess`(배치)

선택·새로고침은 기존 암호화 전송기의 `031e`·`0326` 요청을 사용한다. 조건은 선택한 거점 ID·그리드, 창고는 해당 거점·부대 ID 0과 개수를 확인한다. 개요는 조건 응답, 창고는 창고 응답을 받은 뒤 표시하며 이전 선택의 값을 남기지 않는다. 창고는 품목·등급·유닛·척수를 8행씩 표시하고 이전/다음 재고를 제공한다. 병력 번호는 1000 기반을 원래 이름 인덱스로 변환하며, 함선은 원본 창고 응답의 유닛 수·척수를 그대로 표시하고 등급은 비워 둔다. 병력만 응답의 숙련도와 유닛 수를 사용한다. 거점 없음·빈 재고·응답 지연도 전용 영역에 표시한다. 닫기·위치/인물/모드 변경 시 화면을 숨기며, 다시 열면 새로 조회한다. CP·자원·명령 결과는 바꾸지 않는다.

이 화면은 행성 및 창고의 **조회**를 제공한다. 세율 변경·할당·재편성·생산 명령은 별도의 권한과 서버 처리가 필요하다. 원본 할당/편성 UI 자체는 실제로 열었지만 준비 응답과 부대 문맥이 미연결인 상태다. [행성 화면의 구현·검사와 원본 창고 경로](../docs/protocol/world-navigation.md#행성-정보-조회-창-연결-2026-10-25)를 따른다.

조회 버튼과 정보 구획은 원본 `00502fe0`의 분할 배경을 사용한다. 구획은 아틀라스의 테두리와 내부 픽셀을 따로 확대하므로 큰 패널이 인접 부품을 읽지 않는다. 개요는 기본 현황과 담당자 두 구획, 환경·내정은 통치 상태와 자원 구획으로 나눈다. 창고·시설은 표로 전환하며 다른 탭의 구획을 숨긴다. 현재 행성·탭의 강조와 모델 아이콘을 유지한다. 배경 결합은 생성 때만 수행하며 장식은 19개다. 별도 이미지나 전역 렌더링 변경은 없으며 이 배치도 원래 행성 화면 전체의 복원은 아니다.

총독/주지사 카드의 세율 변경(명령 30)은 `planet_tax.h`의 별도 조작 창에 연결한다. 원본 생성기가 실패를 반환하고 원래 활성 명령 목록에서도 빠져 있으므로, 확인한 카드 클릭·활성화 호출만 보완한다. 원본 행성 창틀/버튼과 네이티브 컨트롤로 현재값·변경값·±1/10·실행·닫기·서버 응답을 표시한다. 이는 재구성 UI이며 원래 화면 실행 코드의 복원은 아니다. 원본 통신 객체의 직렬화/암호화를 사용하며 서버가 저장을 확정하기 전에는 성공으로 표시하지 않는다. 조회 창의 세율을 임의로 바꾸거나 카드 클릭만으로 권한을 부여하지 않는다.

원본 GUI 관리자의 ID 범위는 `0..0x72`다. 세율 창은 지원 CD의 전략 화면에서 비어 있고 직접 생성/표시 참조가 없는 `0x70`을 사용하며, 이미 할당돼 있으면 덮어쓰지 않는다. `0x71`은 행성 조회, `0x72`는 게임 설정이다. 범위를 넘는 ID를 추가하지 않는다. 다른 화면·특히 전술 화면에서의 슬롯 사용과 조작 창 확장은 해당 화면 구현 시 별도로 검증해야 한다.

원래 글자 캐시는 UTF-16을 키로 삼지만 일본어 CRT 바이트를 ANSI GDI에 전달한다. 한국어 Windows에서는 일본어가 깨지고 한글이 변환 단계에서 사라진다. 글자 캐시 함수 `004b0960` 안의 변환·폭 측정·출력 네 곳만 연결해 실제 글자를 스레드별로 보관하고 `GetTextExtentPoint32W`·`ExtTextOutW`로 그린다. 기존 한 글자 처리와 ASCII·반각 가나의 폭 구분은 유지한다. 시스템 로캘·글꼴 설치·전역 API·원본 파일은 바꾸지 않는다. 이 수정은 전체 UI 번역이나 입력/채팅의 코드페이지 문제까지 해결한 것으로 간주하지 않는다. `evidence:client`

채팅의 색상 제어 문구 추가에도 별도 변환 손실이 있었다. UI 추가 함수의 `005035d3` 호출은 기존 UTF-16 텍스트를 ANSI로 왕복시키므로, 새 조각만 CP932에서 변환해 원래 UTF-16 추가 함수로 넘긴다. 기존 한글·일본어·이름·색상 코드는 그대로 유지한다. 원본 클라이언트에서 혼합 메시지 수신 표시와 영문 답장을 확인했으며, 한글 IME 입력이나 긴 기록 정리까지 검증한 것은 아니다. [채팅 문서](../docs/protocol/spot-chat.md)를 따른다. `evidence:client`

주변 인물 등장·이탈 알림의 두 호출은 존재하지 않는 constmsg 그룹 118의 항목 58·59를 조회한다. 확인한 호출 두 곳만 연결해 수신 인물의 실제 이름과 한국어 안내를 기존 시스템 메시지 창에 출력한다. 문구는 현재 가시성 동작에 맞춘 설계이며, 원작 문구 복원이 아니다. 이탈 뒤 비활성 인물의 이름도 보존하고 기존 알림 함수의 색상·스크롤·CString 정리를 사용한다. 다른 UI의 `NO DATA`를 일괄 숨기지 않는다. 스폿 얼굴 아래의 한글 이름 표시는 별도 미완료다. `evidence:client`(조회·렌더링), `evidence:guess`(문구)

전략 탭·카드 설명이 시스템 설정 문구를, 공통 결정/취소 버튼이 로그인 오류 문구를 참조하던 호출 위치도 수정한다. 실제 전략 항목은 `constmsg` 그룹 96, 결정/취소·카드 조건은 그룹 98이다. 확인한 호출 위치만 연결하며 로그인 오류 목록 자체는 바꾸지 않는다. 같은 스폿 인물 탭은 원래 인물 목록·얼굴 로더를 사용한다. 얼굴 표시/숨김 버튼도 원래 기능을 유지한다. `evidence:client`

출항(명령 60)은 기항 `0b00`이 아니라 내부 선택자 `0x42`의 `0b06` 모드 변경을 전송한다. CD의 `004b4a00`은 요청의 카드 번호를 0으로 보내므로, 자기 캐릭터·함장 카드의 전략 출항일 때만 초기화한 레코드로 보완한다. 다른 모드/명령은 원래 함수로 전달한다. 서버가 권한과 현재 부두를 검사하고 저장한 결과로 위치를 바꾼다. `evidence:client`

기항 대상 선택창은 원래 목록·선택 ID·조회·결정/취소 동작을 유지하고, 거점명과 상세 표시를 보완한다. 목록의 이름 생성 세 곳과 문자열 변환 네 곳을 연결해 서버의 UTF-16 거점명을 보존한다. 상세는 선택한 ID와 그리드가 일치하는 조건 및 해당 거점의 창고만 읽는다. 소속·환경·인구·세율·민심·치안·군수물자·식량·광물을 표시하고, 아직 응답이 없으면 조회 중으로 표시한다. constmsg 그룹 95에는 항목 0~3만 있으며, 원본 상세의 4~22 조회가 범위를 벗어난다. 이 그룹을 전역 치환하지 않는다. [기항 선택창 문서](../docs/protocol/world-navigation.md#기항-선택창의-거점명과-상세-정보-2026-10-25)를 따른다. `evidence:client`

기항 접수 `0b00`의 목적지·시각·대기를 받아 HUD의 위치 아래에 목적지와 남은 게임 시간을 표시한다. 초기 접속 응답은 화면 준비보다 먼저 올 수 있어, 표시할 때 현재 인물·그리드를 검사한다. 원래 UTF-16 글자 큐와 게임 시계를 사용하며, 남은 시간이 0이어도 서버의 실제 도착 `0b0b` 전에는 도착 확인 중으로 표시한다. 도착 통지는 원래 수신기에 전달하면서 대기 표시를 해제한다. 원본의 위치·CP·게임 시계를 수정하지 않는다. [재접속 복원](../docs/protocol/world-navigation.md#기항-대기-hud와-재접속-복원-2026-10-25)을 따른다. `evidence:client`(기존 수신기·그리기·시계), `evidence:guess`(HUD 안내 배치)


보유 CD에 없는 게임 설정 탭은 `return_base.h`에서 기존 탭/버튼 생성기로 추가한다. 귀환 대상을 선택·해제하면 원래 송신기의 내부 선택자 `0x77`로 `0f1a`를 전송한다. 서버 응답만 안내에 반영하고 실제 저장값은 `0323`/`0356`의 귀환 필드로 표시한다. 종료·사운드 탭은 유지하며 관련 문자열의 잘못된 그룹만 수정한다. 원본 패치판의 구체적인 레이아웃을 복원한 것은 아니다. [귀환 설정과 한계](../docs/protocol/world-navigation.md#귀환-행성-설정과-저장-2026-10-25)를 따른다. `evidence:client`(송수신·GUI), `evidence:guess`(추가 탭 UI)

부대 정보의 분류 4 선택은 `outfit_information.h`가 기존 상세 GUI 예약 슬롯 13~17을 사용해 원본 탭 프레임·스크롤 표에 연결한다. `outfit_info_data.h`는 비연속 목록 행과 편성 응답 경계를 확인하고 닫기/재열기의 요청 순서를 보존한다. 상세 내용은 재구성 배치이며 서비스 당시 화면을 확인한 것은 아니다. 같은 세력의 편성과 자신의 지휘관 카드가 가리키는 부대 창고만 조회한다. 원본 디코더 뒤에서 응답을 복사하고 GUI 스레드에서 표시하며, 인물·월드·그리드·전술 전환 시 문맥을 폐기한다. 원본 인물/기함 창·창고 수신기는 계속 호출한다. [범위와 검사](../docs/server/unit-production.md#부대-상세의-원본-탭스크롤-컨트롤-연결-2026-10-26)를 따른다.

행성·요새 진입은 `planet_directory.h`의 원본 스크롤 목록 컨트롤을 먼저 연다. 소속·성계·거점·구분·거주·인구를 표시하고 전체/현재 성계를 고르며, 행 선택으로 기존 상세를 새로 조회한다. 상세의 ‘행성 목록’으로 복귀한다. 조건은 네 곳씩 순차 조회하고 미조회·실제 0·응답 없음·사용자 조회 중단을 구분한다. 원본의 600셀 한도와 빈 끝 행 판정 때문에 여섯 열·98개 거점씩 페이지를 나누며, 숨긴 컨트롤의 입력도 끈다. 목록과 상세의 구체적인 배치는 여전히 재구성이다. [원본 컨트롤·데이터와 확인 범위](../docs/protocol/world-navigation.md#원본-목록-컨트롤을-통한-행성요새-탐색-2026-10-26)를 따른다.


행성 상세의 ‘시설·스폿’ 탭은 선택 거점의 `0320→0321` 새 응답을 원본 디코더 뒤에서 읽고, 원본 시설/스폿 이름으로 여덟 행씩 탐색한다. 다른 거점 응답과 잘못된 개수·종류·ID는 목록을 바꾸지 않는다. 방문 장소 조회이며 건설 시설/주둔 병력 조회가 아니다. 원작 상세 배치와 통치자·수비대장·방어 정보 복원은 미완료다. [표시 경로와 검사 범위](../docs/protocol/world-navigation.md#행성-상세의-시설스폿-조회-2026-10-26)를 따른다.


행성 개요의 통치자는 선택 행성의 정규 세력에 맞는 원본 카드 보유 인물 조회 `034e→034f`를 사용한다. 새 응답의 종류·거점 카드 대상 ID를 대조해 이름/미임명을 표시하고, 수신 전과 응답 미확인은 따로 표시한다. 이 명단은 현재 캐릭터 갱신으로 적용하지 않는다. [수신 구조와 확인 범위](../docs/protocol/world-navigation.md#행성-통치자와-원본-카드-보유-인물-조회-2026-10-26)를 따른다.


행성·요새 개요의 수비대장은 부대 지휘관과 별도로 저장된 직위 명단을 조회한다. `PlanetOfficeHolder`는 통치자와 수비대장의 원본 종류·담당 거점 ID를 각각 확인한다. 행성 55/191·요새 52/188을 구분하고, 미임명·조회 중·응답 미확인을 나눈다. 요새 사령관/직무별 명령의 완성은 이 표시 변경에 포함하지 않는다. [저장과 표시 범위](../docs/protocol/world-navigation.md#행성요새-수비대장의-별도-임명과-표시-2026-10-26)를 따른다.

원본 임명 선택창의 직무 정보는 선택 행/주 조회의 카드 번호로 표시한다. 제국 총독의 확인창에는 완료된 선택 결과의 인물·행성·직무 이름을 연결하며 원래 비용·시간·결정/취소를 유지한다. 확인 대상 첫 행의 배치는 표시 보완 설계다. [지원 범위·실제 실행·남은 수도 규칙](../docs/protocol/garrison-appointment.md#선택-정보와-확인-문구-보완)을 따른다.

사임 확인창은 본인이 보유한 카드 종류와 원본 직무 이름을 확인해 대상을 표시한다. 원래 비용·결정/취소와 `0709` 송신을 유지한다. [서버 처리·실제 입력과 미완료 범위](../docs/protocol/office-resignation.md)를 따른다.

행성 상세의 ‘아군 배치’는 원본 `032c→032d`로 선택 성계의 동진영 상비 부대를 조회하고 `032e→032f`로 실제 배치 거점을 대조한다. 선택 행성과 일치하는 편성만 함선 유닛·척수·병력 유닛으로 표시한다. 창고와 개인 기함을 배치 부대로 세지 않으며 전체 응답 전·실제 빈 배치·응답 미확인을 구분한다. [범위와 실행 확인](../docs/protocol/world-navigation.md#행성-상세의-아군-상비-부대-배치-2026-10-26)을 따른다.

배치된 부대 이름을 누르면 같은 실제 ID의 기존 부대 상세 창을 연다. 네이티브 탭 갱신기로 함선·병력·창고를 전환하고 닫으면 같은 행성·목록 페이지에서 다시 조회한다. 선택 거점과 다른 편성 응답은 표시하지 않으며, 이전 상세 응답이 남으면 배치 조회를 기다린다. 기존 정보 메뉴 진입과 창고 권한 검사를 유지한다. [연결 범위](../docs/server/unit-production.md#행성-배치-목록에서-부대-상세-연결-2026-10-26)를 따른다.
