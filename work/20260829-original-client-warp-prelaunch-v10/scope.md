# Scope

## Question

Can a fresh, same-run, input-free WARP-stage prelaunch candidate close the current identity, manager67/manager65, foreground, and initial MVB installation prerequisites without issuing a permit or consuming the one authorized physical activation?

## Included

- Read-only VMware running-state and guest-operation checks against `oracle-win11-hd-re.vmx`.
- Fresh G7MTClient/x32dbg PID, start time, executable hash, module base/size, HWND ownership, foreground, interactive session, and client TCP-state collection.
- Current host listener/process evidence for port 47900 and fresh heartbeat/connection disposition.
- Existing verified manager67/manager65 collector and independent hit-region composition.
- Existing no-command debugger foreground probe composition.
- Existing movement hardware-breakpoint receipt-v2 initial-install composition, if every earlier gate passes.
- TDD, independent read-only review, final receipt, report, handoff, and bounded commit.

## Excluded

- Physical game activation, automatic input, retry, permit chaining, or permit issuance.
- DESTINATION, CONFIRM, movement command, packet, queue, or movement-pixel claims.
- Process-memory writes, software breakpoints, binary/resource patching, VM lifecycle changes, or server/protocol/DB changes.
- Reuse of stale PID/HWND/module/pointer/rectangle or the consumed historical permit.

## Acceptance

- Every observation is timestamped and bound to the current executable hash and fresh process/window/module identity.
- No debugger attach or breakpoint command occurs before listener/heartbeat, manager, hit-region, foreground, and independent-review gates pass.
- Missing heartbeat or another earlier gate fails closed without input, attach, breakpoint installation, or permit issuance.
- All operation counters distinguish guest operations, read-only process-memory reads, debugger commands, breakpoint installation, captures, and physical inputs.
