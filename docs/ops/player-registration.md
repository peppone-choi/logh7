# 플레이어 가입과 운영 계정 관리

작성: Peppone Choi ([peppone-choi](https://github.com/peppone-choi))

가입 페이지에서 만든 아이디와 비밀번호를 게임 클라이언트의 로그인 화면에 입력한다. 런처에서 시험 서버 주소를 `127.0.0.1`, 로그인 포트를 `51140`으로 설정한다.

## Windows에서 실행

JDK 25와 Node.js 20.9 이상을 사용한다. 아래 명령은 저장소 루트에서 각각 별도 PowerShell로 실행한다. 시험용 포트는 게임 로그인 `51140`, 운영 `51141`, 업데이트 `51142`, 세션 `51143`, 가입 내부 API `51144`, 웹 `48174`다.

첫 번째 PowerShell에서 새 시험 저장소와 운영 토큰을 준비하고 게임 서버를 실행한다.

```powershell
$state = Join-Path (Get-Location).Path 'work\registration-local'
New-Item -ItemType Directory -Force $state | Out-Null
$env:JAVA_HOME = 'E:\Tools\jdk-25.0.4.1+1'
$env:GRADLE_USER_HOME = 'E:\Tools\gradle-home'
$env:TEMP = 'E:\Tools\tmp'
$env:TMP = $env:TEMP
$env:LOGH7_ENV_FILE = Join-Path $state 'server.env'
$env:LOGH7_ACCOUNTS_FILE = Join-Path $state 'accounts.properties'
$env:LOGH7_OPS_TOKEN_FILE = Join-Path $state 'ops-token.txt'
$env:LOGH7_OPS_AUDIT_FILE = Join-Path $state 'ops-audit.jsonl'
if (!(Test-Path $env:LOGH7_ACCOUNTS_FILE)) {
    New-Item -ItemType File $env:LOGH7_ACCOUNTS_FILE | Out-Null
}
if (!(Test-Path $env:LOGH7_OPS_TOKEN_FILE)) {
    [IO.File]::WriteAllText($env:LOGH7_OPS_TOKEN_FILE, [guid]::NewGuid().ToString('N'))
}
$env:LOGH7_BIND_ADDRESS = '127.0.0.1'
$env:LOGH7_OPS_BIND = '127.0.0.1'
$env:LOGH7_GAME_PORT = '51140'
$env:LOGH7_OPS_PORT = '51141'
$env:LOGH7_UPDATE_PORT = '51142'
$env:LOGH7_SESSION_PORT = '51143'
$env:LOGH7_REGISTRATION_PORT = '51144'
Set-Location server
.\gradlew.bat :app:installDist
if ($LASTEXITCODE -eq 0) { .\app\build\install\app\bin\app.bat }
```

두 번째 PowerShell에서 가입 웹을 실행한다.

```powershell
$env:npm_config_cache = 'E:\Tools\npm-cache'
$env:TEMP = 'E:\Tools\tmp'
$env:TMP = $env:TEMP
$env:NEXT_TELEMETRY_DISABLED = '1'
$env:LOGH7_GAME_PORT = '51140'
$env:LOGH7_REGISTRATION_PORT = '51144'
Set-Location web
npm.cmd ci
if ($LASTEXITCODE -eq 0) { npm.cmd run dev }
```

- 플레이어 가입은 [http://127.0.0.1:48174/](http://127.0.0.1:48174/)에서 연다.
- 가입을 마치면 런처에 입력할 서버 주소와 로그인 포트가 표시된다. 웹의 `LOGH7_GAME_PORT`에 게임 서버와 같은 포트를 넣는다. 웹에 포트를 설정하지 않으면 가입한 서버의 주소와 포트를 확인하라는 안내가 나온다.
- 기존 게임 비밀번호는 [변경 화면](http://127.0.0.1:48174/password)에서 아이디와 현재 비밀번호를 확인한 뒤 바꾼다. [복구 화면](http://127.0.0.1:48174/password/recovery)에서 현재 비밀번호로 일회용 복구 코드를 발급하거나, 미리 보관한 코드로 비밀번호를 재설정할 수 있다.
- 운영 계정 관리는 [http://127.0.0.1:51141/admin](http://127.0.0.1:51141/admin)의 「계정」에서 한다. 토큰으로 접속할 때는 Basic 인증의 사용자명에 임의의 값, 비밀번호에 `work\registration-local\ops-token.txt`의 값을 입력한다. 변경 폼의 운영자 이름은 감사 기록에 남는다.
- 종료할 때는 두 PowerShell에서 각각 `Ctrl+C`를 누른다.

## 계정 처리

가입과 운영 계정 관리는 같은 게임 서버 프로세스의 계정 파일을 공유한다. 가입 직후 재시작 없이 게임에 로그인하고, 인증된 운영자는 기존 화면에서 새 게임 계정을 조회·재설정·삭제할 수 있다. 비밀번호는 기존 방식인 PBKDF2 해시로 저장한다. 등록 요청이 중복되면 먼저 저장한 계정이 유지된다.

가입 기능은 `LOGH7_REGISTRATION_PORT`를 설정하면 켜진다. 게임 계정 파일, 운영 인증과 감사 파일이 필요하다. 운영 토큰·운영자 자격 증명은 별도 파일로 관리하며 웹 프로세스에는 가입 API 포트만 전달한다. 계정 파일 하나당 게임 서버 프로세스 하나를 사용한다.

가입을 켠 상태에서 운영자가 삭제한 ID는 예약된다. 목록과 로그인에서 사라지며, 같은 이름을 되살릴 수 있는 경로는 인증된 운영자의 계정 설정이다. 예약 기록은 가입을 켠 뒤의 삭제부터 쌓이므로, 과거에 지운 ID와 캐릭터가 남아 있는 파일 대신 위 절차의 새 시험 저장소를 사용한다.

플레이어 비밀번호 변경은 현재 비밀번호 확인과 새 해시 저장을 계정 파일의 같은 잠금 안에서 처리한다. 다음 게임 로그인부터 새 비밀번호를 사용한다. 틀린 현재 비밀번호와 등록되지 않거나 삭제된 아이디에는 같은 안내를 표시한다. 웹 비밀번호 변경은 서버 프로세스에서 1분마다 계정당 5회, 전체 60회로 제한한다.

## 확인 결과

헤드리스 Chrome에서 키보드 이동·포커스, 비밀번호 표시, 320px 및 글자 200%, 빈 값·형식 오류·중복·제출 대기·성공을 확인했다. 초기·오류·성공 화면의 axe 검사에서 해당 WCAG 규칙 위반은 0건이었다. 실제 격리 서버에서 웹 가입 직후 기존 게임 게이트웨이의 암호화 요청이 성공(`0x7001`)했고, 틀린 비밀번호는 거절(`0x7002`)됐다. 운영 화면의 무인증 차단과 인증 후 조회·재설정·삭제, 삭제한 ID의 재가입 거절도 확인했다. 실제 스크린리더 실기는 미확인이다.

### 필수 입력 안내와 좁은 화면 (2026-11-08)

빈 항목을 서버에 보내기 전에 해당 입력란으로 이동해 무엇을 입력할지 안내한다. 포커스가 이미 입력란에 있으면 상태 영역으로 오류를 알린다. 헤드리스 Chrome에서 키보드만으로 필수 입력·형식·중복 오류를 확인하고 가입을 마쳤다. 320px에서 글자를 200%로 키워 가입·비밀번호 변경 화면의 조작 요소가 패널 안에 들어오는지 확인했다. 가입 직후 같은 격리 서버에서 암호화 로그인 성공(`0x7001`)과 틀린 비밀번호 거절(`0x7002`)을 확인했다. 시험용 운영 토큰과 비밀번호는 웹 응답과 서버 로그에서 검출되지 않았다. 이번 변경의 원본 클라이언트와 실제 스크린리더 실기는 미확인이다.

### 가입 결과를 받지 못했을 때

가입 결과를 확인할 수 없으면 같은 아이디와 비밀번호로 다시 시도한다. 같은 화면에서 재시도해 이미 등록된 아이디라는 응답을 받으면 처음 가입할 때 입력한 비밀번호로 게임에 로그인해 본다. 처음부터 중복 응답을 받은 경우에는 다른 아이디를 입력한다.

별도 로컬 서버에서 계정 저장 직후 브라우저로 가는 성공 응답을 끊었다. 같은 아이디로 재시도하면 로그인 안내가 표시됐고, 처음 입력한 비밀번호로 암호화 게임 로그인(`0x7001`)이 성공했다. 계정 파일 저장 실패 시 입력이 유지되고 재시도할 수 있는 경로도 확인했다. 320px·1280px, 글자 200%, 키보드와 주요 상태의 axe 검사를 통과했다. 이 변경에서는 원본 화면과 실제 스크린리더를 다시 실행하지 않았다.

가입 완료 화면에 표시된 주소와 포트로 격리 서버에 접속해 새 계정의 암호화 로그인 성공과 틀린 비밀번호 거절을 확인했다. 웹에서 포트 설정을 생략했을 때의 일반 안내, 320px에서 완료 화면의 글자 200% 확대, 키보드 포커스와 axe 검사도 통과했다.

### 웹 가입부터 원본의 첫 워프까지 (2026-11-07)

빈 계정 파일과 새 시험 월드로 실행한 로컬 서버에서 브라우저 가입 성공과 비밀번호 해시 저장을 확인했다. 같은 서버를 재시작하지 않고 설정한 주소와 포트로 릴리스 런처를 실행해 새 계정으로 로그인했다. 원본에서 은하제국 평민 소위를 등록하고 1920×1080 전략 화면에 진입했다.

함장 카드로 발할라의 인접 칸에 워프한 뒤 게임 메뉴로 정상 종료했다. 서버를 내리고 저장을 열어 국가 2·계급 13, 위치 2487→2488, MCP 1000→960, 항속 1000→900, 이동 1회, 예약 없음을 대조했다. 가입 성공과 원본 화면은 `work/web-signup-native-20261107`에 보존했다. 새 PC 설치와 공개 배포 검증은 남아 있다.

### 플레이어 비밀번호 변경 (2026-11-07)

헤드리스 Chrome에서 같은 사이트로 가입하고 비밀번호를 바꿨다. 확인란 불일치 시 요청이 생략되고, 틀린 현재 비밀번호는 거절되며, 여섯 번째 시도는 재시도 안내와 함께 제한되는 것을 확인했다. 키보드 이동과 오류·성공 포커스, 320px에서 글자 200%로 표시, 초기·오류·성공 화면의 axe 검사를 통과했다. 재시작 없이 게임 게이트웨이의 암호화 로그인에서 이전 비밀번호 거절(`0x7002`)과 새 비밀번호 성공(`0x7001`)을 확인했다. 스크린리더 실기는 미확인이다.

후속 원본 시험에서는 앞서 가입과 첫 워프를 마친 계정·인물의 저장 사본을 사용했다. 웹에서 비밀번호를 바꾸고 이전 비밀번호로 로그인하면 640×480 오류 창에 아이디·비밀번호 확인과 점검 중 재접속 안내가 표시된다. 결정으로 입력 화면에 돌아와 같은 게임 프로세스에서 새 비밀번호로 로그인했다. 기존 인물 카드와 1920×1080 전략 화면을 확인하고 정상 종료했다. 저장 재개방에서도 기존 인물, 위치 2488, MCP 960, 항속 900, 이동 1회가 일치했다. 원본 해시·시작 전 메모리 전용 오디오·소유 프로세스 정리 검사도 통과했다.

### 일회용 코드로 비밀번호 복구 (2026-11-08)

가입 직후 또는 비밀번호 복구 화면에서 현재 비밀번호로 22자 복구 코드를 발급한다. 화면에 나온 코드를 비밀번호와 별도로 보관한다. 비밀번호를 잊으면 같은 화면에서 아이디·복구 코드·새 비밀번호를 입력한다. 복구 후 런처에서 새 비밀번호로 로그인하고 다음 복구에 쓸 코드를 다시 발급한다. 코드도 잃었다면 운영자에게 본인 확인과 복구를 요청한다.

계정 하나에 활성 코드 한 개를 둔다. 새 코드 발급, 비밀번호 변경·재설정 또는 계정 삭제 시 이전 코드는 폐기된다. 서버는 안전한 난수 128비트로 코드를 만들고 계정 파일에 SHA-256만 저장한다. 새 비밀번호 저장과 코드 폐기는 같은 원자적 파일 교체에서 처리한다. 복구 전 로비·게임 연결과 입장권은 재설정 시 무효화된다. 발급은 기존 비밀번호 변경 한도를 공유하며, 재설정에는 별도 계정당 분당 5회·전체 분당 60회 제한을 둔다. 없는 계정과 틀리거나 사용한 코드에는 같은 오류를 보낸다. [OWASP 비밀번호 복구 지침](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

복구 코드가 있는 계정 파일은 이전 서버에서 암호를 해석할 수 없으므로 전환·복귀에 `--accounts`를 넘겨 확인한다. 백업은 비밀번호 해시와 복구 코드 해시를 함께 보존한다. 오래된 계정 백업으로 복구하면 당시 비밀번호와 복구 코드 상태도 복원된다. [운영 절차](backup.md#세션-저널과-계정-저장의-릴리스-전환-검사-2026-11-08)

로컬 헤드리스 Chrome에서 가입→발급·재발급→이전 코드 거절→새 코드로 재설정과 재사용 거절을 확인했다. 320px·글자 200%와 키보드 포커스, 주요 상태의 axe 검사도 통과했다. 시험 비밀번호·복구 코드·운영 토큰은 서버 로그와 웹 로그에서 검출되지 않았다. 암호화 통신에서 이전 비밀번호 거절, 새 비밀번호 로그인, 이미 연결된 로비·게임 연결 종료, 기존 입장권 거절과 다른 계정의 연결 유지를 확인했다. 공개 HTTPS 환경은 별도 확인 범위다.

같은 격리 서버에 원본 CD 사본으로 접속했다. 이전 비밀번호는 한국어 로그인 오류를 표시했고, 새 비밀번호는 1024×768 로비를 열었다. 신규 시험 계정으로 진행했으며 게임 진입 전까지만 확인했다. 캡처는 `work/player-recovery-20261108/run-103434ed`에 보존했다. 비활성 데스크톱 시험에서 시작 전 메모리 전용 오디오, 원본 해시 보존과 소유 프로세스 정리를 확인했다.
