# 국가 이미지 운영

작성: Peppone Choi ([peppone-choi](https://github.com/peppone-choi)) · 2026-11-07.

`/admin/images`에서 PNG를 등록하고 이름·설명·파일을 수정한다. 원본은 국가 정의 DB에
보관하며 수정할 때마다 새 버전을 만든다. 이전 버전의 미리보기와 복원도 같은 화면에서 한다.
이미지 키와 용도는 등록 후 유지한다. 삭제 대신 국가 연결을 해제해 기본 문양으로 돌아간다.

최대 파일은 4 MiB, 가로/세로는 각각 2048 이하인 PNG다. 투명도와 원본 바이트를 보존하고
비율을 유지해 32×32 게임 표시본을 만든다. 전략 지도는 지도 아이콘을 우선하고 없으면 국가
문장을 사용한다. 전술 함정 라벨은 국가 문장을 사용한다. 세션 선택·캐릭터 생성·추첨은 문장,
지도 아이콘, 국가 프로필의 기본 문양 순으로 사용한다. 게임에서는 기존 국가색 처리와 같이
회색 명암과 투명도에 국가색을 입힌다. 반란 표시는 기존 구분을 유지한다.
깃발도 등록·수정·연결할 수 있으나 실제 깃발 화면, 함정 외형·NPC 초상 연결은 남아 있다.

## 저장과 접근

기존 국가 정의 DB의 V1~V3에 `server/persistence/src/main/resources/db/migration/V5__country_images.sql`을
한 번 적용한다. V4 시설 정의와 독립적이다. 기존 `LOGH7_DEFINITIONS_JDBC_URL` 및 DB 계정을 사용한다.
V5가 없거나 DB에 연결할 수 없으면 이미지 편집은 사용할 수 없으며 게임은 기본 문양 또는 마지막
정상 게시본을 유지한다. 이미지가 들어 있는 백업을 복원할 DB에도 V5를 먼저 적용한다.
기존 정의 DB 백업은 같은 스키마의 모든 테이블을 포함하므로 원본과 이력도 포함한다.

`nation_asset_pack`·`nation_asset`의 경로와 해시는 현재 PNG에 대응한다. 실제 바이트와 표시본은
`nation_image_version`, 현재 버전은 `nation_image_current`가 보관한다. 과거 파일과 정보는 수정하지 않는다.
복원도 새 개정이며, 파일 없는 정보 수정은 현재 PNG를 보존한다. 이력과 원본이 쌓이는 DB 용량은
기존 백업·디스크 경보와 함께 관리해야 한다.

국가 연결은 그 국가 전용 자산 프로필을 만든다. 공용 제국/동맹 프로필과 같은 프로필을 쓰는
다른 국가를 함께 바꾸지 않는다. 국가 ID·거점·인물·계급·함정 모델은 이 작업으로 수정하지 않는다.
국가 정의 개정 행으로 편집 순서를 직렬화하고 폼의 이미지 개정 또는 국가 정의 개정이 다르면
409를 반환한다. 감사의 요청 기록이 저장돼야 수정하며 결과도 기록한다. 이미지 바이트·토큰은
감사 로그에 넣지 않는다.

운영 API의 기존 Bearer/운영자 인증과 같은 출처 검사를 적용한다. 이미지 파일 미리보기도 인증이
필요하며 `image/png`와 `nosniff`, `no-store`로 응답한다. 외부 URL·로컬 파일 경로를 읽지 않는다.

| 경로 | 기능 |
| --- | --- |
| `GET /admin/images` | 목록·현재 정보·이력·국가 연결 폼 |
| `GET /admin/images/file/{key}?revision=N` | 현재 또는 지정한 버전의 PNG |
| `POST /admin/images/save` | 등록, 정보 수정, PNG 교체 |
| `POST /admin/images/restore` | 과거 버전을 새 개정으로 복원 |
| `POST /admin/images/bind` | 국가의 문장/깃발/지도 슬롯 지정·해제 |

POST는 같은 화면의 URL 인코딩 폼을 사용한다. 파일만 Base64 `png` 필드이며 서버는 요청 크기·PNG
시그니처·압축 해제 전 크기·실제 읽기를 검사한다. 각 폼은 `operator`와 `revision`을 보낸다.
등록은 이미지 개정 0, 나머지는 현재 이미지 개정이다. 국가 연결의 `revision`은 국가 정의 개정이다.

## 게임 전송

원본 호환 계층은 `032e/032f` mode17을 명시적으로 조회한다. 원본 PNG·경로·DB 접속정보를 보내지 않는다.
현재 표시본과 기본 문양만 게임 연결로 보내며 국가색은 기존 mode4, 기본 문양/이름/역법은 mode16을 사용한다.
이미지 폼과 타이머가 DB 게시본을 갱신하고, DLL은 국가 정의 개정이 바뀌면 이미지를 다시 받는다.
전체 전송의 국가·nonce·개정·순서·크기·지문을 확인한 뒤 교체한다. 수신 중이거나 실패한 전송으로
화면을 비우지 않으며, 연결 해제는 정상적인 빈 표시본으로 전달한다. 그래픽 자원은 UI 스레드에서 만든다.

mode17 요청은 국가 ID와 nonce(1~65535)다. 응답은 전송용 power2이고 실제 소속 코드가 아니다.
kind0/number0의 10필드는 `CI1`, 정의 개정 앞12/나머지, 바이트 수, FNV-1a32(부호 없는 10진),
Base64 문자 수, 조각 수, `32`, 빈 칸 둘이다. 헤더 멤버 ID는 1~10, kind는 0~9다.
kind1 데이터의 number는 0부터, 멤버 ID는 전체 조각 순서 1부터이며 kind/rank는 0이다.
각 멤버는 Base64 최대 12자, 프레임은 최대 10멤버다. 데이터는 버전1·플래그(문장1/지도2) 두 바이트 뒤
문장·지도 순서의 RGBA 4096바이트다. 없으면 버전1/플래그0 두 바이트만 보낸다.
최대 8194바이트·데이터92프레임과 헤더1프레임이다. 같은 국가라도 반란 문양은 이 파일로 덮지 않는다.

## 현재 확인

`work/country-image-assets-20261107`의 별도 DB와 월드 사본에서 검사했다. 운영 브라우저에서
문장 L·지도 +·깃발 △ 등록과 국가42 연결, PNG 교체, 이미지 정보만 수정, 이력 미리보기와 복원을 확인했다.
1920×1080 원본 클라이언트의 전략 지도에서 +→△ 교체, 지도색 변경, 이전 PNG 복원, 연결 해제에 따른
문장 L과 기본 제국 문양 복귀를 확인했다. 전술 화면에서 문장 L→△→L과 국가색을 확인했고,
빔으로 적함 한 척을 격침한 뒤 전략 지도로 돌아왔다. 서버와 클라이언트를 다시 시작한 뒤에도
지도에 하늘색 +가 표시됐고, 저장의 실제 국가42·제국 함정 양식·격침 결과가 유지됐다.
암호화 통신을 다시 해독해 완성 전송 11건의 픽셀을 DB와 대조했다.

PNG·투명도·게시본 역행 방지, 프로토콜, 실제 PostgreSQL의 이력/교체/복원/동시 수정과 공용 프로필 보호,
운영 API의 인증·출처·잘못된 파일·오래된 수정·HTML 이스케이프 검사가 통과했다.
2026-11-07 `work/lobby-country-emblems-20261107`의 별도 DB·두 월드와 원본 로비에서 확인했다.
Alpha·Beta 세션 선택과 Beta 캐릭터 생성, Alpha 캐릭터 추첨에서 실제 국가42의 등록 문장을 표시했다.
Beta 선택 화면을 열어 둔 채 운영 API로 문장을 교체하고, 문장 해제 후 지도 아이콘, 두 이미지 해제 후
기본 제국 문양으로 돌아가는 것을 확인했다. 이후 이미지 복원과 국가42 선택을 확인했다.
암호화 통신의 국가42 응답 9건에서 세션 ID·기본 슬롯·표시본 픽셀이 일치했다. 이전 서버 응답에서는
기존 국가 목록을 사용할 수 있었다. [로비 전송 규칙](../protocol/session-login.md)

깃발·함정 외형·초상 표시와 국가별 생성 출신·얼굴·추첨 후보 규칙은 남아 있다.
