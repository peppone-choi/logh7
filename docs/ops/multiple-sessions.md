# 여러 세션 운영

작성자: Peppone Choi ([peppone-choi](https://github.com/peppone-choi))

`LOGH7_SESSIONS_FILE`에 [예시 설정](../../config/sessions.example.properties)의 사본을 지정하면 한 프로세스에서 여러 월드를 실행한다. 빈 값이나 미지정은 기존 단일 세션 실행을 유지한다. 계정 파일과 운영자 설정은 공통이며, 클라이언트는 어느 세션의 로그인 포트로 접속해도 같은 세션 목록을 조회한다.

세션마다 고유 ID(1~65535), 12자 이내 이름, 게임·업데이트·세션·운영 API 포트, 상태 저장 폴더를 지정한다. 설정의 상대 경로는 설정 파일 위치를 기준으로 한다. 공통 `LOGH7_WORLD_FILE`을 시드로 사용하며 `session.<id>.worldFile`로 별도 시드를 지정할 수 있다. 기존 운영 상태를 새 폴더로 자동 이전하지 않는다.

상태 폴더 아래에 캐릭터·항행·자원·세대·월드·세션 저널·감사 기록을 각각 저장한다. 캡처·백업이 활성화돼 있으면 그 경로도 해당 세션 아래에 둔다. 겹치는 포트, 포함 관계인 저장 폴더, 상태 폴더 안의 공통 입력 파일, 외부로 연결된 상태 파일 경로는 실행 전에 거부한다. 검증을 통과한 뒤 상태 폴더를 만든다. 각 운영 API는 자기 월드만 수정한다.

로비는 실제 등록 캐릭터 수와 정규 진영의 지배 거점 수를 세션별로 제공한다. 선택 응답에는 대상 세션의 주소·포트와 세션 ID·현재 세대를 담은 일회용 입장권을 반환한다. 다른 세션, 이전 세대, 재사용한 입장권은 인증 전에 거부한다. 호스트 전용망으로 접속했다면 대상 세션도 같은 어댑터에 바인딩돼 있어야 한다. 종료된 세션은 신규 참가 목록에서 빠지고, 자기 종료 캐릭터 조회는 유지한다.

원본 암호화 프레임 하나에 최대 길이의 종료·캐릭터 레코드가 들어가도록 한 로비에 최대 128개 세션을 등록한다. 게임·채팅·접속자·캐릭터·월드 저장은 공유하지 않는다. 여러 국가를 표시하는 국력 그래프, 동시 접속/이동 전체 정책은 후속 구현 범위이며 체크리스트의 전체 완료 조건은 아직 충족하지 않았다.

공통 계정 평판은 `LOGH7_ACCOUNT_FAME_FILE`에 저장한다. 빈 값은 세션 설정 파일 옆의 `account-fame.properties`를 사용한다. 이 파일은 각 월드 상태 폴더 및 입력 파일과 분리하며, 한 프로세스만 쓰도록 잠근다. Windows의 파일 저장은 기존 운영 방식처럼 `LOGH7_SESSION_DIRECTORY_SYNC=files-only`를 지정한다. 파일 내용은 강제 저장하고 원자적으로 교체하지만 이 모드의 디렉터리 전원 장애 내구성은 OS에 맡긴다.

계정 평판 합계는 공통으로 유지하며 각 월드의 `session/world.identity`와 세대별로 지급·평가 이력을 기록한다. 이 ID는 상태 복구·이동 뒤에도 보존해야 한다. 같은 ID를 가진 상태 사본 두 개를 동시에 실행하면 시작을 거부한다. 기존 월드의 ID가 있는데 공통 평판 파일이 없으면 0점으로 초기화하지 않고 복구를 요구한다. 실행 중 파일이 없어지거나 형식/합계가 손상돼도 지급을 중단한다.

월드 상태의 쓰기 잠금을 확보한 뒤 예전 `characters.properties.fame`를 한 번만 가져온다. 이전 파일은 수정하지 않으며 이후의 단일 원천은 공통 평판 파일이다. 과거 평가의 이전/최종 평판은 당시 정산값을 유지하고, 다른 월드의 추가 지급으로 다시 계산하지 않는다. 열린 캐릭터 저장소와 추첨 자격 조회도 최신 공통 평판을 읽는다.

종료 결과 저장과 평판 지급 사이에 서버가 중단됐을 수 있으므로, 시작 시 종료된 월드의 저장 자원을 불러와 정산한다. 복구·캐릭터 공급자 연결이 끝나기 전에는 시계를 진행하지 않아 자동 다음 세대 전환이 정산보다 앞서지 않게 한다. 지급 이력이 있으면 다시 지급하지 않는다. 지급 내역이 없으면 클라이언트 입장을 열기 전에 정산하며, 조회 응답 자체가 지급을 발생시키지는 않는다.

월드별 실시간 백업에는 `world.identity`가 포함된다. 공통 평판은 월드별 복구로 되돌리지 않는다. 전체 재해 복구용 백업에는 모든 월드를 정지한 뒤 공통 평판 파일과 각 월드 상태를 함께 보존해야 한다. `.lock` 파일은 복구 데이터가 아니다. 공통 평판 파일을 옮길 때도 기존 파일을 먼저 복사해야 하며, 빈 새 경로를 지정해 과거 지급 이력을 버리면 안 된다.

확인: 두 실제 월드의 암호화 TCP 접속, 동일 계정·동일 인물 번호의 서로 다른 소속 및 월드 상태, 다른 대상·재사용·이전 세대 입장권 거부, 세션 종료·재시작·등록 해제 검사. 원본의 신규 캐릭터 생성 경로에서 Alpha/Beta 두 세션과 세션별 거점 집계가 표시됨을 확인했다(`work/multiple-sessions-20261105/two-session-selection.png`).

추가 확인: 원본에서 동일 인물 번호의 두 담당 캐릭터를 별도 표시하고 Beta(하이네센·우주력)와 재접속한 Alpha(발할라·제국력)의 플레이 화면 진입을 확인했다(run-02/03). 공통 평판은 동시 정산·중복 방지·재시작·기존 파일의 이행과 보존·이전 평가 조회·손상/누락 거부를 검사했다. 두 월드의 종료 통지와 공통 로비 조회에 각각 0→10, 10→20의 평판이 유지되는 암호화 TCP 검사도 통과했다. 실제 두 월드를 실행해 예전 평판 7+11이 양쪽 계정 정보 응답에 18로 나오고 재시작 뒤에도 18을 유지함을 확인했다. 두 번째 JVM의 공통 원장 열기는 거부됐다. 이들은 시험 계정과 상태이며 신규 유저의 무주입 생성·양방향 세션 이동 전체 완료를 뜻하지 않는다.

## 같은 계정으로 두 세션에서 플레이 (2026-11-07)

1. 새 캐릭터를 만들려면 로비의 **새 캐릭터 생성**에서 세션을 고른 뒤 등록한다.
2. 다른 세션에서 플레이하려면 현재 게임을 정상 종료하고 같은 계정으로 다시 로그인한다. 로비의 **게임 시작**에서 세션 이름이 적힌 캐릭터를 고른다. 그 세션에 담당 캐릭터가 없다면 먼저 생성한다.

빈 계정 파일과 독립 저장 폴더 두 곳에서 로컬 가입 API로 만든 계정 하나를 사용했다. 원본 클라이언트에서 Alpha의 제국 평민 소위와 Beta의 동맹 시민 소위를 각각 생성했다. Alpha에서 인접 칸으로 워프한 뒤 정상 종료하고 Beta에 들어갔다. Beta의 MCP·항속은 각각 1,000으로 시작했고, 동맹 얼굴과 하이네센의 우주력 표시를 확인했다.

서버 재시작 후 로비의 게임 시작 목록에는 Alpha와 Beta의 캐릭터가 각각 표시됐다. Alpha를 골라 돌아오니 발할라의 워프 도착 위치와 MCP 960·항속 900이 유지됐다. 정상 종료 뒤 저장을 읽어 두 캐릭터의 번호가 모두 10000이어도 국가·함정 스타일·위치·CP·이동 횟수가 서로 분리됨을 확인했다. 실제 화면은 `work/session-player-native-20261107`에 있다. 통화와 직위 전체의 격리는 별도로 확인해야 한다.

### 세션 선택이 거절됐을 때

캐릭터 목록을 열어 둔 사이 대상 세션이 점검에 들어가면 「세션 선택 실패」 창에서 점검 사유를 안내한다. 확인을 누른 뒤 **게임 시작**에서 다른 세션의 캐릭터를 고르거나, 점검이 끝났을 때 다시 고른다. 종료되거나 목록에서 사라진 세션은 현재 참가할 수 없다는 공통 안내를 쓴다.

로컬 원본에서 두 캐릭터가 표시된 목록을 연 뒤 운영 API로 Beta를 차단했다. 호환 패치가 한국어 점검 안내를 띄웠고, 확인 후 같은 로비 연결에서 Alpha를 골라 1920×1080 전략 화면에 들어가 정상 종료했다. 이전 서버의 일반 거절 응답도 한국어 안내와 같은 로비 복귀를 확인했다. 실제 화면은 `work/session-selection-failure-20261107`에 있다. 입장권이 발급된 뒤 시작한 점검은 새 게임 연결에서 별도의 참가 거절로 처리하며, 확인 뒤 게임을 다시 실행한다. 이 입장권 경합은 암호화 TCP 검사에서 확인했다. 선택 뒤 서버 주소에 연결 자체가 실패하는 경로는 추가 확인이 필요하다.
