# 경비대(U-13) 설계안 (2026-10-31, 검토 대기)

작성: Peppone Choi · 2026-10-31

## 1. 근거

### 매뉴얼·공식 사이트 `evidence:manual`

출처는 공식 사이트 update01·update03 스냅샷이다(`E:\manual-variants\wayback\update01-…`, `update03-…`).

- **경비대란:** 플레이어 한 명이 직접 지휘하는 전용 부대다. 상관의 임명이 필요 없다.
  - 부대 종류로 함대·순찰대·지상부대에 경비대가 추가된다.
- **편성 자격:** 함대·순찰대·지상부대에 소속되지 않은 인물만 편성할 수 있다.
- **구매:** `警備艦購入` 명령으로 산다.
  - 수도의 기함공창 스폿에서만 실행할 수 있다.
  - 평가 포인트로 결제한다.
  - 최대 3유닛까지 보유한다.
- **유닛 성질:** 무인 유닛이다.
  - 기존 함종을 바탕으로 하지만 능력이 원래 함종보다 낮다.
  - 유닛당 300척이다.
  - 손실분을 보충하거나 수리할 수 없다. 회복하려면 `警備隊解散` 뒤 다시 구매해야 한다.
  - 승조원을 소비하지 않는다. 재고는 일반 함정과 따로 관리된다.
- **함종 목록:** 진영별로 경비함 26종이 있다.
  - 예: 제국 SS75q1형 전함 20000점·준장 이상, Z82q3형 구축함 2000점·이등병 이상.
  - 예: 동맹 787년 XA형 전함 20000점·준장 이상, 796년 XR형 구축함 2000점·이등병 이상.
  - 각 함종에 가격(평가 포인트)과 필요 계급이 정해져 있다.

### 보유 클라이언트 `evidence:client`

보유 클라이언트(버전 131)의 `constmsg.dat`에서 다음을 확인했다.

- `警備隊`는 직무 설명문(순찰대 지휘관 설명)에만 4회 나온다.
- `警備艦`·`警備艦購入`·`警備隊解散` 문자열은 없다.

즉 구매·해산 UI, 경비함 함종 정의, 부대 종류 표시가 클라이언트에 없다. 패치로 추가된 기능이라 보유 CD에는 빠져 있다.

## 2. 제안

### 2.1 서버 모델

- **부대 종류:** `OutfitKind.GUARD`를 추가한다.
  - 지휘관은 구매한 본인이다. 부대원은 없다.
  - 위치는 본인 기함을 따라간다.
- **유닛:** 경비함 정의 표(26종)를 서버 자료로 둔다. 각 행은 다음 항목을 가진다.
  - 이름, 진영, 가격, 필요 계급
  - 바탕 함종(일반 함종 번호)
  - 능력 감소율(`evidence:guess`: 공격·방어·색적 85%, 속도는 설명에 따라 개별 보정)
- **척수와 회복:** 유닛당 300척, 승조원 0으로 둔다. 보충·수리·재편성의 대상에서 제외한다.
  - 군수물자 보급은 허용한다. 매뉴얼은 보충·수리만 금지한다(`evidence:guess`).
- **구매 조건**
  - 장소: 수도 기함공창 스폿
  - 소속: 함대·순찰대·지상부대 미소속
  - 보유: 경비함 3유닛 미만
  - 계급: 필요 계급 이상
  - 결제: 평가 포인트를 차감한다. 기존 기함 구매와 같은 원자 저장을 쓴다.
- **해산:** 전략 상태이고 전술 중이 아닐 때 어디서나 가능하다(`evidence:guess`).
  - 유닛은 사라지고 환불은 없다.
- **편성 중 제약:** 경비대를 가진 동안에는 다른 부대 가입·직무 임명으로 부대에 소속될 수 없다(`evidence:guess`).

### 2.2 클라이언트 표시와 조작 (호환 DLL)

- **부대 종류 표시:** 클라이언트에 경비대 종류가 없다. 그래서 원본에 있는 순찰대 종류로 보내고, 이름만 "경비대"로 바꿔 표시한다.
  - 전술의 유닛 모델·성능표는 바탕 함종의 것을 쓴다.
- **구매 창:** 기함공창 스폿의 명령 목록에 "경비함 구매"를 추가한다. 기존 기함 구매창의 창틀을 재사용한다.
  - 목록 열: 함종명, 가격, 필요 계급, 구매 가능 여부
  - 확인 뒤 서버로 보낸다.
  - 새 요청은 기존 프로토콜 스키마에 확장 opcode로 정의한다.
- **해산:** 부대 정보창(본인 경비대)에 "경비대 해산" 버튼을 두고, 확인창을 거친다.
- **문구:** 한국어로 표시한다.
  - 거부 사유도 표시한다: 장소, 소속, 3유닛 초과, 계급 부족, 평가 포인트 부족.

### 2.3 범위 밖

- 경비함 고유 3D 모델·아이콘(바탕 함종으로 대체)
- NPC의 경비대 구매

## 3. 결정이 필요한 점

1. 클라이언트에 없는 기능을 DLL로 새 UI(구매 목록·해산 버튼)까지 추가해 구현할지, 아니면 서버 규칙과 시험 경로만 먼저 구현할지
2. 경비대를 원본의 순찰대 종류로 위장해 표시하는 방식이 괜찮은지
3. 무인 능력 감소를 일괄 85%로 둘지, 설명문 특징(예: 장갑 강화형, 속도형)을 함종마다 반영할지
