# 설계안: CP 사용 경험치와 능력치 성장

작성: Peppone Choi · 2026-10-30 · 상태: **승인**(2026-10-30, 제안대로) · 구현 완료

체크리스트 101행("PCP/MCP 결제·2배 대용·경험치 누적을 실제 명령 효과와 같은 저장 경계에 적용")과 178행(능력 성장·경험치)의 남은 핵심이다. 규칙 코드 `AbilityGrowthRules`는 있지만 실제 명령에 연결되지 않았다. 승인 전에는 구현하지 않는다.

## 1. 근거

- W p.15(웹판 신설, 잠정 사양): 전략 커맨드 실행에 쓴 CP가 누적되고, 일정 사용량마다 대응 능력의 경험치 하나가 1 오른다. 경험치 100마다 능력치 +1, 경험치는 0으로 돌아간다. `evidence:manual`
- 대응 능력: PCP는 통솔·정치·운영·정보, MCP는 지휘·기동·공격·방어(W p.14). `evidence:manual`
- 매뉴얼에 없는 값: "일정 사용량"의 크기, 4개 능력 중 어느 것을 올릴지, 2배 대용 결제를 어느 풀로 셀지, 상한. `evidence:guess`로 정해야 한다.
- 이미 있는 저장: 사관학교 구현에서 인물별 능력 경험치(0..99, 8칸)를 `SocialState.academy.experience`에 두었다. 같은 칸을 공용 경험치로 쓴다.

## 2. 제안 `evidence:guess`

- **누적 단위:** 실제로 낸 CP 10마다 경험치 1. 나머지(0..9)는 인물·풀별로 저장해 다음 결제에 이어 센다.
- **풀:** 실제로 차감된 풀을 센다. MCP 명령을 PCP 2배로 대신 냈으면 PCP 쪽 경험치가 쌓인다(낸 풀의 능력이 자란다).
- **능력 선택:** 그 풀의 네 능력 중 현재 경험치가 가장 낮은 것, 같으면 W p.14 순서의 앞쪽. 무작위를 쓰지 않아 재현이 쉽고 고르게 자란다.
- **상한:** 사관학교와 같은 100. 100인 능력은 건너뛰고, 네 능력이 모두 100이면 경험치를 버린다.
- **적용 범위:** 서버의 공통 결제 함수(`CpPayment.charge`)를 거치는 전략 명령 전체. 결제와 경험치를 같은 월드 저장 한 번에 확정해, 실패하면 둘 다 남기지 않는다. 전술 명령·무료 명령·환불은 제외한다.
- **표시:** 기존 캐릭터 갱신 응답의 능력치 값만 바뀐다. 경험치 숫자 표시는 사관학교 창에만 있다.
- **이번 범위 밖:** 월별 나이 효과(젊은/장년의 증감), 격침 시 감소. 별도 설계로 남긴다.

## 3. 검사

- 엔진: 10 단위 누적과 나머지 보존, 2배 대용 시 PCP 풀 적립, 가장 낮은 경험치 선택과 동률 순서, 100 상한 건너뛰기, 결제 실패 시 경험치 무변경, 저장 왕복.
- 실기: 원본 한 개로 MCP 160 명령 한 번 뒤 MCP 능력 하나의 경험치 +16을 사관학교 창에서 보고, 재시작 뒤 보존을 확인한다.

## 4. 결정 요청

1. 누적 단위: CP 10당 경험치 1
2. 2배 대용 결제는 실제로 낸 풀(PCP)로 센다
3. 능력 선택: 그 풀에서 경험치가 가장 낮은 능력(동률이면 앞쪽)
4. 적용 범위: 공통 결제를 거치는 전략 명령 전체(전술·무료·환불 제외)

## 5. 구현 (2026-10-30)

- 결제 기록: 공통 결제 결과를 반영하는 전략 명령 26곳을 `Navigator.paidWith(balance)`로 바꿔, 실제로 줄어든 PCP/MCP를 인물 항행 상태의 누계(`pcpUsed`/`mcpUsed`)에 더한다. 결제와 누계는 같은 저장으로 확정된다. 전술 명령은 별도 차감이라 포함되지 않는다.
- 정산: 월드 엔진의 주기 처리(`CpExperience.settle`)가 누계 10마다 경험치 1을 주고 남은 누계와 능력치·경험치를 한 번의 월드 저장으로 확정한다. 설계의 "결제와 같은 저장"과 달리 한 박자 늦게 반영되지만, 누계와 경험치가 함께 저장되므로 두 번 세거나 잃지 않는다.
- 인물 기록이 없으면 접속 때 게이트웨이가 넘긴 프로필(공적·자금 등 포함)로 만든다. 프로필이 없으면 다음 접속까지 누계를 그대로 둔다.
- 저장: 항행 형식 NAV-19(누계 칸 추가, 0이면 이전 형식 유지).
- 표시: 정산된 인물에게 `0356`을 보내 같은 접속의 인물 정보 경험치가 바로 바뀐다.
- 원본 확인: 근거리 이동 PCP 10으로 정치 경험치 0→1, 재시작 뒤 유지, 다시 PCP 10으로 같은 접속에서 운영 경험치 0→1 표시.

## 6. 영속 월드의 신규 인물 로그인 보완 (2026-11-04)

작성자: Peppone Choi ([peppone-choi](https://github.com/peppone-choi))

실제 파일 저장을 쓰는 월드의 `Join` 분기는 게이트웨이가 전달한 능력 프로필을 경험치 정산에 등록하지 않았다.
전략 인물 기록이 없는 신규 인물은 CP 사용 누계가 보존되지만, 사관학교 같은 다른 행동으로 인물 기록이 생길 때까지
경험치 정산이 미뤄졌다. 메모리 월드에만 있던 프로필 등록을 영속 월드에도 연결했다.
두 경로 모두 입장이 수락된 경우에만 등록하며, 영속 월드는 세션 저장 성공 뒤 등록한다.
중복 접속·오래된 세대의 거절된 프로필이 수락된 프로필을 덮어쓰는 문제도 함께 막았다.

신규 인물·기존 전략 기록 없음·CP 잔여 누계·재정산 무중복과 거절된 로그인 보존을 두 월드 경로에서 검사했다.
수정 전 두 회귀 검사가 실패하고 수정 후 엔진 31개·게이트웨이 로그인 2개 관련 검사를 통과했다.

실기(`work/first-port-20261104`, 수정 후 `work/first-port-fixed-20261104`)는 생성한 동맹 인물 `play2`로
개인 워프 2016→2015, 하이네센 기항, 원거리 이동→사관학교 경계 로비, 근거리 이동→시뮬레이션실을 진행했다.
수정 전 첫 연습 조회는 지휘 경험 0/100이었다. 같은 초기 저장을 복사한 수정 후 시험은 연습 전부터 6/100이었다.
기존 첫 워프 MCP 40과 복귀 MCP 40·기항 MCP 160의 누계가 정상 정산돼 군사 능력 네 개에 6점씩 배분된 결과다.
병기 연습 한 번은 MCP 1000→990, 지휘 경험 6→11, 그날 남은 횟수 5→4로 표시됐다. `evidence:client`

종료 후 실제 저장에서 위치 2015·거점 1177·스폿 11774018·항속 800, 경험 배열 `[1,0,0,0,11,7,6,6]`,
CP 미정산 잔여 PCP 5·MCP 0과 연습 1회를 확인했다. 이동 PCP 15의 1점과 연습 MCP 10의 별도 1점도 포함된다.
기존 캐릭터 파일은 바이트 단위로 보존됐고, 서버 재시작 뒤 원본에서도 시뮬레이션실 배경·지휘 경험 11/100이 복원됐다.
재시작 뒤는 게임 날짜가 다음 날이라 당일 남은 횟수는 5/5로 표시됐다. 연습을 다시 실행한 결과가 아니다.

시험만 배속 600과 별도 세션 저장소를 사용했으며 일반 플레이 서버의 배속·저장은 그대로 유지했다.
실행 네 번의 원본 EXE·호스트 화면/커서 보존, 메모리 전용 음소거와 소유 프로세스 정리를 확인했다.
원작 NPC 배치·일반 부대 가입·다른 강사의 수강은 이 시험 범위가 아니다.
