# 전략 명령·카드/CP 단위

작성: 최병호 · LOGH-29

현재 실제 연결 범위는 아래 연료 보급·성계 기항 연결 절을 따른다. 기존 본문은 규칙 단위의 기초 구현 설명이며 81개 명령 전체의 실제 실행 완료를 뜻하지 않는다.

내정·병참의 CP와 자원 효과를 함께 저장하기 위한 [공통 월드 저장 경계](world-state-storage.md)를 추가했다. 선택 설정을 사용하는 [세율 변경](../protocol/planet-tax.md) 한 경로에 권한·MCP 160 결제·설정 효과의 단일 커밋과 원본 통신/조회 확인을 연결했다. 원본 설명을 찾기 전의 PCP 320 설계값은 교정했다. 총독 임명·실제 카드 조작과 다른 명령의 연결은 미완료다.

전술 게임이 발생한 캐릭터는 CP0을 포함한 모든 전략 커맨드 입력을 거절한다. `submit`의 마지막 필수 인자 `inTacticalGame`은 서버 권위 호출자가 전달하며 기본값은 없다. 역행 시간(`TIME_REVERSED`) 검사 다음, 명령 조회·카드 권한·resolver 호출 전에 `IN_TACTICAL_GAME`을 반환한다. 거절은 잔고·기존 작업·다음 ID·마지막 게임 시각을 변경하지 않는다. `evidence:manual` W p.12. 전술 상태 판정·전술 진입에 따른 기존 WAITING/RUNNING 작업 처리·CP 회복 정지는 미구현이며, `advance`의 기존 동작과 client/wire 연결은 변경하지 않는다.

`engine.strategy`는 기존 `strategy-commands.csv` 81개를 변경 없이 resource로 읽는다. 군별 개수는16/15/8/6/10/12/14다. ID는 군의 고정 영문 키와 원문 명령명이며 행 순서·페이지 이동에 의존하지 않는다. 이것은 client opcode가 아니다. 원문 CP·대기·소요·페이지와07의 상태 표현을 보존한다. 매뉴얼의 구현/미구현/불명/패치와 신규 서버 구현 상태를 혼동하지 않는다. `evidence:manual` W68–74, [명령 표](../manual/07-command-table.md), [기존 데이터 검증](../manual/08-organization-units-data.md).

카드 대응과 활성 명령 목록은 권위 코드가 명시적으로 주입한다. 보유 카드는 중복 없이 최대16장이다. 이름·명령 군으로 권한이나 PCP/MCP를 추론하지 않는다. 권한·기능 플래그 검사 뒤 CP0 결제는 잔량·CP 종류와 관계없이 지갑/경험치 누적 대상량을 바꾸지 않는다. 일반 결제는 해당 CP 전액을 차감한다. 부족하면 다른 CP에서 비용2배를 전액 차감할 수 있으며 원래 CP는 그대로 둔다. 대용의 경험치 누적 대상량은0이다. 부족한 부분만 대용하거나 두 종류를 섞어 지불할 수 있을 것 같은 경우에는 미정 오류를 반환한다. 차감·시간 계산·ID 증가의 overflow나 정책 누락은 지갑·작업·다음 ID를 변경하지 않는다. `evidence:manual` W27·W15; 혼합 결제는 미확정.

고정값·범위·거리 의존·공란은 별개다. 워프의 원문CP40과 빈 대기는 그대로 보존하면서 거리 의존 조건을 표시한다. 범위 비용과 거리 비용은 명시 resolver가 필요하다. 비영 대기/소요 값은 표 단위당 게임 milliseconds를 명시한 주입 정책이 필요하며 고정값/범위와 대조한다. 기본 시간을 게임 시간1시간으로 채우지 않는다. 원문0은 실제0과 대조한다. resolver가 반환한 값은 서버 권위 입력이며 client에서 받아 실행하는 API가 아니다.

작업은 주입된 단조 게임 milliseconds로 등록·시작·완료한다. catch-up 이벤트는 발생 시각→등록 ID→동일 작업의 시작/완료 순으로 반환한다. 완료된 작업은 반복 advance에서 다시 실행하지 않는다. 작업 이벤트는 일정의 진전만 나타내며 원작 명령의 효과를 적용한 것이 아니다. `SessionSimulation`/`WorldEngine`과 실제 client command/wire 연결은 후속 공유 경계다. 기존 `SessionRules`의2게임시간 회복 간격과 `WorldEvent.CpRecovery`는 변경하지 않으며 CP 상한·政治/運営 회복량·전술 회복 정지의 실제 캐릭터 연결을 이번 단위에서 구현했다고 기록하지 않는다.

검사는 `server` cwd에서 `gradle --offline :engine:test`로 실행한다. 원문 bytes·81개 상태와 군별 개수, malformed/duplicate/UTF-8, 카드·CP 결제·경험치 대상량·실패 원자성, 시간 정책/범위/overflow와 등록 순서를 합성 값으로 검사한다. 합성 표 시간 단위는 원작 시간 단위의 확정 근거가 아니다. 기본個人/艦長 배정·전체 카드 대응·PCP/MCP 귀속·CP 상한/회복·Q-M4 제안/명령 분담은 미정이며 전체 LOGH-29 완료나 실제 client 수용을 주장하지 않는다. 인사·작전/병참 효과의 미정 수치는 [05](../manual/05-personnel-operations-logistics.md)를 따른다.

## 연료 보급의 저장 가능한 공통 작업 연결 (2026-10-25)

`NavigationWork`가 실제 `0b02` 요청을 기존 `StrategyPipeline`의 원표 명령 `operation/燃料補給`에 연결한다. 월드 액터의 인증·세대·본인 기함·함장 카드·위치·전술 상태 검사 후 MCP 160 결제, 8시간 대기, 부족 비율에 따른 48~960시간 소요를 등록한다. 이전 구현은 응답에만 대기 8시간을 넣고 완료 시각 계산에서 빠뜨렸다. 새 작업의 완료는 접수+대기+소요이며, 매뉴얼 W p.28의 대기/소요 구분을 따른다. 표의 시간 단위를 G시간으로 해석하고 부족 비율을 보간하는 정책은 여전히 설계값이다. `evidence:manual`(W p.28·68의 구분·수치), `evidence:guess`(단위·보간·MCP 귀속)

`StrategyCheckpoint`는 작업 ID·다음 ID·단조 시각·대기/실행 상태·결제 내역을 복구한다. 최대 128건은 저장 크기를 제한하는 서버 정책이다. 실제 연료 경로는 보급 한 건만 허용한다. `LOGH7-NAV-5`의 마지막 열에 체크포인트를 저장해 CP·완료 시각·항속 효과와 같은 atomic replacement 경계를 사용한다. 별도 작업 파일과 잔고 파일 사이의 부분 성공은 만들지 않는다. 완료 시 같은 저장에서 항속을 채우고 완료 작업을 제거하며 다음 ID는 보존한다. 저장 실패 시 새 상태를 공개하지 않는다. `evidence:guess`(구현 정책)

NAV-1~4를 계속 읽는다. NAV-4에서 이미 접수한 보급은 원래 응답한 완료 시각을 유지하고 8시간을 추가 청구하거나 연장하지 않는다. CP 회복 뒤 파이프라인을 복원할 때 현재 잔고를 사용하므로 과거 결제 당시 잔고로 되돌리지 않는다. 로그인·기존 월드 갱신·명령 접수 때 경과를 정산한다. 서버가 정지한 동안 게임 시계가 흐르도록 바꾼 것은 아니다.

관련 엔진·저장·암호화 게이트웨이 검사에서 대기 경계·실행·완료, 재열기, 중복 완료 방지·ID 유지, CP 대용 내역, 저장 실패, 이전 형식과 시계 범위 초과를 확인했다. 연료 보급 한 경로의 연결이며 전체 카드, 경험치 성장 적용, 예약 취소, 전술 진입 시 작업 정책, 제안/명령 CP 분담, 다른 80개 명령의 효과 연결은 남아 있다.

실제 원본 클라이언트 한 개를 비활성 데스크톱에서 실행해 보급 카드 접수 후 CP 160 결제·WAITING 저장, 클라이언트/서버 종료 후 같은 ID·완료 시각의 RUNNING 복원을 확인했다. 최소 소요 48시간만 지난 시점에는 항속 999가 유지됐고, 8+48시간 뒤 기존 통지와 함께 네이티브 기함·HUD·저장 항속이 1000이 됐다. 완료 뒤 양쪽을 다시 시작해 항속 1000·빈 작업·보존된 다음 ID와 보급 완료 재통지 없음도 확인했다. 관련 42개 검사가 통과했으며 시험용 1000배 시계·캡처·관찰 파일은 `work/strategy-fuel-20261025/`에 둔다. 일반 서버의 시계는 가속하지 않았다. `evidence:client`(실행·표시)


## 성계 기항 연결 (2026-10-25)

실제 기항 `0b00`도 `NavigationWork`에서 원표의 `operation/星系内航行`으로 제출한다. 접수 때 MCP 160을 결제하고 8시간 후 실행·완료한다. 대기 중에는 기함의 현재 거점·모드·항속을 유지하며, 같은 기함의 재기항·워프·보급·스폿 이동을 막는다. 시간 단위와 병행 명령 차단은 연료 보급과 같은 명시적 설계 정책이다. `evidence:manual`(W p.28·68), `evidence:guess`(단위·차단)

NAV-6은 현재 거점과 별개로 목적지 거점 열을 저장하며 NAV-1~5를 계속 읽는다. CP·일정·목적지의 접수와 도착 위치·작업 제거는 각각 한 파일의 원자적 교체로 처리한다. 도착 때 이동 횟수를 한 번 올리고 항속은 채우지 않는다. 도착 시점에 새 명령이 거부되더라도 완료 결과·자기/관찰자 갱신을 보존한다. 같은 그리드의 가시적 동료에게 실제 유닛 위치와 도착을 전달하며, 대기 중에는 위치 변경을 전달하지 않는다.

실제 확인과 남은 UI·취소 범위는 [기항 예약](../protocol/world-navigation.md#성계-기항의-예약과-도착-2026-10-25)을 따른다. 전체 명령·제안·취소 파이프라인의 완료로 보지 않는다.
