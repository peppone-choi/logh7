# 이동·CP와 행성 재고의 공통 저장 경계

작성: Peppone Choi · 2026-10-25

내정·병참 명령의 CP 결제와 자원 효과를 함께 확정하기 위한 저장 기반이다. `FileWorldStateStore.saveWorld(navigation, inventory)`는 두 상태의 완성본을 저장하고 하나의 포인터 교체로 확정한다. 기존 명령이 각각 호출하는 이동 저장·재고 저장을 자동으로 하나의 명령 트랜잭션으로 합치는 기능은 아니다. 2026-10-26 [세율 변경](../protocol/planet-tax.md)에 권한 검사·상태 계산·한 번의 저장·월드 액터의 두 상태 공개를 연결했다. 다른 명령과 내정 UI·인사 연결은 미완료다.

## 저장 방식

- `slot-0`과 `slot-1`에 각각 이동 상태와 재고를 보관한다. 이동은 경로가 없으면 NAV-8, 기함 전술 경로가 있으면 NAV-9로 쓰며, 재고는 부대 위치가 없으면 STOCK-14, 있으면 STOCK-15로 쓴다. NAV-8은 기함의 에너지 배분 11개를, NAV-9는 원점·서버 접수 시각·속도·방향·경유점을 추가한다. NAV-1~7은 배분 미설정으로, NAV-1~8은 전술 경로 없이 읽는다. 실제 원본의 이동/복원은 [전술 연결](../protocol/tactical-entry.md)의 미확인 범위를 따른다. 재고에는 함정 유닛 ID와 다음 번호, 세율·총독 ID·수비대장 ID도 포함된다. STOCK-7까지의 저장본은 기존 값을 보존하고 수비대장을 자동 임명하지 않고 읽는다.
- 현재 선택되지 않은 슬롯에 두 파일을 완전히 쓰고 `force(true)`를 수행한다. 기존 코덱으로 다시 읽어 검증한 뒤 `CURRENT.tmp`도 강제 기록한다.
- `CURRENT`를 원자적으로 교체한 뒤에만 새 상태를 메모리에 공개한다. 이 파일은 형식 `LOGH7-WORLD-1`, 활성 슬롯, 재고 유무만 포함한다. 슬롯이 번갈아 사용되므로 이력 파일이 계속 늘어나지 않는다.
- 확정 전 실패는 이전 포인터와 이전 두 상태를 유지하고 해당 writer의 추가 쓰기를 차단한다. 활성 슬롯 손상·누락이나 슬롯이 있는데 포인터가 없는 경우 자동 초기화·이전 파일로의 후퇴를 하지 않고 기동을 실패시킨다.
- 파일 내용 강제 기록과 프로세스 종료 복구를 제공한다. 디렉터리 메타데이터의 전원 장애 내구성은 기존 NAV/STOCK 파일 저장과 같이 OS·파일시스템에 의존한다. 세션 시계·접속 journal과의 단일 트랜잭션이나 데이터베이스를 대체한 것은 아니다.

## 서버 설정과 이관

`LOGH7_WORLD_STATE_DIR`를 지정하면 실제 app의 기존 이동/재고 인터페이스가 이 저장소를 사용한다. 지정하지 않으면 기존 파일 저장 방식을 유지한다. 기존 `LOGH7_NAVIGATION_FILE`과 `LOGH7_PLANET_STOCK_FILE` 및 캐릭터 파일에서 유도하는 기본 경로는 최초 이관 입력으로 사용한다.

처음에는 기존 두 파일을 읽고 다음 저장에서 한 묶음으로 기록한다. 원래 입력 파일 내용은 수정하지 않는다. 실행 중에는 원래 입력 파일의 쓰기 잠금도 계속 보유해 구버전 서버와의 동시 쓰기를 막는다. 이후 시작에서는 `CURRENT`가 선택한 데이터만 권위 상태로 읽는다. 입력 파일 옆에 `.world-owner` 표시를 강제 기록해 같은 저장 디렉터리에 묶는다. **현재 빌드는 환경 변수 누락이나 다른 디렉터리 지정 시 과거 파일로 되돌아가지 않고 기동을 거부한다.** 잠금 획득 전후에 모두 소유 표시를 검사한다. 이 표시를 모르는 이전 빌드의 종료 후 실행까지 막는 기능이나 최신 데이터의 역변환 도구는 아직 없다. 재개 시 같은 디렉터리를 계속 지정해야 한다.

기존 이동 또는 재고 인터페이스 한쪽만 저장할 때도 다른 쪽의 마지막 확정 상태를 함께 보존한다. 이는 저장 구현의 호환 경로이며, 두 번 호출한 서로 다른 상태 변경을 하나의 명령으로 확정한 것으로 해석하지 않는다.

## 검사 범위

저장소 검사 7개에서 결제·자원 상태의 동시 저장/재개방, 확정 직전 실패와 추가 쓰기 차단, 원본 파일 보존 이관, 단일 writer, 개별 인터페이스의 상대 상태 보존, 빈 초기 재고, 활성 슬롯 손상/포인터 누락의 기동 거부를 확인했다. 별도 시험 JVM이 확정 직전 또는 확정 직후 `Runtime.halt`로 종료된 뒤에는 각각 이전 두 상태 또는 새 두 상태가 함께 복원됐다. 실제 게임 명령의 재전송 멱등성이나 전원 차단 시험을 대신하지 않는다.

저장소 전체 52개 검사와 app 빌드가 통과했다. 일반 플레이 저장 파일의 사본을 새 디렉터리로 이관한 실제 app에서 원본 클라이언트 한 개의 로그인·전략 화면·오딘 창고 조회를 확인했다. 서버와 클라이언트를 모두 종료한 뒤 재기동 직전/직후 활성 슬롯의 이동·재고 파일이 같았으며, 재접속 후 위치 2487·PCP/MCP/항속 1000과 창고 조회를 유지했다. 재접속 중 정상 CP 회복 시각은 갱신됐지만 재고 완성본은 같았고 함정 ID 1200개와 다음 번호 1201도 유지했다. 최종 재고 유무·소유 표시 검사 보강 후 새 app 빌드의 기동/health와 같은 활성 재고 재개방도 확인했다. 같은 이관 입력에서 환경 변수를 제거한 실제 app은 `LOGH7_WORLD_STATE_DIR` 설정 필요 오류로 기동을 거부했다.

최초 설정 시험과 실제 클라이언트 확인 자료는 `work/world-state-20261025/`에 보존한다. 원본 클라이언트 파일 보존·소유 프로세스 종료·음향 정리를 확인하고 일반 서버를 복구했다. 당시에는 일반 플레이 저장 파일을 직접 이관하지 않았다. 두 원본 동시 실행, 신규 내정 명령의 실행, 전원 차단·디스크 고장·장기간 성능은 이 최초 확인에 포함하지 않았다.

## 일반 로컬 서버의 전환 (2026-10-26)

세율 카드 조작 연결 후 일반 로컬 서버도 `LOGH7_WORLD_STATE_DIR=E:\logh7\work\playable-20261025\world`로 전환했다. 기존 이동·재고 입력은 `work/governor-tax-ui-20261026/normal-*-before-runtime22.tsv`로 백업했으며, 실제 이관 후에도 입력 본문은 바이트 단위로 같았다. 소유 표시만 새 저장 디렉터리에 연결된다. 이후에는 같은 환경 변수를 계속 지정해야 한다.

일반 데이터의 총독은 모두 0이며 별도 시험의 직무·세율·저잔고를 가져오지 않았다. 새 활성 재고는 STOCK-7, 다음 함정 ID 1201을 유지했다. 원본 한 개가 전략 화면에 진입하고 개인·함장 2장만 표시하는 것을 확인했다. 종료 후 같은 공통 저장소를 다시 연 서버의 이동/재고 완성본은 전과 같았고 health가 정상이었다. 원본·프로세스·음향 정리는 `work/governor-tax-ui-20261026/native-09-normal`에 남긴다. 이는 로컬 전환이며 외부 서비스 배포가 아니다.
