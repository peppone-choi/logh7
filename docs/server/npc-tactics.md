# 무지휘관 함정의 전술 AI

작성: Peppone Choi · 2026-10-28

## 범위와 근거

`evidence:manual` 전술의 자동 공격·철수 준비와 최고사령관 임무는 [매뉴얼 요약](../manual/06-tactics.md)에 있다. 오프라인 인물이 AI ON 상태일 때 임무를 수행하는 규칙과, 이번 무지휘관 함정의 자율 행동은 구분한다. 원작 인물의 이름·얼굴·직책 생성, AI ON/OFF와 최고사령관 임무는 아직 연결하지 않았다.

`evidence:guess` 함장/참모 등 플레이어 소속 인물이 없는 우주 공간 부대의 실제 현역 함정 ID를 AI가 운용한다. 정박 중인 함정은 출격시키지 않는다. 같은 그리드의 적 함선/기함을 탐지해 가까운 적에게 접근하고, 사정 안에서는 장착된 무장으로 공격한다. 적이 사라지면 현재 위치에서 대기하며 다음 적을 찾는다. 지휘 인물이 배치되면 AI 이동·공격을 멈추고 현재 위치를 보존한다. 미선택 원작 인물의 정식 초기 배치를 대신하는 완료 항목은 아니다.

## 실행과 저장

- `NpcTactics`는 월드 액터에서 실행한다. 탐지 거리 500, 교전 거리 2, 판단 간격 실제 1초, 발사 간격 실제 5초는 대체 설계다. 최고 속도는 매뉴얼 함종 수치를 20,000으로 나눠 지도 속도로 환산하며 상한은 기존 이동 모델의 1이다. 원작 색적·사선·가속 공식을 복원한 값은 아니다.
- 무장 유무·위력·건/미사일 소비는 매뉴얼 데이터에서 읽는다. 잔존 척수 비율로 위력을 낮추고, 소비 물자는 해당 함정 유닛의 잔존 척수만큼 계산한다. 부대의 실제 물자와 유닛별 배분을 넘겨 쓰지 않는다. 물자가 없어도 빔은 가능하다. 별도의 NPC 무한 탄약 잔고는 없다.
- 발사 대상은 매번 다시 확인한다. 아군·정박 함정·거점·격침된 함정은 제외한다. 플레이어 사격과 같은 `strike` 경로가 내구도·방어막·척수·격침 후 부상/구축함 귀환을 처리한다. 다른 NPC 부대와의 교전도 같은 경로다.
- 부대의 원래 현역 함정 총 척수 대비 잔존 척수가 25% 이하거나 무장이 없으면 철수를 시도한다. 인접 그리드의 진입 제한·수용량을 확인하고 적이 없는 방향과 본거지 쪽을 우선한다. 레이더 밖으로 이동한 뒤 실제 5초 대기+150초 준비를 마치며, 생존 함정 모두가 밖에 있고 목적지가 여전히 허용될 때 부대 위치를 함께 바꾼다. 막힌 목적지로 강제 이동하지 않는다.
- STOCK-16의 현역 함정 레코드에 이동 경로·다음 판단/발사 시각·발사 순번·목표·철수 준비를 보존한다. STOCK-1~15에는 이 상태를 만들어 넣지 않는다. 현재 위치는 저장 경로와 서버 시각으로 계산하며, 매 프레임 좌표를 저장하지 않는다.
- NPC 이동·사격·물자·상대 손실·귀환은 기존 월드의 두 슬롯 커밋으로 확정한다. 저장 실패 시 이동/피해를 전파하지 않는다. 같은 시각 재정산은 중복 발사하지 않으며, 중단 동안의 모든 과거 발사를 한 번에 소급하지 않는다.

`evidence:client` 원본 이동 적용 함수 `004be8f0`은 명령의 유닛 ID 목록으로 이동 대상을 찾으며 명령자 필드를 사용하지 않는다. 서버 소유 NPC 이동은 명령자 0의 `0400`으로 알리고, 클라이언트가 보내는 명령자 0은 계속 거절한다. 재접속 시에도 저장 위치와 남은 경로를 초기화에 넣는다. 철수 완료는 `0425`, 피해는 기존 `0426`을 전장 연결에 전달한다. 자기 기함 격침 시에는 기존의 전술 퇴장→귀환 순서를 유지한다.

## 검사와 실제 실행

엔진 487·프로토콜 110·영속화 97·게이트웨이 171개, 합계 865개 검사와 앱 배포 빌드가 통과했다. NPC 접근/사격·서로 다른 NPC 간 교전·빈 탄약·동일 시각 중복 방지·저장 실패·지휘권 전환·철수 준비/목적지·상태 재로딩과 두 암호화 연결의 이동/피해/이탈 통지를 포함한다.

별도 `npc-world`에서 두 동맹 기함과 제국 함정 두 부대를 사용했다. 정상 부대는 300척·물자 50,000, 약화 부대는 75척으로 제한했다. 다른 부대는 정박시켜 시험 밖 교전을 막았다. 정상 부대의 첫 판단은 클라이언트 초기화를 기다리는 시험용 미래 시각으로 지정했으며, 실제 NPC 경로·사격·철수는 서버가 결정했다.

`run-69`: 원본 두 개 실행 중 NPC 유닛 1이 첫 기함에 접근해 격침하고, 다른 기함을 다시 추적·공격했다. 원본 메모리의 NPC 위치 (-178,-95), 이후 (-179.801,-76.990)과 이동 상태·피해를 관찰했다. 첫 플레이어는 동맹 귀환지 1177/2015·구축함 93·물자 0으로 복귀했고, 두 번째는 방어막 손실 뒤 내구도 20까지 진행했다. 약화 NPC 유닛 41은 준비 뒤 2017→2118로 철수하고 75척·물자 50,000을 보존했다. 철수 준비 전 과정의 두 화면 동시 연출을 확인한 것으로 해석하지 않는다.

종료 직전 활성 슬롯의 NPC 유닛 1은 물자 200·발사 순번 90·마지막 위치와 목표, 약화 부대는 2118 위치를 보존했다. run-70에서는 같은 월드로 서버와 두 원본을 다시 시작했다. NPC는 남은 빔으로 10회 더 발사해 순번 100에 두 번째 기함을 격침했고, 물자 200과 마지막 위치를 보존한 채 목표 0의 대기 상태로 전환했다. 두 원본의 메모리에서 모두 2015/1177·구축함 93·물자 0을 확인했고 첫 플레이어의 부상 기한은 그대로였다. 약화 NPC의 2118·75척·물자 50,000도 보존됐다. 두 실행 모두 원본 프로세스 정리·원본 해시·호스트 포커스/커서 보존을 통과했다. QA를 종료하고 기존 일반 runtime-70을 복구했으며 새 코드/월드는 일반 런타임에 배포하지 않았다. 시작/검사/캡처는 `work/native-multiplayer-20261028/`와 작업 트리의 같은 이름 디렉터리에 있다.

## 남은 범위

원작 인물의 정식 배치·이름/얼굴, 플레이어의 AI ON/OFF와 오프라인 대행, 전략 이동·출격·순찰·임무·해적·생산/내정 판단, 수리·보급 요청, 지휘권/CRC·색적/사선·부대 대형·사기와 원작 전투 수치 복원은 남아 있다. 현재 위치가 남아 있는 오프라인 기함도 공격 대상이 되므로 로그아웃/AI 설정 정책은 별도로 연결해야 한다. 이번 변경으로 NPC 전체나 한 판 완주를 완료 처리하지 않는다.


## 유닛별 탄약 물자 차감 보완 (2026-10-28)

작성: Peppone Choi

부대 총량만 줄이면 ID순 적재 배분이 다시 계산돼 실제 사격한 함정 외의 잔액이 줄 수 있었다. 현역 함정별 적재 배분을 저장하고 NPC 사격 비용을 해당 유닛에서 차감하도록 고쳤다. 부대 총량은 각 유닛의 합계로 함께 확정한다. 두 NPC 함정이 각 5,000으로 시작해 같은 시각 세 무장씩 발사한 검사에서 각각 3,200·총량 6,400을 확인했고 같은 시각 다시 정산해도 추가 차감이 없었다. 단일 함정뿐인 기존 run-69/70의 결과를 복수 함정 잔액 시험으로 확대 해석하지 않는다. 새 저장은 STOCK-17이며 [저장 정책](../protocol/tactical-entry.md#유닛별-군수물자-저장의-선행-수정-2026-10-28)에 범위와 이전 형식 호환을 기록했다.


## 무지휘관 전투 부대의 전략 이동 연결 (2026-10-29)

작성자: Peppone Choi

전략에서 움직이지 않던 무지휘관 함대/순찰대에 인접 그리드 이동 예약을 추가했다. 현재 정규 소유 거점의 부대 또는 우주 공간 부대에서 가장 가까운 적 병력/거점 방향의 허용 인접 그리드를 선택한다. 판단 간격 6게임시간·이동 대기 1게임시간, 생존 1척당 군수물자 1의 이동 비용과 거점에서 최대 10회분을 실어 나르는 정책은 복원 설계다. 원작의 함대 이동 시간·소모 공식으로 확정하지 않는다. `evidence:guess`

가까운 적을 향한 다음 도약이 막히거나 도약 후 귀환에 필요한 물자가 부족하면, 같은 조건으로 다음 공격 후보를 확인한다. 예약 정산에서는 기존 방향의 유효한 후보를 우선한다. 가능한 공격 후보가 모두 없으면 기존 귀환 규칙을 따른다.

출발 때와 완료 때 지휘관/부관/참모 부재, 전투 부대 종류, 현재 거점 소유권, 진행 중 지원/공격/육전 명령과 목적지 진입/정원을 검사한다. 정박 부대는 완료 때 우주 배치로 전환하고 함정 ID·잔존 척수·본래 창고와 육상 주둔 병력 위치를 유지한다. 거점의 실재 군수물자를 함정별 적재 한도 내에서 이전하고, 각 생존 함정이 가진 물자에서 비용을 차감한다. 부족하거나 목적지가 막히면 이동하지 않고 다음 판단을 기다린다. 예약 자체는 물자/CP를 소비하지 않는다. 모든 변경과 적 접촉은 기존 월드 커밋으로 확정한 뒤 알린다.

예약·대기 종료 시각과 다음 판단 시각은 STOCK-27의 부대 행에 저장한다. 1–26 저장도 읽되 옛 저장에 예약을 만들어 넣지 않는다. 잘린 예약·비정규 범위·구형 헤더로 바꾼 새 행은 거부한다. 재처리로 물자를 다시 차감하지 않는다. 전략 시청자에게 지도 병력을 갱신하고, 도착지에서 적과 접촉한 항행 인물에게 기존 전술 진입 통지를 보낸다. 기존 전술 시청자에는 전체 현재 정의·상태를 보낸다. `evidence:client` 통신 형식을 재사용했으며 구체적인 자율 판단은 위 설계 정책이다.

엔진 전체 620개·저장 전체 125개·관련 암호화 접속 4개와 app 배포본 빌드가 통과했다. 예약/완료·출처 물자 차감·같은 시각 중복 방지·지휘관 임명/거점 상실 취소·정원 재검사·물자 부족·저장 실패 시 무발행을 검사했다. 두 암호화 접속은 전략 대기 중 NPC 도착 통지와 전술 초기화의 실제 함정 ID 1/종류 32를 포함하는 상태를 확인했다. 엔진의 개별 시험 기본값은 기존 동작을 유지하고 일반 앱 진입점은 전략 AI를 활성화한다. 현재 가동 중인 일반 runtime-236은 이전 코드이며 이번 AI는 아래 별도 localhost QA로 확인했다.


### 원본 두 개의 전략 접촉·교전·재시작

run-237은 기존 QA 월드의 사본에서 제국 전함 ID 1(300척) 한 부대만 오딘 2487/1049에 정박시키고 두 동맹 기함을 인접 우주 그리드 2488에 배치했다. 다른 부대는 시험에서 제외했다. 전략 화면인 양쪽 앞에서 이동 예약 777600→781200을 처리하자 NPC가 2488로 도착하고 두 원본이 전술 화면으로 전환됐다. 양쪽 실제 실행 객체에 같은 NPC ID 1·함종 32와 두 기함 1010000/1010001·함종 89가 생성됐다. 거점에서 물자 3000을 이전해 이동비 300을 소비한 잔량 2700을 확인했다. 이어 시험 시계를 진행하자 NPC가 접근·자동 사격했고 첫 기함은 방패 한 면 0·내구도 61, 두 번째는 내구도 100이 됐다. NPC는 실제 물자를 모두 소비하고 발사 순번 30을 저장했다. 빔만 사용 가능한 상태에서 새 탄약을 만들어 넣지 않았다.
