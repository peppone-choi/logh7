# 행성 일일 경제 정산

작성: Peppone Choi · 2026-10-25 · 관련: LOGH-51, 실제 플레이 완성 체크리스트 §4

행성 재고의 군수물자만 증가하던 경로를 인구·성인 인구·식량·광물·민심·치안과 연결했다. 이 문서는 해당 일일 정산의 구현 범위다. 징세·예산·개척·무역·생산 명령 및 전체 내정 완료를 뜻하지 않는다.

## 근거와 현재 정책

매뉴얼은 경제가 미구현이었다고 명시하고(W p.9), 자동 생산물의 행성 창고 입고와 인구에서의 모병을 설명한다. 군수물자의 1G일 생산 간격은 [생산 규칙](../manual/05-personnel-operations-logistics.md#72-생산)과 패치 이력의 기존 근거를 따른다. 아래 수량·소비·인구 및 민심 변화 공식은 소실된 서버 규칙의 복원이 아니라 사용자 요청에 따른 설계값이다. `evidence:manual`(위 설명), `evidence:guess`(이하 공식)

게임 하루 경계마다 다음 순서로 계산한다. 모든 중간 계산은 Long 정수이며 소수점 이하는 명시적으로 버린다. 재고 상한 기본값은 Int.MAX_VALUE이고, 이미 설정 상한보다 많은 이전 재고를 강제로 잘라내지 않는다.

| 순서 | 현재 설계값 |
|---|---|
| 농업 | 거주 가능 행성만 성인 인구 / 500만큼 식량 생산. 저장 상한 적용 |
| 소비 | 전체 인구 / 1000의 올림만큼 식량 소비. 부족분과 잔량은 음수가 되지 않음 |
| 인구 | 충분히 먹고 거주 가능하면 하루 0.01% 증가(내림), Int.MAX_VALUE 상한. 비거주 거점은 자연 증가 없음 |
| 기아 | 최대 하루 1% 인구 감소분(올림)을 식량 부족 비율에 비례 적용(올림). 성인 인구는 기존 비율을 유지하며 내림 |
| 광업 | 성인 인구 / 5000만큼 광물 생산. 해당 일 시작 시점의 노동 인구 사용 |
| 군수물자 | 아군을 포함한 제국/동맹 정규 진영의 식량 충족·성인 인구가 있는 거점에서 최대 하루 1000. 생산량 10마다 광물 1 소비(마지막 부분도 올림), 실제 광물·보관 여유로 생산 제한 |
| 민심·치안 | 식량 부족이면 민심 -2·치안 -1(최저 0). 충족하면 초기 기준보다 낮은 수치만 하루 +1로 복구. 현재값이 초기 기준보다 높으면 유지 |

중립에서도 농업·소비·광업·인구 정산은 진행하지만 군수물자는 생산하지 않는다. 비거주 거점의 초기 주둔 인구도 식량을 소비하므로 공급이 없으면 기아가 발생한다. 수송·자동 보급·무역은 아직 연결되지 않았다. 노동 배분·농장/광산 건설·시설별 생산 설정·세수는 별도 구현 범위다. 위 변수는 `PlanetEconomyPolicy`와 `PlanetProductionPolicy`에 모아 둔다. 정책 변경 전에 재현·밸런스 검사가 필요하다.

## 시간·저장·표시

월드 액터의 시계 갱신에서 조회자 없이도 정산한다. 조회 시에도 같은 마지막 정산 일자를 사용하므로 로그인·재조회 빈도로 추가 생산하지 않는다. 여러 날을 한 번에 따라잡아도 하루씩 진행하며 인구·기아의 피드백이 매일 조회한 결과와 같다. 서버가 멈춰 있는 동안 게임 시계가 흐르도록 변경하지 않는다.

`LOGH7-STOCK-2`는 기존 6열 뒤 인구·성인 인구·민심·치안 4열을 추가한다. STOCK-1의 재고·소유권·정산 일자는 보존하고, 인구 정보는 다음 정산에서 해당 거점의 초기값으로 채운다. 기존에 정산했던 날의 인구·식량 효과를 소급 적용하지 않는다. 새 세션은 해당 세대의 초기 상태를 한 번 생성한다.

식량·광물·군수물자·인구·민심·치안과 마지막 정산 일자는 한 파일의 원자적 교체로 저장한다. 저장 실패 전에는 새 재고를 공개하지 않고 엔진의 후속 변이 요청을 차단한다. 세션 시계와 재고는 별도 저장 경계다. 시계를 저장한 다음 재고 저장이 실패하면 재시작 시 보존된 재고 일자부터 같은 시각까지 다시 정산하며 중복 생산하지 않는다.

원래 `031f` 행성 정보는 저장된 인구·성인 인구·민심·치안·식량·군수물자를 표시한다. `0327` 창고도 같은 재고의 식량·광물·군수물자를 사용한다. 이전에는 행성 정보의 식량만 초기값으로 남는 문제가 있었다. 화면에서 다음 행성/새로고침 또는 재열기로 최신 정보를 조회한다. 열려 있는 정보 창의 즉시 자동 갱신과 인구 변화의 세션 승리 조건 반영은 아직 연결되지 않았다.

## 확인 결과와 남은 범위

식량/광물 수지, 중립·비거주·무인 거점, 부분 기아·회복, 재고/정수 경계, 이전 저장 이관·재개방, 분할/일괄 정산 일치, 저장 실패 및 조회 없는 시계 갱신을 검사했다. 암호화 행성 정보와 창고 조회에서 같은 실시간 값을 확인했다. 엔진·게이트웨이 전체 회귀 검사와 저장소 관련 검사도 통과했다. 기본 수도 규모로 2400G일을 진행했을 때 기아 없이 인구가 증가하고 식량·광물·군수물자가 전송 범위 안에 남는 검사도 통과했다. 이는 세금·군수 소비·수송까지 포함한 전체 밸런스 검증은 아니다.

비활성 데스크톱의 실제 원본 한 개에서 1일 뒤 조스트(1048)의 인구 100010000·성인 60006000·식량 1020000·광물 111900·군수물자 101000을 화면·디코딩 값·저장에서 확인했다. 오딘(1049)의 1일 인구 1000100000·식량 10200000·광물 219900도 확인했다. 비거주 거점(1050)은 시험 시작 재고의 식량만 0으로 배치해 2일 뒤 인구 98010·성인 58806·민심 66·치안 78·식량 0·군수물자 100000 유지와 광물 100023을 확인했다. 이 배치는 기아 재현용 별도 데이터다.

양쪽 종료 후 서버 재기동 직후 2일째 전체 저장값이 동일했으며, 재접속한 원본에서 이어진 3일째 조스트 인구 100030003·식량 1060005·광물 135703·군수물자 103000을 확인했다. 초기값으로 리셋하거나 이틀을 다시 생산하지 않았다. 세 거점의 일자별 상태를 독립 수지 계산과 대조했다. 1000배 시험 시계·원본 보존·프로세스 정리·캡처·수신·저장 비교는 `work/planet-economy-20261025/`에 둔다. 일반 서버 시계는 24배를 유지한다. 두 원본 동시 조회·전체 세션 밸런스·수송에 의한 기아 해소는 미확인이다.

징세·납입률·관세·예산·금고·분배·개인 계좌, 시설 명령, 함정/승조원/육전대 생산, 물자 수송·부대 창고·보충/재편성, NPC 내정 판단은 미완료다. 이 구현으로 LOGH-51 전체를 완료 처리하지 않는다.


## 일일 징세·지방/국가 금고 연결 (2026-10-29)

작성: Peppone Choi

`PlanetProduction`의 일일 정산에 징세를 연결했다. 성인 1인당 하루 1 회계단위를 소득으로 보고 현재 유효세율을 적용한다. 징세액의 50%를 중앙 금고에, 나머지를 지방 금고에 적립한다. 이 숫자와 회계단위는 원작 통화 환산이 아닌 복원 설계값이다. `evidence:guess` 원작이 경제 미구현이라고 밝힌 사실은 위 W p.9 근거와 같다.

하루 시작 시점의 저장 성인 수를 사용하므로 전날 모병·기아의 감소를 되돌리지 않는다. 저장된 현재 소유 세력이 2/3이고 일반 진영이며 거주 가능 행성일 때만 징세한다. seed 소유권으로 역귀속하지 않는다. 자동 생산물 자체에 추가 세금을 부과하지 않는다. 현재 일일 모병 정산과의 관계는 시작 인구 기준이며 수동 모병 경제는 별도 범위다.

지방 금고는 `PlanetStock.treasury`, 국가 금고는 `PlanetStocks.nationalTreasuries`에 저장한다. 점령 시 지방 잔액은 거점과 함께 승계하고 이미 적립된 국가 금고는 기존 세력에 남는다. 다음 날부터 새 소유 세력이 중앙 수입을 받는다. 정수 나눗셈의 나머지는 지방에 두어 양쪽 적립 합계가 징세액과 같게 한다. 두 금고 모두 음수와 덧셈 오버플로를 거부하며 실패 시 새 재고를 공개하지 않는다.

세수·재고·마지막 정산 일자는 하나의 원자적 교체로 저장한다. STOCK-28은 지방 잔액 열과 국가 금고 T행을 추가하며 이전 STOCK-1~27을 읽는다. 금고가 없는 구버전은 잔액0으로 시작하고 기존 producedDays 이전 세금을 소급 징수하지 않는다. 새 세션은 금고0에서 시작한다. 같은 시각의 재조회·재접속·재시작은 재징수하지 않는다.

엔진 전체 635개·저장소 전체 127개·관련 gateway 15개 검사와 앱 배포본 빌드가 통과했다. 이후 추가한 금고 오버플로 거부와 실제 액터의 하루 정산→파일 재개방→새 액터 재시작/동일 시각 무재징수 검사도 통과했다. 구버전 읽기, Long 잔액 왕복, 음수/중복/잘린 T행과 잘못된 버전 거부, 일괄/일별 정산 동일, 저장 실패 미공개, 점령 후 귀속을 포함한다. 실제 클라이언트의 금고 조회·납입률 변경·예산/분배/개인 계좌 명령은 아직 연결하지 않았으며 내정 전체 완료로 처리하지 않는다. 일반 runtime-236도 아직 교체하지 않았다. 검사 로그는 work/native-multiplayer-20261028/treasury247-tests.log, parallel247-integration.log, treasury247-restart.log에 있다.


납입률 명령 후속 추적: constmsg의 명령 이름/설명은 ID16과 MCP320·대기0·소요0을 가리키며, 매뉴얼 W p.73은 세금의 중앙 납입 비율이라고 설명한다. 재무상서/재정위원장 카드8/136의 권한 설명은 있지만 실제 카드-명령16 레코드·원본 생성기와 실행 패킷 필드는 아직 미확인이다. 메시지 이름표의 CommandChangeBudgetRate 후보0a08을 이 명령으로 확정하지 않는다. 세율0a00의25바이트 패킷을 복사하거나 PowerDistribution0308/0309를 예산 명령으로 오인하지 않는다. 다음 연결 전 이 대응을 먼저 확인한다. `evidence:manual`(명령/권한 설명), `evidence:client`(이름표 후보와 아직 미확정인 대응).
