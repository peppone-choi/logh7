# 설계안: 워프 거리 비례 CP·대기, 사관학교 명령, 회견·우호도

작성: 최병호 · 2026-10-30 · 상태: **검토 대기**(구현 전)

체크리스트에서 설계가 큰 세 항목의 구현 전 설계다. 근거와 추정을 나누고, 검토자가 정해야 할 결정은 각 절 끝의 "결정 요청"에 모았다. 승인 전에는 구현하지 않는다.

- 대상 체크리스트: 1절 워프 줄, 11절 `ワープ航行`·`受講`·`兵棋演習`·`講義`·`会見`, 6절 회견·강의·수강·병기 연습·우호도 줄, 10절 U-18·U-22
- 근거 자료: 웹판 매뉴얼 `gin7manual.pdf`(이하 W), CD 메시지 데이터 `constmsg.dat`(그룹 0 도움말·그룹 18 명령명·그룹 21 선택 안내), `messages_com_0.dat`, CD 실행 파일 `G7MTClient.exe`

## 1. 워프의 거리 비례 CP와 실행 대기

### 1.1 근거

| 출처 | 내용 | 태그 |
|---|---|---|
| W p.28 | 실행 대기 시간은 명령 입력부터 실행 시작까지, 실행 소요 시간은 실행부터 완료까지 | `evidence:manual` |
| W p.68 별표 | 워프 CP 40, 소요 0. 이동 거리에 따라 소비 CP와 실행 대기 시간이 변한다(대기 칸은 수치 없음) | `evidence:manual` |
| constmsg 그룹 0 #110(CD 도움말) | 소비 MCP 80～320, 실행 대기 `？`G시간, 소요 0 | `evidence:client` |
| messages_com_0(CD 확인창) | 통상 320MCP, 지시된 작전 목표에 근접하면 80MCP | `evidence:client` |
| 패치 2004-08-04/05 예고 | 워프 CP 80→40, 도움말은 옛 값이 남음 | `evidence:manual` |
| CD 흐름 `00581c80` | 요청 `0b01` 송신 뒤 완료 통지 `0b07`을 기다리는 단계(`006702c0`). 기항(`0b00`→`0b0b`)과 같은 구조 | `evidence:client` |
| 기항 구현 선례 | 접수 응답에 대기 28,800초, 도착 시 `0b0b`, 재접속 시 HUD 복원(이미 실기 확인) | `evidence:client` |

CD판은 "작전 목표 근접 여부"로 80/320을 나눴고, 후기 웹판은 "기본 40, 거리에 따라 CP·대기 변화"다. 대기의 실제 수치는 어느 자료에도 없다.

### 1.2 제안

- **CP:** 후기 규칙을 따르되 CD의 1:4 폭을 유지한다. `MCP = 40 × ⌈광년/100⌉`(최대 4배)이다. 현재 범위 3칸에서는 인접 40, 대각 80, 2칸 80, (2,1) 120, (2,2)·3칸 120이다. PCP 대용 2배 규칙은 그대로 둔다.
- **작전 목표 할인(선택):** CD 확인창의 "작전 목표 근접 시 80/320"을 후기 기본값에 맞춰 옮긴다. 발령된 작전의 목표 성계 또는 그 인접 그리드로 가는 실행 부대 인물은 거리와 무관하게 MCP 40으로 한다. 작전 데이터는 `StrategicOperations`에 이미 있다.
- **실행 대기:** `대기(G시간) = ⌈광년/100⌉ − 1`이다. 인접(대각 포함) 0, 2칸 1G시간(실시간 약 2.5분), 3칸 2G시간(약 5분)이 된다. 인접 0을 둔 이유는 성계 진입이 인접 워프를 강제하므로 기본 이동 감각을 지금처럼 유지하기 위해서다.
- **처리 흐름(기항과 같은 구조):**
  - 접수: 검사(카드·위치·항속·CP·목적지 진입)를 통과하면 CP를 결제하고 `NavigationWork.WARP` 작업을 저장한다. `0b01` 응답의 대기 필드(+4)에 초를 넣는다. 대기 0이면 지금처럼 즉시 이동한다.
  - 대기 중: 기함은 원래 그리드에 있다. 출항·워프·기항·보급은 BUSY로 거부하고 CP 회복은 계속한다.
  - 실행 시작(대기 만료): 그 시점의 병력으로 목적지 진입과 오차 도착을 다시 판정한다. 성공하면 항속을 소비하고 위치를 옮기며 `0b07`을 보낸다(함대 동행 포함).
  - 실행 시점 거부: 진입 불가로 바뀌었으면 위치를 유지하고, 원위치 `0b07`로 명령 흐름을 끝낸다. 결제한 CP는 돌려주지 않는다(결정 요청 2).
  - 재접속: 기항 HUD 경로를 워프 목적지 그리드와 남은 시간까지 확장한다. 서버 재시작 시 작업 마감 시각부터 이어간다.
- **취소:** 매뉴얼에 전략 워프 취소 규칙이 없어 만들지 않는다. 전술 돌입으로 CP 회복이 멈추는 상태(`cpPaused`)에서는 마감이 와도 실행을 미룬다.
- **저장:** NAV 형식에 워프 목적지 열을 추가한다. 이전 형식은 "워프 작업 없음"으로 읽는다.
- **검사:** 거리별 CP·대기 경계, PCP 대용, 대기 0 즉시 이동, 대기 중 BUSY, 마감 시 재판정(진입 불가 무환불), 함대 동행, 재시작 복구, 암호화 왕복을 엔진·게이트웨이 검사로 확인한다. 원본 한 개로는 2칸 워프 접수→HUD 남은 시간→재접속→도착 `0b07`과 대기 중 다른 명령 거부를 확인한다.

### 1.3 결정 요청

1. CP 공식 `40×⌈광년/100⌉`와 작전 목표 할인 적용 여부
2. 실행 시점에 진입이 불가해졌을 때 CP 환불 여부(제안: 환불 없음)
3. 대기 공식 `⌈광년/100⌉−1` G시간(인접 0) 또는 "모든 워프 칸당 1G시간" 중 선택

## 2. 사관학교 명령: 受講·講義·兵棋演習

### 2.1 근거

| 명령 | 번호(그룹 18) | CP·대기·소요 | 원문 요지 | CD 흐름 |
|---|---|---|---|---|
| 受講 | 93 | MCP 160·0·0 | 능력 파라미터 증가, 사관학교에서만 | `00587850` 빈 흐름(객체 생성 직후 삭제) |
| 講義 | 27 | MCP 160·0·0 | 受講한 인물의 능력 증가, 120G분 또는 실행 스폿을 떠날 때까지 유효, 사관학교에서만 | `0058c220`: 강의 내용 4택 단계를 만든 뒤 명령 객체 삭제(미완성) |
| 兵棋演習 | 94 | MCP 10·0·0 | 시뮬레이터에 의한 전술 훈련, 사관학교에서만 | `005878b0` 빈 흐름 |

- 강의 내용 선택지(그룹 21 #309~312): 戦術関係(전술 관계)·戦史関係(전사 관계)·参謀要務(참모 요무)·特殊技能(특수 기능). 안내 #78·#150. `evidence:client`
- 장소: 시설 종류 20 `士官学校`가 두 수도에 있고 스폿 종류 17 `シミュレーションルーム`이 있다. 직무 카드에는 사관학교 교장·교관이 있다(그룹 4 #9·#10). `evidence:client`
- 능력 8종과 CP 경험치 성장(`AbilityGrowthRules`, 100 경험치 = 능력 +1)은 이미 구현돼 있다. `evidence:manual`(W p.14–15)

### 2.2 제안

- **강의 상태:** `LectureSession(id, 교관, 시설, 스폿, 내용, 시작, 만료=시작+120G분)`을 전략 상태에 저장한다. 교관이 그 스폿을 떠나거나 만료되면 끝난다. 교관 1명당 동시에 1개만 연다.
- **강의 내용별 대상 능력(설계):** 전술 관계 → 지휘·기동, 전사 관계 → 공격·방어, 참모 요무 → 통솔·운영, 특수 기능 → 정치·정보.
- **受講:**
  - 조건: 사관학교 시설 안의 스폿, MCP 160.
  - 같은 스폿에 진행 중인 강의가 있으면 그 내용의 두 능력에 각 경험치 +50을 준다. 강의가 없으면 수강자가 고른 능력 하나에 +20을 준다.
  - 같은 인물은 1G일에 1회로 제한한다.
  - 능력 상한은 현재 생성 규칙과 같은 범위로 막는다.
- **講義:** 사관학교 교관·교장 카드, 사관학교 시설 안의 스폿, MCP 160. 원본 4택 단계를 호환 DLL이 완성해 내용을 서버에 보낸다. 교관 자신에게는 효과가 없다.
- **兵棋演習:** 사관학교의 시뮬레이션 룸(스폿 17), MCP 10. MCP 계열 능력 하나에 경험치 +5를 주고, 1G일 5회로 제한한다. 전술 스킬 습득(`陸戦/空戦戦術訓練`)과는 별개다.
- **화면:** 受講·兵棋演習은 기존 연설 조작창과 같은 방식(조회→확정, 티켓, `0x7f10` 계열)으로 능력 선택·현재 강의·남은 횟수를 표시한다. 講義는 원본 4택 단계를 살려 흐름 삭제를 막는 방식을 우선 시도하고, 실패하면 같은 조작창으로 대체한다.
- **검사:** 장소·카드·CP·1일 제한·강의 만료/교관 이탈·능력 상한·저장 왕복·재시작을 확인한다. 원본 한 개로 오딘 사관학교에서 교관 강의→수강 효과와 兵棋演習 횟수 제한을 확인한다.

### 2.3 결정 요청

1. 강의 내용→능력 대응과 경험치 수치(+50/+20/+5)
2. 1G일 제한 횟수(受講 1회, 兵棋演習 5회)
3. 講義를 원본 4택 단계 복원으로 할지, 조작창으로 통일할지

## 3. 회견(会見)과 우호도

### 3.1 근거

- 会見(그룹 18 #87): MCP 10·0·0, 같은 스폿 인물과 회견해 우호도를 올린다. CD 흐름 `005877f0`은 빈 흐름이다. `evidence:manual`, `evidence:client`
- 狩猟·談話도 초대객과의 우호도를 바꾼다(그룹 0 #78·#80). 우호도는 W와 CD 데이터에 이름만 있고 수치·표시 UI가 없다. CD 실행 파일에도 우호도 표시 문자열이 없다. `evidence:client`
- 미구현 후보 U-18(사교·영향력·우호도)로 분류돼 있다.

### 3.2 제안

- **저장:** `Friendship(a,b)`는 방향 없는 0..100 값이고 기본 50이다. 최대 4,096쌍을 전략 상태에 둔다.
- **会見:**
  - 조건: 같은 스폿(소유자 포함)에 있는 다른 인물, MCP 10, 상대가 접속 중일 필요는 없다.
  - 효과: 우호도 +3, 같은 쌍은 1G일 1회로 제한한다. 상대에게 "○○와 회견했습니다" 통지를 보낸다.
  - 화면: 스폿 인물 목록에서 대상을 고르는 조작창(조회→확정)을 쓴다.
- **표시:** 원본에 우호도 UI가 없으므로 인물 정보창의 기존 재구성 탭에 "나와의 우호도"를 숫자로 추가한다.
- **사용처(후속):** 謀議 성공률, 狩猟·談話 결과, NPC 대응에 쓸 수 있게 조회 함수만 열어 둔다. 이번 범위에서는 다른 명령 효과를 바꾸지 않는다.
- **검사:** 같은 스폿·다른 스폿·자기 자신·1일 제한·저장·재시작을 확인한다. 원본 두 개로 회견 통지와 양쪽 우호도 표시를 확인한다.

### 3.3 결정 요청

1. 우호도 범위·초기값(0..100, 50)과 회견 증가량(+3, 쌍당 1G일 1회)
2. 우호도를 플레이어에게 숫자로 보여 줄지, 숨긴 값으로 둘지

## 4. 구현 순서 제안

승인되면 ① 워프 CP·대기(이동 흐름의 남은 공백), ② 사관학교, ③ 회견·우호도 순으로 각각 별도 PR로 구현한다. 각 PR에서 해당 체크리스트 줄과 이 문서의 상태를 갱신한다.
