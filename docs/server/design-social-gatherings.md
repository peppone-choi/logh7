# 설계안: 야회·수렵·회담·담화 (U-18 사교)

작성: Peppone Choi · 2026-10-31 · 상태: 승인(사용자 2026-10-31, 제안대로)

- 대상 체크리스트: 11절 `夜会`·`狩猟`·`会談`·`談話`, 10절 U-18
- 이미 있는 기반: 연설 14(`SocialActions`), 회견 87과 우호도(`MeetingActions`, [회견 설계](design-warp-academy-meeting.md#3-회견会見과-우호도))

## 1. 근거

`evidence:manual` W p.72–73과 `evidence:client` CD `constmsg.dat` 그룹 0 #77–80의 설명:

| 명령 | 장소 | 초대 | 효과 | 비용 |
|---|---|---|---|---|
| 夜会(야회) | 자기 수도 저택 | 특정 인물 | 영향력 변화 | MCP 320·대기 0·소요 0 |
| 狩猟(수렵) | 자기 봉토 행성의 저택 | 특정 인물 | 초대객과의 우호도·영향력 변화 | 같음 |
| 会談(회담) | 자기가 머무는 호텔 객실 | 특정 인물 | 영향력 변화 | 같음 |
| 談話(담화) | 자기가 머무는 호텔 객실 | 특정 인물 | 초대객과의 우호도·영향력 변화 | 같음 |

- 원본 시설표: 그룹 73 #17 호텔, #18 저택. 서버 시설 배치는 이미 있다. 호텔(17)은 로비·객실(13), 저택(18)은 로비·무도회장(14)·객실·숲(15)이다.
- **수치(영향력·우호도 변화량)와 "성과" 판정식은 어디에도 없다.** 아래 수치는 모두 `evidence:guess`다.
- 현재 저택은 오딘에만 있고, 봉토 행성에는 저택이 없다. 객실(13)은 소유자 본인만 들어갈 수 있고, 무도회장(14)·숲(15)은 입장 규칙이 없다.

## 2. 제안

### 2.1 장소와 실행 조건

| 명령 | 실행 위치(주최자) | 추가 조건 |
|---|---|---|
| 야회 | 자기 진영 수도 저택의 무도회장(14) | 제국: 작위 보유자. 동맹: 하이네센에도 저택(18)을 추가하고 정치가·장관급(준장 이상)만 |
| 수렵 | 자기 봉토 행성 저택의 숲(15) | 봉토를 가진 인물. 봉토가 지정되면 그 행성에 저택(18)을 둔다 |
| 회담·담화 | 자기 호텔 객실(13) | 현재 거점의 호텔 |

- 무도회장·숲은 "소유자 = 그 거점의 저택 주인"인 사유 공간으로 두고, 소유자와 그가 초대해 수락한 인물만 들어간다.

### 2.2 초대 흐름

1. 주최자가 장소에서 명령을 열면, **같은 거점에 있는 같은 진영 인물** 목록을 보여 준다(회견의 인물 목록 요청 재사용, 범위만 스폿→거점으로 넓힘).
2. 대상을 고르고 실행하면 상대에게 60초 초대 요청을 보낸다(명함 교환과 같은 요청/수락 방식). 이때는 CP를 쓰지 않는다.
3. 상대가 수락하면 상대를 주최자의 장소로 옮기고, 그 순간 효과를 정산하며 주최자 MCP 320을 결제한다. 거절·시간 초과·상대 이동이면 아무것도 바뀌지 않는다.
4. 같은 주최자는 사교 명령(야회·수렵·회담·담화)을 게임 1일에 1회만 성립시킬 수 있다. 같은 쌍의 수렵·담화 우호도 변화도 게임 1일 1회다.

### 2.3 성과와 효과

- 성과 = 주최자 정치 능력 + 0~49 난수(결정적, 주최자·날짜 기준).
  - 100 이상: 대성공 / 70~99: 성공 / 70 미만: 실패
- 주최자 영향력: 대성공 +3, 성공 +1, 실패 −1 (0~100 범위)
- 초대객 영향력: 성공 이상이면 +1
- 우호도(수렵·담화만, 주최자–초대객 쌍): 대성공 +10, 성공 +5, 실패 −3 (0~100)
- 야회는 영향력 변화량을 1.5배(올림)로 한다(수도 저택·작위 행사라는 점을 반영). 회담은 기본값.

### 2.4 화면

- 원본에는 이 명령들의 실행 창이 없으므로, 연설·회견처럼 호환 DLL이 작은 조작창을 만든다: 대상 ◀/▶, 성과 예상 없이 "초대" 버튼, 결과(성과 등급·영향력·우호도 변화) 표시.
- 초대받은 쪽에는 수락/거절 창(명함 교환 요청 창 재사용)을 띄운다.

### 2.5 저장과 검사

- 사교 기록(주최자별 다음 가능 시각, 쌍별 우호도 다음 변경 시각)은 기존 사회 상태(`SocialState`)에 붙인다.
- 검사: 장소·작위·봉토 조건, 초대 수락/거절/만료, 성과 경계값, 1일 제한, 결제 원자성, 저장·재시작.
- 원본 확인: 두 원본으로 회담 1건(초대→수락→이동→영향력 표시)과 수렵 1건(우호도 표시)을 확인한다.

## 3. 결정 요청

1. 야회 자격(제국 작위 보유자 / 동맹은 하이네센 저택 추가 + 준장 이상·정치가) 그대로 둘지
2. 초대 범위(같은 거점·같은 진영)와 60초 수락 방식
3. 성과식과 효과 수치(2.3)
4. 구현 순서: 회담·담화(호텔, 기존 객실 활용) → 수렵(봉토 저택) → 야회
