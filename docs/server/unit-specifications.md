# 생산 유닛의 성능 목록

작성: 최병호 · 2026-10-25 · 관련: LOGH-28·33

부대 할당·재편성·보충을 연결하기 위한 선행 작업이다. 생산 창고에 있는 일반 함선의 성능 목록이 없고 병종 목록이 비어 있던 초기 접속 경로를 보완했다. 부대 상태·명령 실행·전투 연결은 아직 완료되지 않았다.

## 근거와 범위

`UnitSpecifications`는 생산 대상 일반 함선 106종과 기존 기함 6종, 병력 11종을 기존 검토 CSV에 조인한다. 이름이 잘린 기함 2행, 원작 고유 기함 전체, 요새·경비함·전투정의 별도 성능 정의는 이번 범위에 포함하지 않는다. 원자료를 복사하거나 CSV의 미확정 이름을 고치지 않는다.

- 일반 함정 1유닛은 300척이고 기함은 1척이다. 매뉴얼 웹판 p.46의 유닛 구분을 따른다. `evidence:manual`
- 일반 함선의 건조 기간·필요 승조원 유닛 수·색적·속도·장갑·무기 위력·미사일 소모·전투정 탑재수·물자 적재량·수리는 기존 `ship-units.csv`에서 읽는다. `-`는 현재 전송값 0으로 해석하고 쉼표·소모량 쌍을 분리한다. 원래 표기와 출처는 CSV에 남는다. 건 소모량은 원본 wire에 별도 필드를 확정하지 못해 새로 끼워 넣지 않는다. `evidence:manual`(수치), `evidence:guess`(0 변환)
- 병력의 훈련 과정·육전 공격/방어 값은 `crew-units.csv`를 따른다. 승조원의 육전 공방 공란은 0으로 보낸다. 근위병·교도대·장미의 기사도 성능 정의는 전달하지만 자동 모병 허용 품목을 새로 추가한 것은 아니다. `evidence:manual`

## 종류 번호와 원본 구조

함선은 `030a→030b`, 병력은 `030c→030d`로 전송한다. 기함과 일반 함선의 종류는 서로 다르다. 예를 들어 제국 기함 전함은 0, 일반 전함Ⅰ은 32이며 동맹은 각각 89·119다. 이름·모델 번호·분류 번호도 종류와 구별한다. `evidence:client`

병력의 **서버 내부/저장 번호는 0–10, 원본 통신 종류는 1000–1010**이다. `004c4c50`은 병종을 원래 객체로 옮길 때 1000을 뺀 인덱스를 사용한다. 병종 성능뿐 아니라 `0327` 창고의 병력 목록에도 통신 번호를 사용한다. 이전 자동 생산 변경의 0 기반 병력 전송을 수정했다. 저장 파일의 기존 번호는 유지하므로 재고·공정을 초기화하거나 마이그레이션하지 않는다. 호환 정보 창은 1000을 뺀 번호로 원본 이름 그룹 86을 조회한다. `evidence:client`

함선 원본 읽기 경로는 `004109a0/00411a60`이며, 수신 원본 레코드는 140바이트다. 전송에는 패딩이 없고 이름 길이에 따라 레코드 크기가 달라진다. 원래 실제 객체의 `+0x218`은 유닛당 척수다. 병력 경로 `004121f0/00412770`은 22바이트 wire를 24바이트 레코드로 읽는다. 종류·type·category·공적·훈련 과정·훈련 비용·자원·속도·육전 공방·적재 순서를 보존한다. `evidence:client`

## 남은 설계값

원본 constmsg 그룹 114의 함급 분류와 type 9/10의 항공 구조 초기화 경로를 참고했다. 아래 category/type 대응과 일반 함선 모델 배정은 현재 설계값이다. 여덟 세부 형식에 각각 다른 원본 모델을 확정한 것이 아니며 같은 함급의 기본 모델을 공유한다. `evidence:client`(그룹·초기화 경로), `evidence:guess`(아래 배정)

## 검증

엔진은 모든 생산 품목의 검토된 행 조인, 300/1척 구분, 승조원 필요량·상선 예외·적재량·소모량을 확인했다. 프로토콜의 병력 1000 기반 종류, 레코드 길이·필드 위치·중복 및 범위 검사와 인증된 암호화 TCP의 함선 112종·병력 11종 수신 검사를 통과했다. 관련 엔진·프로토콜·게이트웨이 회귀 검사와 x86 `/W4 /WX` 빌드도 통과했다.

원본 클라이언트 한 개에서 초기 수신 캐시의 함선 112종·병력 11종과 실제 원본 객체의 활성 등록을 확인했다. 일반 전함Ⅰ은 제국/동맹 모두 300척이며 승조원은 각 5/4유닛, 건조 기간은 90이었다. 양쪽 재시작 뒤에도 성능 캐시의 종류·기간·승조원·척수가 같았다. 창고에서 전함 2유닛=600척·구축함 16유닛=4800척, 병력 이름·Green 수량을 표시했고, 원본 병력 레코드의 종류는 1000·1003이었다. 원본 보존·대상 프로세스 정리·오디오 복원을 확인했다. `evidence:client`

최종 빌드의 수신 캐시에서 일반 함선 106종의 척수·기간·승조원·물자 적재량을 원본 CSV와 대조했다. 112종의 수신 레코드와 실제 객체의 척수·기간·승조원이 일치했고 병력 11종도 모두 활성 등록됐다. 배정한 모든 중형/대형 모델 경로의 실제 파일 존재를 확인했다. 대형 파일이 없는 동맹 모델 1022 후보는 1023으로 바꿨다. 파일 존재 확인은 해당 함종에 맞는 외형이라는 입증과 다르다.

캡처와 읽기 전용 캐시 확인은 `work/fleet-catalogue-20261025/`에 보존한다. 실제 두 클라이언트 동시 편성, 일반 유닛의 모든 3D 렌더링, 재편성/보충 실행과 전투 성능은 아직 검증하지 않았다.
