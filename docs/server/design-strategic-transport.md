# 설계안: 전략 수송(輸送計画·輸送中止·搬出入, U-15)

작성: Peppone Choi · 2026-10-31 · 상태: 승인(사용자 2026-10-31, 제안대로)

## 1. 근거

- `evidence:manual` W p.71/72 명령표

  - 搬出入: MCP 160. 특정 행성/요새를 대상으로 만든 수송 패키지를 반출입한다.
- `evidence:client` CD `constmsg.dat`에 남은 화면 문자열

  - 그룹 22·46·51: 수송 창고, 수송 패키지, 수송 유닛 수, 수송원/수송처 성계·행성/요새.
  - 원본 통신 이름표: 패키지(0x0328/0329), 부대 수송(0x0332/0333), 반출입(0x0c08).
- 기존 서버: 수송함대(`OutfitKind.TRANSPORT`, 최대 6,900척)와 전용 창고, 함종별 물자 탑재량, 할당(割当)·완전보급의 수송함대 경로가 이미 있다.
- **원작의 권한 카드·패키지 용량·수송 중 손실 규칙은 없다.** 아래는 모두 `evidence:guess`다.

## 2. 제안

### 2.1 흐름

1. **輸送計画:** 수송원 행성/요새의 창고에서 품목(군수물자, 함정 유닛, 승조원·육전대 유닛)과 수량을 고르고 수송처 행성/요새를 정한다. 그 수량을 수송원 창고에서 빼서 "수송 패키지"로 묶어, 수송원 거점의 **수송 창고**에 둔다.
2. **搬出入(반출):** 수송원 거점에 정박한 수송함대 사령관이 그 거점 수송 창고의 패키지를 자기 부대에 싣는다. 실을 수 있는 양은 수송함대의 물자 탑재량과 유닛 수 한도 안이다.
3. 수송함대는 기존 부대 이동으로 수송처까지 간다.
4. **搬出入(반입):** 수송처에 정박한 수송함대 사령관이 실은 패키지를 수송처 창고에 내린다. 패키지는 소멸하고 품목이 수송처 재고가 된다.
5. **輸送中止:** 아직 싣지 않은 패키지(수송 창고에 있는 것)를 수송원 창고로 되돌린다. 실은 뒤에는 중지할 수 없다.

### 2.2 권한

| 명령 | 카드 |
|---|---|
| 輸送計画·輸送中止 | 이미 할당(割当)을 가진 병참 직무 카드(제국 24·25, 동맹 150) |
| 搬出入 | 수송함대 사령관 카드(제국 44, 동맹 180) |

### 2.3 규칙

- 패키지 하나는 수송원 하나·수송처 하나·품목 여럿이다. 거점당 열린 패키지는 최대 20개다.
- 수송함대가 격침돼 유닛을 잃으면, 실은 패키지는 잃은 비율만큼 함께 잃는다.
- 같은 진영·진영 0(반란 아님)의 거점끼리만 보낼 수 있다.

### 2.4 화면

- 원본 CD에는 이 명령들의 실행 창이 없다. 그래서 기존 할당 창처럼 호환 DLL이 조작창을 만든다.
  - 輸送計画: 수송처 선택 → 품목·수량 선택 → 결정.
  - 輸送中止: 패키지 선택.
  - 搬出入: 거점의 패키지 목록(반출) / 실은 패키지(반입) 선택.

### 2.5 저장과 검사

- 패키지는 재고 저장에 새 행으로 둔다.
- 검사: 권한, 수송원 재고 차감, 탑재 한도, 반출→이동→반입 왕복, 중지 반환, 격침 손실, 저장·재시작.
- 원본 확인: 한 원본으로 계획→반출→이동→반입 전체와 수송처 재고 증가를 확인한다.

## 3. 결정 요청

1. 흐름(계획=패키지 생성, 搬出入=수송함대 적재/하역)과 권한(병참 카드 / 수송함대 사령관)
2. 격침 시 비율 손실, 거점당 패키지 20개 상한
3. 구현 순서: 서버(계획·중지·반출입) → DLL 창 → 원본 실기

## 4. 구현 (2026-10-31)

- 서버: `TransportActions`(28/29/65)와 `TransportPackage`. 패키지는 전략 상태 저장(`S` 행)의 선택적 여섯째 구획(`id:진영:수송원:수송처:물자:함정:병력:적재부대:적재시척수`)이다. 패키지가 없으면 기존 다섯 구획 그대로 저장한다.
- 탑재 한도(`evidence:guess`): 물자는 수송함대 물자 탑재량에서 부대 보유 물자와 이미 실은 패키지를 뺀 값이다. 유닛 칸은 살아 있는 함정 유닛당 수송함·상선·병원수송함·양륙함 10, 그 밖의 함정 2이며, 탑승 중인 육전대와 실은 패키지 유닛이 칸을 차지한다.
- 손실: 반입할 때 `현재 척수 / 적재 시 척수` 비율로 물자·유닛을 내림 계산한다.
- 통신: `0x7f00` 확장. 28은 base=수송원, target=수송처, amount=물자(u16), value=유닛 종류(함정 0~199, 승조원·육전대 1000~1015, 0xffff 없음), argument=유닛 수. 29는 target=패키지. 65는 argument=수송함대, target=패키지. 29·65 미리보기는 패키지 목록을 `수송처/물자[+][*]` 이름으로 돌려준다(`+` 유닛 포함, `*` 적재 중).
- 카드 명령표: 병참 카드 24/25/150에 28·29, 수송함대 사령관 카드 44/180에 65를 더했다.
- DLL `transport_actions.h`: 수송 계획(수송원·수송처·물자·유닛 종류·유닛 수), 수송 중지·반출입(패키지 목록 선택)을 기존 전략 명령 창으로 만든다. 유닛 종류는 아직 번호로만 표시한다.
- 원본 확인(`work/transport-20261031`): 제국 병참 카드(통수본부 작전2과장)와 수송함대 사령관 카드에 새 명령이 나타났다. 비켄바흐(1032)→게른스하임(1033)으로 물자 2000·육전대 2유닛 패키지와 물자 2000 패키지를 만들고(MCP 80씩, 수송원 물자 121530→117530, 육전대 20→18 저장), 수송 중지로 둘째 패키지를 되돌리고, 반출입으로 첫 패키지를 수송함대 272에 실었다(MCP 160, 화면 `적재 중(반입 대상)`).
  - 이어서 함장 카드로 출항·기항해 게른스하임에 도착했다. 시험 인물이 순찰대도 지휘해 함대 동반 이동 조건이 걸리지 않았으므로 수송함대 위치는 저장 상태에서 옮겼다. 그 뒤 반입으로 수송처 물자 105920→107920·육전대 0→2가 저장되고 패키지가 사라졌다(MCP 160).
- 남은 것: 실제 격침 손실의 원본 확인, 수송처 소유권이 바뀐 패키지 처리, 유닛 종류 이름 표시.
