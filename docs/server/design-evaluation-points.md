# 평가 포인트 획득 설계 (제안, 검토 대기)

작성: Peppone Choi · 2026-10-31

## 1. 배경

- 매뉴얼 W p.34 `evidence:manual`
  - 평가 포인트(評価ポイント)는 세션 안에서만 쓰는 값이다.
  - 얻는 경로는 세 가지다.
    1. 전술에서 적 유닛을 격파하거나 적 행성/요새를 점령한다.
    2. 소속 세력이 승리하면 최종 계급에 따라 받는다. 생존해 있어야 한다.
    3. 준장 이상은 사망하면 계급에 따른 고정값을 받는다. 승패와 무관하다.
  - 쓰는 곳은 기함 구매와 경비함 구매다(update03·05).
- 수치는 매뉴얼에 없다. 아래 수치는 모두 `evidence:guess`다.
- 현재 서버는 평가 포인트를 기함 구매 때 차감만 한다. 증가 경로가 없어서, 정상 플레이로는 기함을 살 수 없다.

## 2. 제안

| 경로 | 지급 시점 | 지급 대상 | 수량(제안) |
|---|---|---|---|
| 적 함정 격파 | 전술 피해 정산에서 함정이 격침될 때 | 사격한 유닛의 전술 지휘자. 개인 기함이면 본인 | 격침 척수 10척당 1(올림) |
| 적 기함 격침 | 기함 격침·귀환 처리 때 | 사격자 | 50 |
| 적 거점 점령 | `BaseOccupation`에서 소유권이 바뀔 때 | 그 칸의 승리 진영 전술 참가자. 거점 주둔 육전대 지휘관을 우선한다 | 행성 100, 요새 300을 참가자 수로 균등 분배 |
| 세력 승리 | 세션 결과 확정 때 한 번 | 승리 세력의 생존 인물 | 최종 계급별로 원수 1000 → 이등병 50 |
| 준장 이상 사망 | 미구현(U-11 전사)이므로 이번 범위에서 제외 | — | — |

### 구현 원칙

- **저장 방식:** 기존 공적과 같은 장부 방식으로 한다.
  - 전술 누계와 정산 누계를 따로 두고, 정산 때 `StrategicPerson.evaluation`에 합산한다.
  - 재시작이나 재접속 때 두 번 지급하지 않는다.
- **위조 방지:** 지급은 서버의 실제 격침·점령·결과 사건에서만 한다. 클라이언트 값은 쓰지 않는다.
- **표시:** 지급은 기존 인물 레코드의 평가 칸에 바로 보인다. 별도 알림은 이번 범위에서 만들지 않는다.
- **상한:** u32 최대에서 포화시킨다. 세션이 바뀌면 다음 세대 인물로 넘기지 않는다(세션 한정).

## 3. 결정이 필요한 점

1. 위 수치를 그대로 대체 정책으로 쓸지
2. 점령 보상을 참가자 균등 분배로 할지, 주둔 지휘관 한 명에게 줄지
3. 세력 승리 보상을 이번에 함께 연결할지, 전술 경로만 먼저 할지
