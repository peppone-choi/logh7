# 평가 포인트 획득 설계 (2026-10-31 승인, 일부 구현)

작성: Peppone Choi · 2026-10-31

## 1. 배경

- 매뉴얼 W p.34 `evidence:manual`
  - 평가 포인트(評価ポイント)는 세션 안에서만 쓰는 값이다.
  - 얻는 경로는 세 가지다.
    1. 전술에서 적 유닛을 격파하거나 적 행성/요새를 점령한다.
    2. 소속 세력이 승리하면 최종 계급에 따라 받는다. 생존해 있어야 한다.
    3. 준장 이상은 사망하면 계급에 따른 고정값을 받는다. 승패와 무관하다.
  - 쓰는 곳은 기함 구매와 경비함 구매다(update03·05).
- 수치는 매뉴얼에 없다. 아래 수치는 모두 `evidence:guess`다.
- 현재 서버는 평가 포인트를 기함 구매 때 차감만 한다. 증가 경로가 없어서, 정상 플레이로는 기함을 살 수 없다.

## 2. 제안

| 경로 | 지급 시점 | 지급 대상 | 수량(제안) |
|---|---|---|---|
| 적 함정 격파 | 전술 피해 정산에서 함정이 격침될 때 | 사격한 유닛의 전술 지휘자. 개인 기함이면 본인 | 격침 척수 10척당 1(올림) |
| 적 기함 격침 | 기함 격침·귀환 처리 때 | 사격자 | 50 |
| 적 거점 점령 | `BaseOccupation`에서 소유권이 바뀔 때 | 그 칸의 승리 진영 전술 참가자. 거점 주둔 육전대 지휘관을 우선한다 | 행성 100, 요새 300을 참가자 수로 균등 분배 |
| 세력 승리 | 세션 결과 확정 때 한 번 | 승리 세력의 생존 인물 | 최종 계급별로 원수 1000 → 이등병 50 |
| 준장 이상 사망 | 미구현(U-11 전사)이므로 이번 범위에서 제외 | — | — |

### 구현 원칙

- **저장 방식:** 기존 공적과 같은 장부 방식으로 한다.
  - 전술 누계와 정산 누계를 따로 두고, 정산 때 `StrategicPerson.evaluation`에 합산한다.
  - 재시작이나 재접속 때 두 번 지급하지 않는다.
- **위조 방지:** 지급은 서버의 실제 격침·점령·결과 사건에서만 한다. 클라이언트 값은 쓰지 않는다.
- **표시:** 지급은 기존 인물 레코드의 평가 칸에 바로 보인다. 별도 알림은 이번 범위에서 만들지 않는다.
- **상한:** u32 최대에서 포화시킨다. 세션이 바뀌면 다음 세대 인물로 넘기지 않는다(세션 한정).

## 3. 결정이 필요한 점

1. 위 수치를 그대로 대체 정책으로 쓸지
2. 점령 보상을 참가자 균등 분배로 할지, 주둔 지휘관 한 명에게 줄지
3. 세력 승리 보상을 이번에 함께 연결할지, 전술 경로만 먼저 할지

## 4. 구현 (2026-10-31)

- **승인:** 사용자가 제안대로 승인했다.
- **구현한 경로**
  - 모든 사격 피해가 지나는 `TacticalCombat.strike`에서 지급한다.
    - 일반 유닛 격침: 10척당 1점(올림)
    - 개인 기함 격침: 50점
  - 사격자: 개인 기함이면 그 소유자, 일반 유닛이면 전술 지휘자(`TacticalAuthority.commander`)다.
    - 지휘자가 없는 NPC 사격에는 지급하지 않는다.
  - 점령: `BaseOccupationOperations.advance`에서 지급한다.
    - 행성 100점, 요새 300점
    - 승리 진영의 그 거점 지상 참가 부대 지휘관과, 같은 칸의 전술 중인 플레이어가 균등 분배한다. 나머지는 낮은 ID부터 1점씩 준다.
- **저장 방식:** 지급은 피해·점령과 같은 재고 변경에 들어가, 같은 월드 커밋으로 확정된다. 그래서 별도 장부 없이도 재시작해도 두 번 지급되지 않는다. 설계에서 말한 "공적과 같은 장부 방식"을 이 방식으로 대신했다.
- **미구현:** 세력 승리 보상.
  - 종료 판정이 커밋된 재고에서 다시 계산되는 구조라, 재시작 때 두 번 지급하지 않으려면 지급 표지를 따로 저장해야 한다.
  - 지금은 세션 종료 뒤 평가 포인트를 쓰는 곳(명성 환산, U-27)이 없다.
  - 그래서 명성 환산과 함께 구현한다.
- **검사:** `EvaluationPointsTest` 5건이 통과했다.
  - 격침 환산, 지급·상한, 점령 분배, 사격자 판정
  - `strike` 통합 검사
- **원본 실기**(`work/eval-20261031`)
  - 알테나 전투에서 지휘관 없는 제국 순찰대 266이 동맹 함대를 125척 격침했고, 아무에게도 지급되지 않았다(지휘자 없음, 설계대로).
  - 시험 준비로 266에 지휘관을 지정하자 NPC 전술이 그 부대를 움직이지 않아 교전이 없었다.
  - 따라서 지휘자가 있는 사격의 원본 지급은 미확인이다.

## 기함 구매 전후의 평가 포인트 (2026-11-08)

기함·경비함 구매 목록은 함종의 가격과 계급 조건에 더해 본인의 현재 평가 포인트를 표시한다. PCP 80을 낼 수 있으면 PCP를, 부족하면 전액 대체하는 MCP 160을 안내하며 두 잔액이 모두 부족한 경우에도 표시한다. 실행 시 서버가 장소·계급·잔액을 다시 검사한다. 성공 응답은 확정된 평가 포인트를 같은 창에 표시한다.

오딘 기함공창의 시험 저장에 평가 포인트 50과 PCP 0을 넣었다. 1920×1080 원본에서 구축함 50점과 순항함 200점으로 목록을 바꿔 보고, 구축함을 선택해 평가 포인트 50→0과 MCP 1000→840을 확인했다. 같은 기함의 두 번째 주문은 거절됐고 추가 차감이 없었다. 서버 재시작 뒤 원본 구매 창에 보유 0점과 MCP 840이 표시됐으며 저장에서 구축함(3)과 접수처 위치를 확인했다. 화면은 `work/flagship-receipt-20261108/`에 보존했다. `evidence:client`
