# 게임 시계·세션 엔진

작성자: 최병호 · 2026-10-08 · LOGH-27

`WorldEngine`의 단일 작성 코루틴이 `SessionSimulation`을 갱신한다. 스케줄러는 단조 시각으로 경과한 실시간을 큐에 넣고, 시뮬레이션은 이를 게임 시간으로 변환한다. 운영체제 시각 보정의 영향을 받지 않으며 밀린 간격은 누락 없이 합산한다. 전략 틱·전술 인스턴스 틱·CP 회복은 첫 회차와 발생 횟수를 담은 이벤트로 전달해 긴 지연에도 틱마다 객체를 만들지 않는다.

## 규칙과 설정

- 게임 시간 배속 24, 세션 정원 2,000명: 매뉴얼 W p.10. `evidence:manual`
- CP 회복 간격 게임 2시간, 실 5분; 오프라인 캐릭터에도 적용: W p.27. 현재 엔진은 회복 이벤트를 만들며 실제 PCP/MCP 회복량 계산은 LOGH-29에서 구현한다. `evidence:manual`
- 수도 행성 점령, 어느 정규 진영의 지배 성계 3개 이하, 801-07-27 도달 시 종료: W p.12. 승리 평가·공적 보상 계산은 포함하지 않는다. `evidence:manual`
- 클라이언트 전략 표시 함수는 초→일→30일 월→12개월 연으로 계산하고 연도에 795를 더한다. 서버 종료일도 이 달력으로 환산한다. 801-07-27은 epoch 이후 204422400초다. `evidence:client`
- 시작 795-01-01은 P2 epoch=0을 유지하는 잠정값이다. 매뉴얼의 정확한 시작 날짜를 확정한 것이 아니다. 전략 틱 실 1초·전술 틱 실 250ms는 로컬 스케줄 선택이다. `evidence:guess`

수치는 `server/engine/src/main/resources/rules/session.properties`에서 읽는다. `LOGH7_SESSION_RULES`로 외부 설정 파일을 지정할 수 있다. 값의 근거·미확정 여부는 파일 주석에 기록한다. 서버가 돌고 있는 동안 파일을 바꾸어 즉시 적용하는 기능은 없다.

## 세션 상태

시뮬레이션 API는 가입·접속 종료·세션 제외·전술 인스턴스 개폐·영토 갱신·종료 후 재시작을 지원한다. 오프라인 캐릭터도 정원을 차지하고, 제외 후 같은 세션 복귀는 제너레이트·이전 소속 진영만 허용한다. 재시작은 세션 세대를 올리고 시계·멤버·복귀 제한·전술 상태를 초기화한다. `evidence:manual`(복귀·정원), `evidence:guess`(내부 상태 모델)

영토 판정에는 양 진영의 수도 성계를 포함한 지배 성계 수와 점령된 수도 소유 진영을 호출자가 전달해야 한다. 아직 월드 시드·점령 로직에서 호출하지 않는다. 종료는 한 번만 발생하고 종료 후 시계·틱·가입은 멈춘다. 잘못된 생애주기 명령은 거절 횟수에 기록하고 엔진을 중단시키지 않는다.

## 클라이언트 연결과 확인 범위

앱의 실제 게임 시계를 `0x0300 → 0x0301` 초기화 응답의 u32 초로 전달한다. `/snapshot`에 현재 시각·전략/전술 틱·CP 회복 이벤트 수·세션 상태를 표시한다. 기존 상수 epoch=0 응답을 대체한다.

`SessionSimulationTest`와 `WorldEngineTest`는 실 1시간=게임 1일, 소수 간격 누적, 정확히 실 5분의 CP 회복, 전술 인스턴스의 공유 시간·누적 틱, 2,000명 정원과 오프라인 슬롯, 제외 후 복귀, 세 종료 조건과 종료 후 정지·재시작을 확인한다. 프로토콜·게이트웨이 테스트는 실제 암호 프레임 안의 시계 값을 검사한다.

로컬 앱에서 `/snapshot`의 게임 시각 진행을 확인했고, `work/logh27-host-20261008/run-01`의 실제 클라이언트는 새 시계 응답을 받고 전략 화면에 진입했다. 원본 보존·활성 오디오 출력 유지 중 음소거·프로세스 정리는 통과했다. 실제 전술 게임·CP 수치 회복·시간 제한까지 장기 실행은 시험하지 않았다.

## 로그인·접속 종료 연결

`0x0205` 게임 로그인은 인증 티켓의 계정과 서버 저장 캐릭터로 엔진에 가입을 요청한다. Netty 이벤트 루프는 판정을 기다리며 블로킹하지 않고, 같은 루프로 돌아온 결과가 승인된 뒤에만 `0x0206` 성공을 보낸다. 정원 초과·동일 계정의 중복 온라인·종료·다른 세대는 거절한다. 실패 응답의 1 값은 로컬 정책이며 원 서비스의 오류 코드 의미를 복원한 것은 아니다. `evidence:guess`

연결 종료는 엔진의 해당 연결 토큰만 오프라인으로 바꾼다. 이전 연결이 늦게 종료돼도 새 접속을 끊지 않으며 가입 완료 전에 소켓이 닫히는 경우도 가입 뒤 종료 순서를 유지한다. 오프라인 슬롯은 유지된다. 현재 세션이 끝나거나 세대가 바뀌면 이전 게임 연결을 닫고 재로그인을 요구한다.

`run-02` 실제 게임 접속 중 `/snapshot`에서 참가자 1·온라인 1을 관측했고, 게임 종료 뒤 참가자 1·온라인 0을 확인했다. 전략 진입·원본 보존·오디오·정리는 통과했다. 정원 초과·중복 접속·조기 소켓 종료·이전 세대 거절은 단위 테스트로 확인했다.

## 종료·재시작과 캐릭터 저장 세대

종료 후 `session.restart_delay_real_millis`(기본 실 60초)가 지나면 자동 재시작한다. localhost 운영 API `POST /session/restart`는 종료된 세션을 즉시 재시작하며 실행 중이면 HTTP 409다. 지연 값은 원 서비스 수치가 아닌 로컬 정책이다. 엔진이 먼저 세대 표식을 원자적으로 저장하고 성공한 뒤 새 상태를 공개한다. 저장 실패 시 이전 종료 상태를 유지한다.

운영 상태 변경 POST(`/commands/probe`, `/session/restart`)에는 `LOGH7_OPS_AUDIT_FILE`로 지정한 쓰기 가능한 감사 파일과 `X-LOGH7-Operator` 헤더(`[A-Za-z0-9._-]{1,64}`)가 필요하다. 파일 미설정 또는 REQUESTED 기록 실패는 503으로 큐 제출 전에 거절하며, 헤더 오류는 400이다(미설정 검사가 먼저다). 헤더는 자기 신고 식별자이지 인증이 아니며 유일한 접근 통제는 `127.0.0.1` 바인딩이다. 감사 파일은 append-only JSONL이고 각 REQUESTED/RESULT 행을 fsync한다. REQUESTED에는 원격 주소, RESULT에는 QUEUED/RESTARTED/CONFLICT/FAILED 결과가 남으며 같은 requestId로 연결한다. 결과 기록 실패는 500으로 알리지만 롤백하지 않는다. queued/restarted/conflict와 실패 시 적용 여부 미확정(outcome unknown)을 구분하므로 500을 보고 재시작을 무조건 재시도하지 말고 REQUESTED와 세션 상태를 확인한다. GET `/health`, `/snapshot`은 헤더 없이 기존대로 동작한다. 컨테이너 구성은 이번 변경에 포함하지 않아 별도 감사 파일 설정 전 POST는 503이다. 로그 회전·백업 및 인증/RBAC는 후속 범위다.

`LOGH7_SESSION_GENERATION_FILE`로 세대 표식 파일을 지정한다. 기본은 `LOGH7_CHARACTERS_FILE` 옆 `<파일명>.session-generation`이다. 둘 다 없으면 메모리 전용이다. 세대 1은 기존 캐릭터 파일, 이후 세대는 `<파일명>.session-N`을 사용한다. 이전 파일은 덮어쓰거나 삭제하지 않으며 새 세션의 로비는 비어 있는 캐릭터 저장소를 조회한다. 원작 캐릭터·접수 정보는 새 세션으로 가져가지 않는다. 제너레이트 이월의 평가 조건은 별도 캐릭터 성장·세션 보상 구현 전까지 적용하지 않는다.

종료 직전으로 시작하는 별도 설정·캐릭터 사본의 `run-03`에서 실제 클라이언트 전략 진입 뒤 시간 제한에 따른 연결 종료 UI, 세대 1→2 자동 전환·참가자 0·세대 표식 저장을 확인했다. 이전 캐릭터 파일은 그대로였다. 시험의 재시작 지연은 5초였고 실제 운영 기본값은 60초다. 실행기의 원본 보존·오디오·정리 검사도 통과했다.

이 표식은 세대 번호만 보존한다. 프로세스 재시작 시 게임 시간·오프라인 멤버·월드 상태를 그대로 복구하는 스냅샷/WAL과 백업은 LOGH-43 범위다. 현재 점령 파이프라인은 저장된 거점 소유권에서 `Territory` 종료 명령을 도출한다(아래 2026-10-29 연결 범위). 세션 제외·복귀 제한은 엔진에서 강제하며 전사·제외 게임 커맨드는 후속 게임 로직에서 연결한다.

## 2026-10-25 CP 잔량과 HUD 연결

회복 간격·오프라인 회복·전술 중 정지 및 전술 종료부터 다시 시간 계산은 W p.27

이 수치를 원작 확정값으로 쓰지 않는다. `evidence:manual` / `evidence:guess`

서버 내부 `NavigationRequest.tactical`은 캐릭터별 회복 정지·재개를 처리한다.
다른 그리드의 전투가 모든 플레이어의 전략 이동을 막던 조건도 캐릭터별 상태로
바꿨다. 실제 전술 입장·종료 패킷에서 이 상태를 호출하는 연결은 전술 구현 범위에
남아 있다. 전술 화면 전체 구현 완료를 뜻하지 않는다.

이동 파일 `LOGH7-NAV-3`은 회복 기준 게임 시각과 정지 상태를 추가한다.
NAV-1/2의 위치·CP·항속·시설을 보존해 읽되 알 수 없는 과거 회복분은 임의로 더하지
않고 첫 조회 시각부터 계산한다. 시계가 되감긴 로컬 설정도 과거 시간을 추정하지
않는다. 서버 재시작에도 게임 시각을 이어가려면 `LOGH7_SESSION_STORE_DIR`를 함께
설정해야 한다. 회복 상태 저장 실패 시 새 잔량을 게시하지 않는다.

검사: 회복 경계·능력별 증가·상한·시간 나머지·오프라인·재개·파일 재개방·저장 실패,

## 2026-10-29 점령 결과와 세션 종료 연결

작성자: 최병호

매뉴얼 W p.12의 수도 함락·잔존 성계 3개 이하 종료 조건을 실제 월드 저장 상태와
연결했다. 오딘/하이네센의 정규 소유권이 상대 정규 세력으로 바뀌면 원래 수도의
세력을 패배 대상으로 기록하며, 수도 함락을 성계 감소보다 우선한다. `evidence:manual`

성계 수는 해당 그리드의 모든 거점이 같은 정규 세력·진영 0에 속할 때만 센다.
혼합·중립·반란 거점이 있는 성계는 어느 정규 세력의 완전 지배로도 세지 않는다.
이 계산법은 복원 설계이며 원작 확정 공식은 아니다. 초기 두 세력이 각각 4개 이상의
완전 지배 성계를 가진 지도에서 감소 조건을 적용한다. 작은 시험 지도는 시작부터
종료되는 것을 막기 위해 성계 수 조건을 적용하지 않되 수도 함락은 적용한다.
중립/반란군의 수도 점령에 대한 종료 규칙·승리 등급·보상은 미완료다. `evidence:guess`

엔진은 지상전·점령의 월드 저장 후 종료를 판정하고, 종료 저널의 강제 저장이 성공한
뒤 종료 상태를 공개한다. 복구 후에도 대기열의 새 명령·입장을 처리하기 전에 저장된
수도/성계 소유권을 대조한다. 월드 저장과 종료 저널 사이의 장애는 같은 소유권으로
판정을 재생성하며, 종료 저장 오류가 난 엔진은 후속 변경을 차단한다. 두 저장소가
하나의 트랜잭션인 것은 아니다. [복구 검사](session-persistence.md#2026-10-29-점령과-종료-저널-사이의-복구)를 참고한다.

검사: 엔진 전체 606개 통과 후 저장 오류 차단 보완과 관련 8개 재검사, 저장소 전체
124개·게이트웨이 전체 204개 및 배포본 빌드 통과. 실제 파일에서 종료 append 전과
force 후 공개 전 I/O 오류를 주입하고 재개방하여, 새 입장을 거절하기 전에 종료 상태가
복원되고 점령이 중복 저장되지 않는 것을 확인했다. 이 변경은 아직 일반 실행 서버에
배포하지 않았다. 이후 [종료 통지·결과창](../protocol/session-ending.md#실제-수도-함락두-원본-결과창재시작-확인)을
연결해 실제 수도 함락→두 원본 결과창→정상 종료와 서버 재시작 복원을 확인했다.
정치 조건·보상·이월·다음 세션 전체 완주는 미완료다.
