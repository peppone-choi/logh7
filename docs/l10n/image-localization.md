## 폰트·적용의 남은 조건

결과/세력명은 흰 명조 계열과 청색 테두리, 사망은 적색 테두리를 기준으로 시안을 만들었다. 버튼은 원본의 작은 UI 글자와 상태별 밝기를 참고했다. 원본 이미지를 제작한 폰트 파일·정확한 포인트 크기는 확인하지 못했다. 실행 중 텍스트용 `ＭＳ ゴシック` 설정을 이미지 제작 폰트의 증거로 쓰지 않는다. 동일 폰트·동일 글자 크기를 확정한 결과가 아니다. `evidence:client`(모양 관찰) / `evidence:guess`(근사 시안).

PNG 캔버스·RGBA·투명 픽셀과 문구를 확인했으나, 전체 배경 픽셀/알파 경계·글자 높이/기준선·스프라이트 UV의 동일성 검수는 남았다. 자동 생성 과정에서 생긴 글꼴·테두리 차이도 보정해야 한다. 타이틀·로딩 문구는 백업만 했으며 아직 번역 생성하지 않았다. TGA 재작성·실행 사본 적용·상태 전환·실제 클라이언트 가독성·되돌리기도 미확인이다. 시안을 게임에 자동 적용하지 않는다.

실행 담당의 후속 확인:

1. 원본과 시안의 글자 높이·기준선·글꼴·색/테두리·5개 버튼 상태를 대조하고 보정한다. 원본 폰트 미확인이면 근사임을 유지한다. 각 파일의 원래 팔레트/픽셀 깊이·알파·원점·descriptor를 유지한 TGA를 `reviewed-tga/`에 같은 상대 경로로 준비한다. PNG를 확장자만 바꿔 넣지 않는다.
2. 원본과 검수 TGA의 `inspect` 해시로 선택 JSON을 만들고 `prepare`→`verify`한다. `manifest.json`의 크기·팔레트·알파 통계를 확인한다. 팔레트 크기나 방향 등의 변경으로 거부되면 원본 저장 형식을 다시 맞춘다.
3. 소유 비활성 데스크톱의 클라이언트를 종료한 상태에서 `apply <패키지> <사본의 data/image>`를 실행한다. 해당 사본을 기존 CLI 경로로 띄워 기함·사령관·함정·요새 버튼의 기본/가리킴/누름/전환 상태와 세력명·결과 화면을 확인한다. 글자 잘림·겹침·UV 경계·배경 투명도와 원래 해상도의 가독성을 비교한다.
4. 클라이언트를 종료하고 `restore <패키지> <같은 사본의 data/image>`를 실행한다. 선택 파일의 SHA256이 원본으로 돌아왔는지 확인하고 다시 실행해 원래 이미지 표시를 확인한다. 이 결과를 리드가 체크리스트에 반영한다.
