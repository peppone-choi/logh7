# 리마스터 검토 — 모든 해상도·HUD/UX·HD 자산

작성: Peppone Choi ([peppone-choi](https://github.com/peppone-choi)) · 2026-11-05 · 상태: 2배 HD 로더 구현·1024×768 일부 실기 확인, 해상도·재배치는 시안 단계

사용자 요청: 현재 클라이언트를 업그레이드·리마스터할 방법을 찾는다. 모든 해상도 지원, HUD·UX/UI 개선, 기존 HUD 파일 참고, 시안 제작, 모델·이미지·텍스처 업스케일. 진행 중인 Claude·Codex 세션과 논의하고 마피아 MCP 판단 카드를 참고했다.

이 문서는 구현 순서와 위험을 정한다. 실제 플레이 체크리스트([IMPLEMENTATION-CHECKLIST](../IMPLEMENTATION-CHECKLIST.md))보다 우선하지 않는다. 원작에 없던 기능(콘셉트 이미지의 자원 바 등)은 `content` + `backlog`로만 둔다.

## 1. 현재 사실

- `G7MTClient.exe`는 MFC + Direct3D8이다. dxwrapper가 D3D8을 D3D9Ex로 바꾸고, 창 모드 1024×768에서만 렌더를 확인했다([background-client](../ops/background-client.md)). `evidence:client`
- 2D UI는 D3D8 `DrawPrimitiveUP`(TRIANGLEFAN, stride 28, XYZRHW+색+UV)로 그린다. 화면 픽셀 좌표라서 투영 행렬을 바꿔도 움직이지 않는다. 네이티브 스프라이트 함수 `0x4ddc00`은 텍셀 픽셀 rect를 받는다(`tools/client/capture-frame.js`, `client-compat/tactical_radar.h`). `evidence:client`
- 위젯 클릭 영역은 1024×768 절대 좌표로 저장된다. 입력은 창 메시지·`GetCursorPos`·DirectInput 세 경로다(`tools/client/input-login.js`). `evidence:client`
- 글자는 `004b0960` 단일 글자 캐시 안에서 `ExtTextOutW`로 그린다. 글꼴 생성·크기·줄바꿈은 바꾸지 않았다(`client-compat/README.md`). `evidence:client`
- 원본 이미지 1,717장(241.8MP). UI TGA는 대부분 32비트 팔레트이고, 모델 텍스처는 `model/images/{Hi,Mid,Lo}` 세 등급이다. MDX는 일부 렌더 스트림만 해석했다([asset-formats](../re/asset-formats.md)).
- UV 분모는 **실제 텍스처 크기**다(2026-11-06 정적 분석, 2.1절). 스프라이트 UV는 `픽셀 좌표 ÷ GetLevelDesc 크기`로 계산되고, 미리 넣은 논리 크기는 상쇄된다. `evidence:client`

## 2. 방식과 순서

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 0. 관찰 | 실행 사본에서 백버퍼만 1280×720으로 바꾸고, 전략·전술에서 `traceQuads`·투영/뷰포트·백버퍼 캡처·HUD 버튼 1회 클릭을 기록 | 3D 종횡비, 2D 고정 좌표, Reset 안정성, 입력 불일치가 각각 기록됨 |
| 1. 해상도 | 백버퍼 = 창/모니터 크기. 3D는 뷰포트·투영을 넓힌다(Hor+). 2D 정점은 화면 영역·호출자로 앵커(좌상·우상·좌하·중하·우하·중앙)를 정해 옮기고 UI 배율을 곱한다. 입력 세 경로와 위젯 hit-box에 같은 역변환을 적용 | 4:3(1024×768), 5:4(1280×1024), 16:9(1920×1080, 2560×1440, 3840×2160), 16:10(1920×1200), 21:9(3440×1440), 32:9(5120×1440)에서 전략·전술·로비 표시와 클릭 일치. 최소 창 크기·DPI 배율 포함 |
| 2. HD 자산 | 텍스처 **생성 시점**에 교체한다. 키는 정규화 경로 + 원본 파일 SHA-256 + 하위 자원 식별자. 2×/4× 결과는 같은 픽셀 배치를 키운 것이라 정규화 UV가 유지된다. 팔레트는 A8R8G8B8로 펼치고 mip을 만든다 | 교체 전후 같은 화면 캡처에서 UV 어긋남·검은 이음매·투명 경계 깨짐 0 |
| 3. HUD | 시안 A(원작 그림 + 앵커)부터. B·D는 A 이후 DLL이 직접 그리는 패널로 확장. C는 원작 인상과 멀어 보류 | A: 전략 하단 패널 연결 띠 그림, 전술 네 모서리 고정 |
| 4. 글자 | DPI 배율 글꼴. 현재 단일 글자 캐시를 넘어 글꼴 객체 수명·메트릭·줄바꿈을 설계 | UI 배율 1.0~2.0에서 한국어 긴 문자열 잘림 0 |
| 보류 | 메시 고폴리 교체 | MDX 재질·노드·애니메이션 해석 후 재검토 |

Lock 이후 더 큰 텍스처로 바꾸는 방식, 정점만 옮기는 이동식 반투명 모달은 쓰지 않는다. 앞의 것은 크기·mip·pool이 이미 정해진 뒤라 객체 교체·Reset 복구가 필요하다. 뒤의 것은 네이티브 컨트롤 위치·입력·클리핑이 원래 자리에 남는다(Codex 상담).

호환 위험: `client-compat/country_icon.h`는 `icon_country32`가 128×128 A8R8G8B8일 때만 국가색을 입힌다. HD로 바꾸면 색 입히기가 꺼진다(크래시는 없음). 크기 검사를 배율 허용으로 넓혀야 한다.

### 2.1 HD 텍스처 교체 구현 (2026-11-06)

원본 `G7MTClient.exe`를 읽기만 해서 확인한 로드 경로다. `evidence:client`

- 텍스처 자원 로더 `0x5e2887`: 자원 구조체 +8에 `/../data/image/...` 경로, +0x108에 알파 짝 파일 경로, +0x220에 만든 텍스처를 둔다. 실제 생성은 `0x5e2d20`(정적 링크된 `D3DXCreateTextureFromFileExA` 래퍼, 크기는 파일 크기·필터 없음·MANAGED)이고, 본 로드는 `0x5e29eb`·`0x5e2a1f`, 알파 짝 로드는 `0x5e2c40`·`0x5e2c74`에서 부른다. 메모리 로드는 `0x5e2d60`이다.
- 로드 뒤 후처리: 파일 이름에 `_col_p`·`_col_b`(색 키), `_alpha_s`, `_normalmap`이 있으면 텍스처를 잠가 픽셀을 고친다. `.bmp`는 `_alpha_`가 없으면 A1R5G5B5로 읽는다.
- 스프라이트 `0x4d21c0` → `0x4d2030`: `GetLevelDesc(0)`의 폭·높이로 UV를 계산한다(u = x ÷ 실제 폭). 그래서 4배 텍스처를 그대로 넣으면 원래 영역의 1/4만 그린다.

구현(`client-compat/hd_texture_data.h`, `client-compat/hd_textures.h`):

- 설치 폴더의 `hd\`(exe 폴더의 형제, `data\` 옆)가 있을 때만 켠다. 없으면 아무것도 바꾸지 않는다.
- 본 로드 두 호출을 바꿔, 자원 경로의 `data\` 아래 상대 경로와 원본 파일 전체의 FNV-1a 32비트 값으로 `hd\<상대 경로>.<8자리 16진>.png`를 찾는다. 원본·HD 파일 머리말 크기가 정확히 N배(2~8)일 때만 A8R8G8B8로 만든다.
- 이름에 원본 해시를 넣는 이유: 2004-05-14 업데이트(`G7UPD040514`)가 같은 경로의 모델 텍스처 47장을 바꾸고 106장을 더한다. 현재 실기 사본(`work/facility-guide-native-20261106/client`)은 기본 설치판 47장을 그대로 쓴다. 경로만으로 찾으면 어느 쪽 원본이든 다른 판의 HD가 붙을 수 있어, 두 판의 HD를 한 묶음에 함께 넣고 실제 원본에 맞는 것만 쓴다.
- HD 텍스처는 `GetLevelDesc`가 (실제 크기 ÷ N)을 보고한다. 텍스처 vtable의 GetLevelDesc·Release를 한 번 바꾸고, 포인터별 배율 표는 Release에서 지운다. 2D UV가 모두 원래 픽셀 공간에 남고, 정규화 UV를 쓰는 3D는 영향이 없다.
- 제외: 위 후처리 접미사, 알파 짝 파일이 있는 자원, P8 팔레트, DLL이 고정 크기로 잠그는 `icon_country32.tga`. 제외 목록은 헤더 한 곳에 두고 묶음 빌더가 그대로 읽는다.
- 처음 4000건은 `hd\hd-textures.log`에 배율과 경로를 남긴다.
- 얼굴: 0x5924c0이 `tcf.hed`의 위치·길이로 `.tcf`에서 TGA 바이트를 읽고, 0x5e3650으로 메모리 자원(+0x20c 데이터, +0x210 길이)을 만든다. 같은 로더가 0x5e296a에서 메모리 로드(0x5e2d60, `D3DXCreateTextureFromFileInMemoryEx`)를 부른다. 이 호출도 바꿔 TGA 바이트의 FNV-1a로 `hd\mem	cf.<8자리>.png`를 찾는다. 낱장 파일로 쓰고 TCF는 다시 묶지 않는다(사용자 결정). 크기 보고·배율 확인은 파일 경로와 같다. HD가 없는 메모리 텍스처는 로그에 `x0`으로 남긴다. `evidence:client`(정적 분석)

HD 묶음은 [`tools/assets/build_hd_pack.py`](../../tools/assets/build_hd_pack.py)로 만든다(`--layer 기본 data 업스케일 --layer 업데이트 data 업스케일 --faces 얼굴 TGA 업스케일`). 2배 묶음(`work/remaster-20261105/hd-pack-x2/hd`)은 2,528장(얼굴 659장 포함, 669 레코드 중 같은 바이트 10장), 1,038MB다. 기본 설치판 이미지 1,717장 중 1,716장(제외 규칙 1장)과 업데이트판 246장(바뀐 47·새 106·같은 93)을 모두 덮는다.

초기 실기(Codex, 2026-11-06, `work/hd-native-20261106`, 1024×768): 로비·캐릭터 생성 9화면·전략·행성 정보 5탭·시설 안내 3탭에서 HD 있음/없음을 비교했다. 배치·UV 어긋남은 없었다. 이때는 얼굴 TCF 대체와 아래 알파 보정 전이었다.

같은 실기에서 전략 화면 채팅 창에 줄무늬가 생겼다. 원인은 업스케일이었다. `chat/chat_parts.tga`는 9분할 부품을 1px 투명 줄로 나눠 둔 아틀라스인데, 알파를 Lanczos로 키우면서 그 줄이 번져 부품 가장자리 알파가 최대 57 낮아졌다. 창을 늘려 그릴 때 그 가장자리가 띠로 보인다. UI 세트는 이제 `upscale_assets.py --fit source`로 만든다. 알파는 원본을 그대로 복제하고, 색은 원본 1픽셀에 해당하는 블록 평균을 원본 색에 맞춘다(`fit_source`). 모델은 다시 돌리지 않고 `--reuse`로 기존 결과를 재보정했다(742장, 3분). 재보정 뒤 `chat_parts`의 알파 오차는 0이다. 실기 재확인은 아직이다.

최신 묶음 재확인([PR311](https://github.com/peppone-choi/logh7/pull/311), head `a1e5cf80` + main `630420ef`): 같은 DLL에서 `hd/` 유무만 바꾸고 2,528장 묶음(TCF 659장)을 사용했다. 로비 카드, 생성 얼굴 첫 21개, 전략 HUD 초상·채팅·행성 개요, 전술 원경·제국 표준전함 근접에서 배치·얼굴 잘림/뒤집힘·채팅 격자 무늬가 관찰되지 않았다. 새 얼굴 선택은 `current-base-face-grid.png` / `current-hd-face-grid.png`, 선체는 `current-base-tactical-hull.png` / `current-hd-tactical-hull.png`다. `evidence:client`
