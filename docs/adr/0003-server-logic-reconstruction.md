# ADR-0003 서버 로직 재구현 원칙

- 상태: 채택 (2026-09-27)
- 작성: 최병호
- 관련: CLAUDE.md §5, docs/manual/*, docs/manual/unimplemented-candidates.md

## 맥락

서버 프로그램과 데이터는 서비스 종료로 사라졌다. 남은 근거는 매뉴얼 2판본(2004-04, 2004-10), 공식 사이트 스냅샷(패치 리뷰 ~2005-04), 클라이언트(버전 131, 2004-04 빌드)뿐이다. 판본마다 규칙이 다르고, 매뉴얼에 수치가 없는 규칙이 많다(docs/manual/unimplemented-candidates.md "수치 미기재").

## 결정

1. **서버 권위.** 모든 게임 상태 변경은 서버가 판정한다. 클라이언트 입력은 요청으로만 취급한다(원작도 "모든 커맨드는 서버가 처리", W p.10).
2. **근거 계층**(위가 우선):
   1. 웹판 매뉴얼(2004-10) + 패치 리뷰(update01~05) — `evidence:manual`
   2. CD판 매뉴얼(2004-04) — 웹판이 삭제·미기재한 규칙의 보조 근거. `evidence:manual`
   3. 클라이언트 동작·데이터(UI 문자열, 커맨드 ID, 표시 범위, 로컬 계산) — `evidence:client`
   4. 설계 추정 — `evidence:guess`
   계층이 충돌하면 위 계층을 따르되, 클라이언트가 물리적으로 표현할 수 없는 규칙(UI·패킷 부재)은 클라이언트 쪽 제약을 우선한다.
3. **기준 규칙 버전 = "최종 운영판"**(웹판 매뉴얼 + 2005-04까지 패치). 패치로 바뀐 규칙(철수 방향, 기함 구매 등)은 최신 쪽을 따른다. 단, 보유 클라이언트에 UI가 없는 패치 기능은 클라이언트 패치가 준비될 때까지 기능 플래그로 끈다.
4. **추정값은 코드에 박지 않는다.** 모든 수치 파라미터는 데이터 파일(`server/rules/*.yaml` 예정)에 두고 항목마다 `evidence` 태그·출처·결정 이유를 기록한다. 추정값을 바꾸는 일은 코드 변경이 아니라 데이터 변경이다.
5. **규칙 하나 = 테스트 하나.** 매뉴얼 규칙(예: 승진 시 공적 0, 강등 시 공적 100, CP 대용 2배, 그리드 진영당 300유닛)은 출처 페이지를 이름에 넣은 단위 테스트로 고정한다.
6. **미구현 기능은 기능 플래그**로 분리한다(U-01~U-28). 원작이 미구현이었던 기능을 되살리는 것은 P5에서, 근거 등급(A→C) 순으로.
7. **결정론적 시뮬레이션.** 전술 계산은 고정 틱·시드 난수로 재현 가능하게 만들어, 버그 제보 시 리플레이로 재현한다.
8. **원작에 없던 신규 아이디어는 만들지 않는다**(백로그로만).

## 결과

- 문서 `docs/manual/*` 의 각 규칙이 곧 서버 요구사항 목록이 된다. 구현 이슈는 규칙 문서의 절 번호를 참조한다.
- 미결 질문(Q-M1~Q-M4)은 결정 시 이 ADR의 부록으로 기록한다.

## 재검토 조건

- 원작 플레이 기록(커뮤니티 자료, 트랙 C)이나 원작 서버 트래픽 기록이 새로 발견되면 근거 계층 2~3 사이에 "플레이 기록" 계층을 추가한다.
