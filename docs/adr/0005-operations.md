# ADR-0005 운영 구조

- 상태: 채택 — 개정 1(2026-09-27), GCP 배포 전제·현재 로컬 연습(D-2)
- 작성: 최병호
- 관련: ADR-0001, docs/ops/, docs/research/public-exposure-options.md

## 맥락

- 목표: 동시접속 50명 이상, **GCP 배포 전제·현재 로컬 연습**, **가능한 한 빠른 오픈**. `evidence:guess` (사용자 D-2).
- 클라이언트는 원시 TCP(47900 게임, 47902 업데이트)를 쓴다 → 일반 HTTP 리버스 프록시·CDN으로 감쌀 수 없다.
- 원작 로그인은 ID/비밀번호(β 등록 시 메일 발급), 로그인 화면에서 서버 선택, 서버당 한 진영(W p.8).

## 결정

### 1. 계정·인증
- 가입·비밀번호 재설정은 **웹 포털**(Next.js)에서. 게임 클라이언트는 원래대로 ID/비밀번호로 로그인.
- 비밀번호는 **Argon2id 해시**로 저장. 클라이언트가 보내는 형식(평문/난독화/해시)은 프로토콜 분석 후 게이트웨이에서 정규화.
- 원작 규칙(서버당 한 진영, 명성 포인트의 계정 영속)은 계정 모델에 반영.

### 2. 영속성
- **PostgreSQL 단일 인스턴스.** 월드 스냅샷(게임 1일 = 실 1시간마다) + 도메인 이벤트 로그(append-only) + 계정.
- 복구 목표: 장애 시 마지막 스냅샷 + 이벤트 재적용으로 **실 5분 이내 손실**.
- 백업: 일일 논리 백업·디스크 스냅샷과 연속 WAL 보관을 조합한다. 5분 손실 목표는 일일 백업만으로 달성할 수 없고 WAL 업로드·복원 시험으로 확인해야 한다. [백업 설계](../ops/backup.md). `evidence:guess`

### 3. 관리 툴
- 게임 서버 내장 Ktor 운영 API(내부 전용, ADR-0001 개정) + Next.js 관리 화면: 접속자·세션 상태, 캐릭터 조회/수정, 공지·GM 메시지, 제재(정지·차단), 세션 시작/종료/재시작, 규칙 파라미터 리로드.
- 관리 기능은 내부망/VPN에서만 접근.

### 4. 관측
- 구조화 로그(JSON) + 지표(Micrometer → Prometheus) + 대시보드(Grafana). 핵심 지표: 동시접속, 틱 지연, 커맨드 처리량, 전술 인스턴스 수, 패킷 디코드 오류.
- 가용성 알림: 외부에서 TCP 47900 체크(업타임 모니터) → 메신저 알림.

### 5. 배포
- **Docker Compose**(game-server, postgres, admin-web, prometheus, grafana). 현재는 `E:\VM\myUbuntu` 또는 로컬 Docker에서 연습한다. 초기 구성의 game-server는 자리표시자, 웹은 후속 연결 대상이다. `evidence:guess`
- 배포 설계는 GCP Compute Engine·Ubuntu를 전제로 한다. 서울 리전·e2-standard-2·부팅 20 GiB/데이터 50 GiB는 [운영 초안](../ops/adr-0005-gcp-draft.md)의 측정 전 출발값이며 부하 수용량을 보장하지 않는다. GCP 리소스 생성·과금·apply/create는 별도 승인 전 금지다. `evidence:guess`
- 무중단은 목표로 하지 않는다. 공지 후 점검 재시작(스냅샷 → 종료 → 기동 → 복구).

### 6. 공개 노출 (GCP 설계)

- GCP 리전 고정 외부 IPv4와 방화벽으로 게임 TCP 47900·업데이트 TCP 47902를 제공하도록 설계한다. 세션 포트 47903은 설계 가정이므로 실제 리스너 확정 후 광고 주소와 함께 맞춘다. 47901은 현재 내부 Ktor API 전용이며 공개하지 않는다. `evidence:guess`
- 초기 알파는 승인된 플레이어 CIDR에 한정한다. 운영 API·PostgreSQL·Prometheus·Grafana는 비공개로 두고 관리 접속은 IAP SSH 포워딩을 검토한다. 실제 공개 배포는 이 세션 범위 밖이다. `evidence:guess`
- LGLoginOK가 세션 서버 주소를 반환하므로 외부 접속 시 그 주소도 플레이어가 도달할 수 있어야 한다. `evidence:client` (E-018).
- 자택 회선·포트포워딩 정보는 이제 선행조건이 아니다. 비용은 [출처와 계산 가정](../ops/adr-0005-gcp-draft.md)에 기록한다. 서울 SKU를 확정하지 못한 범위 추정은 공식 견적으로 취급하지 않는다. `evidence:guess`

### 이전 노출 비교 (개정 전 참고자료)

아래 표는 이전 조사 기록이며 현재 채택안이나 최신 가격표가 아니다. `evidence:guess`

| 순위 | 방식 | 조건 | 비용 | 비고 |
|---|---|---|---|---|
| 1 | 공유기 **포트포워딩** + DDNS | 공인 IP(CGNAT 아님), 공유기 설정 가능 | 무료 | 지연 최소. 서버 방화벽·레이트 리밋 필수 |
| 2 | **playit.gg** custom TCP | 없음(플레이어 추가 설치 불필요) | 무료(포트 4개) / Premium $3/월 | 할당 주소 고정. CGNAT 회선 대안 |
| 3 | ngrok TCP | 카드 등록 필요, 예약 주소는 유료 | $10/월~ | 5분 유휴 끊김, 무작위 포트 |
| (비공개 알파) | Tailscale tailnet | 플레이어가 Tailscale 설치 | 개인 무료(6명) | 지인 테스트용 |
| 부적합 | Cloudflare Tunnel(공개 임의 TCP는 Enterprise), Tailscale Funnel(TLS/SNI 한정) | | | |

- 주의(`evidence:guess`): MPS 구조상 로비 서버가 게임 서버 주소를 클라이언트에 내려줄 수 있다. 이 경우 서버가 알려주는 주소도 **외부에서 닿는 주소**(포트포워딩 공인 주소 또는 터널 주소)여야 한다 → 게이트웨이 설정에 "공개 주소" 항목을 둔다.
- LOGH-41은 GCP 운영 구조·비용과 로컬 연습 계획 이슈로 변경했다. `evidence:guess`

## 결과

- P6(운영) 이슈: 계정 포털, 관리 API, 백업, 모니터링, 노출 방식 결정 스파이크.
- 초기 단일 호스트 구성을 시험하되 50명 수용은 부하 시험 전 미검증이다. `evidence:guess`

## 재검토 조건

- 서울 리전의 비용·가용성·실측 지연이 목표에 맞지 않을 때 → 리전·머신 유형 재검토.
- 동시접속 수백 명 이상 → 스냅샷 주기·DB 튜닝·호스트 증설.
