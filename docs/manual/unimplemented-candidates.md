# 미구현·미완성 기능 후보

범위 정의(CLAUDE.md §5): 원작 매뉴얼·공식 사이트·패치노트에 **존재했거나 "준비 중/예정"으로 예고된 기능** + 서버 소멸로 사라진 서버측 로직 전체. 원작에 없던 신규 아이디어는 여기에 넣지 않는다(백로그).

## 분류 기준

| 등급 | 뜻 |
|---|---|
| **A 명시 미구현** | 매뉴얼 본문이 "現在未実装"이라고 적었거나 공지가 연기를 발표 |
| **B 패치 도입** | 서비스 중 패치로 도입. 보유 클라이언트(버전 131, 2004-04 빌드)에 UI가 없을 수 있음 |
| **C 규칙 부재** | 커맨드·용어는 있으나 동작 규칙·수치가 매뉴얼에 없음 |
| **D 잠정 사양** | 매뉴얼이 "暫定"이라 적은 규칙 |

"클라이언트 흔적" 열은 트랙 B(정적 분석) 결과로 채운다: `있음`(UI 문자열·패킷 흔적 확인) / `없음` / `미확인`.

## 다음 단계

1. 트랙 B 결과로 "클라이언트 흔적" 열을 채운다(UI 문자열 `MsgDat`·`constmsg.dat`, 커맨드 ID 테이블).
2. 흔적 `있음` + 등급 A/C → P5 우선순위 상, 흔적 `없음` + 등급 B → 클라이언트 패치 필요 여부 스파이크.
3. 트랙 C(커뮤니티 기록)로 "원작에서의 상태"를 보강.
