# 실제 플레이 완성 체크리스트

작성: Peppone Choi · 기준일: 2026-10-27 · 갱신은 해당 기능 PR에서 수행

사용자 요청에 따라 남은 구현과 실제 플레이 확인을 이 문서에서 하나씩 체크한다. 일정·담당·이슈의 단일 원천은 [Linear LOGH](https://linear.app/peppone-choi/team/LOGH)이며, 이 문서는 저장소 코드와 실제 클라이언트의 연결 상태를 기록한다. Linear의 규칙 단위 완료와 아래 플레이 완료는 구분한다. 과거 목표일은 새 완료 예상일로 사용하지 않는다.

## 체크 기준과 진행 순서

- `[x]`는 설명한 범위의 구현·관련 검사·실제 클라이언트 확인을 마친 항목이다. 저장 대상은 재접속/재시작도 확인한다. 제한된 시험은 옆에 명시한다.
- `[ ]`는 미착수·부분 구현·미확인을 포함한다. 규칙 클래스, CSV, 합성 패킷 시험만 있으면 실제 플레이 항목을 완료로 바꾸지 않는다.
- 한 항목을 끝낼 때 코드·검사·실제 확인·남은 한계를 관련 PR/문서에 짧게 남기고 이 문서의 해당 줄을 갱신한다. 전체 완료율은 체크 수로 계산하지 않는다.
- 사용자 지정 목표(2026-10-27): [10월 30일 전체 구현 마감 LOGH-63](https://linear.app/peppone-choi/issue/LOGH-63), [10월 31일 원본 두 클라이언트 실제 플레이 시험 LOGH-64](https://linear.app/peppone-choi/issue/LOGH-64). 기존 전체 범위를 유지하며 목표일을 완료 보장으로 해석하지 않는다. 시험 준비와 변경별 확인은 구현 중에도 수행한다.
- 진행 순서: 로그인→함대 운영→내정·생산·병참→이동→전투→결과 저장의 막힘을 우선 해소한다. 전략 명령·인사·작전·NPC AI·전술·점령·한글화와 한 판 완주·온라인 운영을 포함한 아래 모든 항목은 계속 완료 대상으로 추적한다. 의존성 때문에 필요한 선행 항목은 먼저 처리한다.
- 규칙은 매뉴얼 → 원본 동작 → 사용자 승인 설계 순서로 정한다. 소실된 수치의 설계값은 `evidence:guess`와 출처를 남긴다. 원작 외 신규 아이디어는 기존 백로그에 둔다.

## 1. 이미 연결된 기반과 남은 이동 문제

- 2026-10-29 최초 감사는 전략 81명령 중 제한 연결 14·실행 미연결 67, 정규 직위 121종 중 저장/카드 36·임명 15·해임 18·사임 33이었다. 후속 통합의 현재 값은 전략 제한 연결 31·미연결 50이며 정규 121개 직위의 조직표 판정·저장/카드·임명/해임/사임도 연결했다. 원본 261카드 슬롯과 여섯 작위도 대조했다. [명령별 현재 상태](manual/07-command-table.md), [직위·작위·카드 전수표](manual/05-personnel-operations-logistics.md#9-직위작위직무카드-전체-연결-감사-2026-10-29). 실제 원본의 전수 실행 완료를 뜻하지 않는다.
- 사용자 지정 담당 분리: 전략 미연결 전체는 `전략 커맨드·직위·작위·카드 전체 연결 구현`, 전술 미연결 전체는 `전술 커맨드·하위 메뉴 전체 연결 구현` 채팅에서 별도 작업 사본으로 구현한다. 리드가 통합·검사·원본 실행을 담당하며 담당 채팅의 구현 보고만으로 플레이 항목을 완료 처리하지 않는다.

## 10. 원작 미구현·패치 후보의 누락 방지

- [ ] U-01 AI 대행: 오프라인 인물·미선택 원작 캐릭터·임무 수행. `0f18` 설정 저장과 오프라인 AI ON 인물의 임무별 이동/연속 사격/철수 코드를 작성했으며 검사·원본 버튼 확인은 NOT_RUN. 점령 임무의 자동 접안/육전 투입·미선택 원작 인물 대행은 미구현.

## 11. 전략 명령별 확인

각 줄은 [기존 원표](manual/07-command-table.md)의 명령을 식별한다. 설명·수치·원작 구현 여부는 원표를 유지하고, 여기의 체크는 **복원 서버에서 실제로 동작하는지**만 뜻한다. 앞 절의 공통 실행·저장·관찰자 갱신 조건을 함께 만족해야 체크한다. 워프·연료 보급은 현재 연결돼 있으나 임시 정책/시간 연결이 남아 있어 전체 완료로 체크하지 않는다.

2026-10-29 통합: 제한 연결 29개/실행 미연결 52개다. 15개 새 명령과 121개 직위의 임명권·정원·계급·지역 판정을 연결했으나 새 전체 조합을 원본 완료로 세지 않는다. 통합 회귀 1,187개 중 1,182개 통과·5개 건너뜀, DLL 빌드/guard 통과. 원본 run-260에서 잘못된 선택값이 훈련 대신 `0f08`을 보내는 문제를 찾아 `1200`의 실제 선택값 `46`으로 고쳤다. run-261 두 클라이언트 온라인 중 카드→육전 훈련/전술 훈련/진압 창→실행으로 MCP 1000→920→840→680, 육전대 두 개 레벨 0→1, 지휘관 전술 숙련 1, 진압 예약을 확인했다. 한 클라이언트만 재접속해 MCP 680과 상태 보존을 확인했고, 예정 시각 887160의 1초 전에는 대기·정시에는 치안 80→85/지지 70→68 및 예약 제거를 저장에서 대조했다. 부대·직위·위치는 QA 사본에 준비했으며 실제 임명/부대 생성 검증을 뜻하지 않는다. 신규 인사/작전·퇴역/지원의 원본 전체 실행, 예약의 서버 재시작 중 복원, 훈련 전후 실제 전투 비교·관찰자 정보창 갱신은 남아 있어 아래 전체 체크는 유지한다.
