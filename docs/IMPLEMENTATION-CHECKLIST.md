# 실제 플레이 완성 체크리스트

작성: 최병호 · 기준일: 2026-10-27 · 갱신은 해당 기능 PR에서 수행

사용자 요청에 따라 남은 구현과 실제 플레이 확인을 이 문서에서 하나씩 체크한다. 일정·담당·이슈의 단일 원천은 [Linear LOGH](https://linear.app/peppone-choi/team/LOGH)이며, 이 문서는 저장소 코드와 실제 클라이언트의 연결 상태를 기록한다. Linear의 규칙 단위 완료와 아래 플레이 완료는 구분한다. 과거 목표일은 새 완료 예상일로 사용하지 않는다.

## 체크 기준과 진행 순서

- `[x]`는 설명한 범위의 구현·관련 검사·실제 클라이언트 확인을 마친 항목이다. 저장 대상은 재접속/재시작도 확인한다. 제한된 시험은 옆에 명시한다.
- `[ ]`는 미착수·부분 구현·미확인을 포함한다. 규칙 클래스, CSV, 합성 패킷 시험만 있으면 실제 플레이 항목을 완료로 바꾸지 않는다.
- 한 항목을 끝낼 때 코드·검사·실제 확인·남은 한계를 관련 PR/문서에 짧게 남기고 이 문서의 해당 줄을 갱신한다. 전체 완료율은 체크 수로 계산하지 않는다.
- 사용자 지정 목표(2026-10-27): [10월 30일 전체 구현 마감 LOGH-63](https://linear.app/peppone-choi/issue/LOGH-63), [10월 31일 원본 두 클라이언트 실제 플레이 시험 LOGH-64](https://linear.app/peppone-choi/issue/LOGH-64). 기존 전체 범위를 유지하며 목표일을 완료 보장으로 해석하지 않는다. 시험 준비와 변경별 확인은 구현 중에도 수행한다.
- 진행 순서: 로그인→함대 운영→내정·생산·병참→이동→전투→결과 저장의 막힘을 우선 해소한다. 전략 명령·인사·작전·NPC AI·전술·점령·한글화와 한 판 완주·온라인 운영을 포함한 아래 모든 항목은 계속 완료 대상으로 추적한다. 의존성 때문에 필요한 선행 항목은 먼저 처리한다.
- 규칙은 매뉴얼 → 원본 동작 → 사용자 승인 설계 순서로 정한다. 소실된 수치의 설계값은 `evidence:guess`와 출처를 남긴다. 원작 외 신규 아이디어는 기존 백로그에 둔다.

## 12. 한국어화 — 화면·입력·이미지

사용자 요청(2026-10-27): 게임 완성 뒤로 미루지 않고 병행한다. 용어는 [용어집](l10n/glossary.md), 문자열 변환은 [텍스트 경로](l10n/text-format.md), 이미지 작업은 [이미지 번역](l10n/image-localization.md)을 따른다. 이미지 시안 생성과 실제 클라이언트 적용 완료는 구분한다.

- [ ] 로그인·캐릭터 생성·전략·내정·인사·생산·전술·설정의 메뉴/도움말/확인·오류/시스템 문구를 번역하고 실제 화면에서 확인. 미치환 표현·잘림·겹침·줄바꿈·변수 토큰도 확인.
- [ ] 한글 지원 글꼴과 인코딩 경계를 연결하고 한글·일본어·영문·숫자·기호 혼합 표시를 확인. 기존 일본어 자산과 이름이 깨지지 않아야 한다.
- [x] 원본 입력란의 ACP 949 표시·DBCS 커서/삭제와 새 IME 확정 이벤트의 1회 반영 보완. 실제 한 개의 입력란에서 혼합 문구·중간 삽입·일본어/한글 한 글자 삭제를 확인. IMM 결과와 윈도우 이벤트를 제어한 구성요소 시험이며 실제 자모 키 입력/후보창·전송 완료는 아래 미완료 범위다. [수정과 시험 한계](l10n/native-input.md).
- [ ] 채팅 IME 조합 중 표시·확정·취소, 한/영 전환, 커서 이동·선택·삭제·붙여넣기와 Enter 처리. 조합 확정 Enter가 메시지까지 보내지 않는지 확인.
- [ ] 실제 클라이언트 두 개에서 한글 채팅 전송·본인 반송·상대 수신·스폿 이동 후 수신 범위 확인. 기존 한글 수신 시험만으로 완료 처리하지 않는다.
- [x] 기본 같은 그리드 채팅 `0f1c`의 Enter 접속 종료와 한글 송신 변환 수정. 실제 하나+합성 상대에서 전체/동진영의 한글 혼합 송신·반송·상대 수신·한글 답장과 버튼 한국어 표시를 확인했다. 채널별 서버 필터 검사는 통과했으며 함대의 실제 조작·두 원본 동시 실행·실제 자모 조합은 남아 있다. [수정과 한계](protocol/grid-chat.md).
- [ ] 모든 문자열 입력칸을 조사해 캐릭터/함선/부대 이름, 검색, 편지 제목·본문·수신자 등 존재하는 입력 경로별 한글 입력·수정·취소·전송을 확인. 계정·비밀번호의 허용 문자 정책은 서버와 일치시킨다.
- [ ] 글자 수와 바이트 수 제한, 마지막 한글 경계·빈 값·최대 길이·지원 밖 문자·서버 거부를 확인. 저장 대상 이름/편지는 재접속·서버 재시작 뒤 복원을 확인.
- [ ] 이미지에 직접 들어간 문구를 전수 분류하고 실제 사용 자산·상태별 참조를 확인. 문자열을 별도로 그리는 빈 창틀·기호 아이콘과 구분한다.

- [ ] 이미지 한글 시안의 원본 캔버스·글자 높이·기준선·색/테두리·버튼 상태를 맞추고 확인. 원본 폰트 확인 전에는 동일 폰트로 완료 처리하지 않는다. 첫 시안은 세력명/결과와 기함·사령관·함정·요새 버튼의 5상태를 대상으로 한다.
- [ ] 검수한 이미지의 TGA 포맷·투명도·스프라이트 좌표를 보존해 실행 사본에 적용하고 기본/가리킴/누름/상태 전환 및 실제 화면의 가독성·잘림을 확인. 원본은 수정하지 않는다.
- [ ] 번역 문자열·이미지·글꼴 패치를 런처 배포/백업·복구 경로에 연결하고 깨끗한 설치 사본에서 적용·되돌리기를 확인.
