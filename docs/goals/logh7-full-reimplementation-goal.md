# 지속 목표: LOGH7 전면 역분석 및 완전 재구현

너는 중단된 2004년작 온라인 게임 `은하영웅전설 VII`를 원본 CD 리소스를 로컬 데이터 팩으로 사용하는 새 엔진과 새 권위 서버로 전면 재구현한다. 이전에 만들어진 LOGH7 코드, 서버, 문서상의 구현 결정은 모두 무시한다. 구현의 1차 증거는 Internet Archive의 `logh-7` CD 이미지, `gin7manual` 공식 매뉴얼, 보존된 공식 웹사이트와 동시대 일본어 기사, 그리고 이번 프로젝트에서 새로 재현한 정적·동적 관측뿐이다. 기존 구현에서 얻은 상수나 결론은 원본에서 독립적으로 다시 확인되기 전까지 사용하지 않는다.

최종 목표는 로그인부터 세션 종료까지 게임의 모든 기능이 실제로 동작하는 운영 가능한 제품이다. 매뉴얼과 바이너리에서 발견되는 전략, 전술, 인물, 국가, 함대, 함선, 행성·요새, 생산, 보급, 수리, 인사, 정치, 외교, 권한 카드, 메일, 메신저, 채팅, 랭킹, 성장, 오프라인 상태, 세션 승패, 재접속, 영속성, 운영자 도구를 빠짐없이 기능 목록에 넣고 구현한다. 원작에서 “현재 미구현”이라고 명시된 경제, 오프라인 전술 AI, 인사·외교의 빈 부분도 완성한다. 단, 원작 관측과 새로 창작한 규칙을 섞지 말고 모든 요구와 데이터에 `observed`, `inferred`, `authored`, `authored-placeholder`, `unknown` 중 하나의 출처 등급을 기록한다.

소스 저장소는 `E:\logh7-greenfield` 단일 모노레포다. `apps/client`는 C++23 새 엔진, `apps/server`는 지원 중인 .NET LTS 기반 C# 권위 서버, `contracts`는 버전이 있는 명령·이벤트·스냅샷 계약, `libs/legacy`는 원본 포맷 디코더, `db`는 PostgreSQL 마이그레이션과 시드, `tools`는 추출·역분석·임포트 도구, `infra`는 Docker Compose, `qa`는 VMware 다중 클라이언트 시나리오를 소유한다. 레포를 추가로 나누지 않는다. 서로 다른 팀과 독립 배포 주기가 실제로 생기기 전까지 계약과 검증을 한 커밋에서 맞출 수 있는 구조를 유지한다.

클라이언트 엔진은 원본 실행 파일을 포함하거나 호출하지 않는다. 사용자가 지정한 `legacy data root`를 시작 시 검증하고, 원본 파일의 해시·크기·포맷 버전을 기록한 뒤 `LegacyDataProvider`를 통해서만 읽는다. 원본 BIN/CUE와 설치 파일은 Git에 넣지 않는다. TGA/BMP/OGG/WAV, 얼굴 TCF, 모델 MDX/MDS, 메시지 DAT, 맵·그리드·UI 파일마다 디코더와 안정적인 리소스 ID를 만든다. 원본, 변환 캐시, 한글화 오버레이, 새 대체 리소스를 별도 계층으로 둔다. 파일이 존재하거나 변환됐다는 사실만으로 통합 완료라 부르지 말고, 실제 로더와 레지스트리를 거쳐 플레이 화면·소리에서 사용된 증거를 남긴다.

원본 `G7MTClient.exe`는 MSVC x86, Direct3D 8, DirectInput 8, DirectSound, Winsock 기반 오라클이다. Ghidra로 함수·RTTI·가상 테이블·문자열 참조·호출 그래프·구조체를 복원하고, x32dbg로 분기·메모리·파일·소켓 동작을 관측한다. 어셈블리에서 확인한 함수는 주소, 입력, 출력, 부작용, 호출자, 피호출자, 신뢰도와 함께 도시에 기록하고 C++ 또는 C#의 명시적 타입과 테스트 가능한 계약으로 옮긴다. 디컴파일 결과를 그대로 복사하지 말고 의미를 독립적으로 재구성한다. `constmsg.dat`, `messages*.dat`, `G7MTClient.exe`의 프로토콜 클래스명과 크기 제한을 교차 검증하고, 패킷 파서는 경계 검사와 버전 처리를 갖춘다.

전술맵 진입 실패는 최우선 차단 이슈다. 단일 `load scene` 문제가 아니라 `NotifyChangeMode` 수신, `NotifyTactics` 수신, 전술 그리드·장애물·기지·군단·부대·함선 스냅샷 완성, `WorldIn_TacticsFieldImport`, `MakeTacticsUnit`, 카메라·레이더·UI 생성, 준비 확인의 상태 전이로 모델링한다. 원본 문자열 `WSeq00_Battle`, `TACTICS SEQUENCE NUM=`, `FIELD_TACTICS`, `Field Make OK`, `World Encount OK`의 참조 함수와 조건을 복원한다. 각 단계에 battleId, clientId, authorityVersion, stateHash, 누락 컬렉션, 대기 시간, 실패 코드를 로그로 남긴다. 두 적대 함대가 같은 전략 그리드에 들어가면 서버가 하나의 전투를 만들고, 최소 두 클라이언트가 동일한 전투 스냅샷으로 전술 화면에 들어가 이동·선회·워프·공격·정지·철수·점령 명령을 주고받는 장면을 실제로 관측할 때까지 완료로 보지 않는다.

서버는 클라이언트보다 항상 권위가 높다. 명령은 사용자·세션·캐릭터·역할 권한·소유권·위치·자원·쿨다운·현재 모드를 검증한다. 승인된 변경은 순서가 있는 이벤트와 트랜잭션으로 PostgreSQL에 기록되고, 스냅샷은 재생 가능한 체크포인트다. 모든 응답은 commandId, result, authorityVersion, authorityStateHash를 포함한다. 중복 명령은 멱등이어야 하며 같은 키의 다른 의미 재사용은 거부한다. 서버 재시작 뒤 이벤트 재생 결과, 재접속 클라이언트 스냅샷, 두 클라이언트의 상태 해시가 일치해야 한다.

PostgreSQL은 Docker로만 실행한다. 검증된 기본 이미지는 `postgres@sha256:18cfe3ef5e6815560c98237d6216d1e5119702fb0f3894c8785dd58b8bbe5d73`이며 현재 확인 버전은 17.11이다. Compose에서 이미지 다이제스트, healthcheck, `restart: no`, loopback 포트, CPU·메모리·PID 제한을 고정하고 DB 데이터는 `E:`에 바인드 마운트한다. 비밀번호와 운영 비밀은 Git에 넣지 않는다. 스키마·밸런스·행성·함선·인물·직책·세션 규칙·AI 정책·현지화 키는 마이그레이션과 편집 가능한 테이블로 관리한다. 서버 자료가 없으면 은하영웅전설 세계관과 매뉴얼에 모순되지 않는 임시 데이터를 만들되 `authored-placeholder`로 표시하고 관리자 도구나 데이터 파일을 통해 코드 변경 없이 수정할 수 있게 한다.

한글화는 원본 일본어 문자열을 실행 파일에서 직접 덮어쓰는 방식이 아니다. 안정적인 메시지 키, 일본어 원문, 한국어 번역, 컨텍스트, 화면 길이 제한, 변수 형식, 출처와 검수 상태를 저장한다. UI는 유니코드와 한국어 폰트를 지원하고 텍스트 잘림·깨짐·변수 순서 오류를 화면별로 검사한다. 원본 UI의 의미와 배치는 증거로 보존하되 현대 해상도와 접근성에 맞춘 차이는 `authored`로 기록한다.

원본 관측은 호스트를 오염시키지 않는다. VMware Workstation의 원본 오라클 VM은 `E:`에 두고 Windows XP SP3 32비트, 2 vCPU, 2GB RAM, 30GB 디스크, 1024x768, DirectX 9.0c, 3D 가속으로 구성한다. 읽기 전용 원본 마운트, 스냅샷 복원, 호스트 전용 네트워크, 공유 클립보드·공유 폴더 최소화, 일반 인터넷 차단을 적용한다. 새 클라이언트 VM은 Windows 10/11 64비트, 4 vCPU, 6GB RAM, 40GB 희소 차등 디스크로 `client-a`, `client-b`를 상시 준비하고 필요하면 `client-c`를 복제한다. 각 VM은 고유 계정·MAC·IP를 사용하며 서버와 패킷 캡처 게이트웨이에만 접근한다. 자동 테스트가 끝나면 VM을 종료하고 Docker 개발 서비스도 필요할 때만 켠다.

C: 여유 공간을 계속 감시한다. 작업 시작과 대용량 다운로드·빌드·VM 생성 전후에 여유 공간을 측정하고 8GB 미만이면 즉시 정리한다. 개인 문서, 원본 프로젝트, Codex/Claude 데이터, Docker 볼륨, 원본 CD와 증거 파일은 자동 삭제하지 않는다. 먼저 이번 작업의 재생성 가능한 ZIP, 변환 ISO, 실패 추출본, 빌드 캐시, 오래된 명시적 임시 디렉터리를 정확한 절대 경로·크기·재분석 지점 여부와 함께 검증한 뒤 내용만 지우고 전후 여유 공간을 기록한다. VM 디스크, PostgreSQL 데이터, 대규모 리소스 캐시는 E:에 둔다.

실행 순서는 증거 인벤토리, 원본 포맷 디코더, 새 클라이언트 부팅과 전략맵 표시, 권위 서버 로그인·세션·캐릭터, 두 클라이언트 전략 이동, 전술 진입과 기본 전투, 영속성·재접속, 커뮤니케이션, 권한·정치·인사·외교·경제, 오프라인 AI, 세션 승패·랭킹·운영 도구, 전체 콘텐츠 완성 순서다. 여러 독립 작업은 병렬화하되 모든 레인은 가장 빠른 실제 플레이 화면과 권위 상태로 합류해야 한다. 목업, fixture, 단위 테스트, 정적 분석, 에이전트 보고만으로 플레이 가능이나 완료를 주장하지 않는다.

각 기능은 요구 근거, 구현, 자동 테스트, 서버 로그, PostgreSQL 변화, 최소 두 VM의 플레이어 화면, 독립 검토를 연결한다. 상태는 `PASS`, `PARTIAL`, `UNSEEN`, `BLOCKED`, `UNKNOWN`을 구분한다. 완료 조건은 새 설치에서 원본 데이터 루트를 선택하고 한국어로 로그인하여 최소 두 사용자가 같은 세션에 접속하고, 전략 이동으로 적대 조우를 만들어 전술맵에 진입하고, 전투·점령·보급·수리·통신·정치·경제·AI·로그아웃·서버 재시작·재접속·세션 종료까지 수행하며, 모든 상태가 PostgreSQL과 재생 로그에서 일치하는 것이다. 기능 매트릭스의 미구현·스텁·TODO·skip 테스트가 0이고 빌드·테스트·수동 QA가 통과할 때만 전체 목표를 완료한다.

웹 조사는 일반 웹, 일본어 웹, Wayback, 보존 파일 순으로 계속하며 공식 자료와 동시대 자료를 우선한다. 막힘이 생겨도 즉시 질문으로 멈추지 말고 안전한 정적 분석, 데이터 추출, 테스트 하네스, 문서화, 다른 기능의 수직 슬라이스를 계속 진행한다. 삭제·외부 공개·권리 판단·비밀 입력처럼 사용자만 결정할 수 있는 사항만 질문한다. 진행 중에는 실제 증거와 남은 미확인 경계를 짧게 보고하고, 이 목표가 모두 충족될 때까지 계속 실행한다.
