# 원본 클라이언트 복원: 다진영 함대전과 전체 콘텐츠

2026-09-08 사용자 추가 요청: 각 진영 동시 전투, 함대 대 함대 전투, 그리고 이를 포함한 모든 콘텐츠를 구현 범위에 포함한다. 현재 작업은 원본 클라이언트와 복원 서버를 연결하는 작업이다. 기존 새 엔진 전면 재구현 목표 문서의 기술 스택으로 작업 대상을 바꾸지 않는다.

콘텐츠마다 출처와 함께 `목록 확인 / 데이터 회수 / 서버 연결 / 클라이언트 표시 / 기능 검증 / 미확인 경계`를 기록한다. 파일 추출, 임시 데이터 등록, 단위 테스트 통과는 실제 플레이 검증을 대신하지 않는다. 전체 분모가 확정되기 전 임의 완료율을 제시하지 않는다. 한글화보다 게임 기능과 콘텐츠 동작을 우선한다.

## 당장 합류할 작업 단위

현재 단일 기본 NPC 등록 경로를 콘텐츠 기반 다진영 함대 등록·전장 투입 경로로 확장한다. 개별 NPC 수만 늘리는 것을 함대전 완료로 세지 않는다. 함대 소속·지휘권과 네이티브 패킷 연결을 먼저 확인하고, 여러 함선의 이동·사격·피해·전투 종결을 연결한다. 서로 다른 전장의 상태 격리와 여러 접속자의 동일 결과 수신도 검증한다.

현재 조사에서 드러난 경계: 기본 NPC 한 척 등록, 같은 전장에 동일 Number 능력값을 요구하는 구조, 유닛 패킷 outfit/boarding_ship 값 0 고정. 각각 실제 소속 의미와 원본 수신 구조를 확인해야 하며, 이름만 붙인 NPC 묶음을 원본 함대로 간주하지 않는다.

작은 수정마다 전체 테스트·개별 배포를 반복하지 않고 기능 묶음의 집중 테스트 후 통합 검증·배포한다. 결과 보고는 참가 진영·함대·함선 수, 실행된 명령과 피해·승패·귀환, 서버/클라이언트 대조 및 남은 미확인 사항 중심으로 한다.

## 유지되는 경계

2026-09-08 추가 요구: 기함 유닛과 휘하 함선/전투 유닛을 명시적으로 구분한다. 인물 ID, 부대 ID, 기함 유닛 ID, 휘하 유닛 ID, 유닛 내 함선 수는 서로 다른 개념이다. 기함 지정·모델·이름·지휘권·손실·격침 후 인물 귀환은 이 관계에 따라 처리해야 한다. boarding_ship 필드를 지휘관/기함 소속으로 임의 전용하지 않는다. 기함과 일반 전투 유닛의 실제 편제 수량은 원본 근거와 임시 규칙을 분리하여 정의한다.

진척 보고의 “함선 수”는 유닛 수와 구별한다. v183 테스트의 4부대·8개 등록 객체는 **8개 전투 유닛**이며 8척의 개별 함선 검증이 아니다. 당시 모든 유닛이 공유 임시 Number=100을 사용했고 기함·휘하 구분에 따른 능력/수량 구현은 아직 없다. 이 문제를 남긴 상태로 함대 편제 완료라 판정하지 않는다.

승인된 서버/프로토콜 변경, 명시된 임시 전투 수치·AI·귀환 행성 범위에서 진행한다. 임시 규칙을 원본 수치로 표시하지 않는다. 원본 EXE 추가 패치, 기존 데이터 리셋, 이미 소비한 실전 입력 재실행은 별도 승인 없이 하지 않는다. 자동 입력 지연 문제가 해결되지 않은 같은 짧은 격침 반복으로 검증을 대체하지 않는다.

이 문서는 범위 확정이며 구현 또는 실전 검증 완료 영수증이 아니다. 전체 목표는 ACTIVE다.

## 기함·휘하 유닛 구분의 완료 조건 (v196 보강)

매뉴얼 OCR의 유닛/지휘권 절에서 기함 유닛은 1척, 일반 함정 유닛은 300척 편제로 확인했다. 따라서 기함 1개와 정상 일반 유닛 2개는 3유닛·601척이며, 일반 유닛에서 10척 격침돼도 해당 유닛 자체가 즉시 제거되는 것은 아니다.

- 인물, 부대, 기함 유닛, 휘하 유닛, 유닛별 현재 척수/손실을 별개로 식별한다. 일반 유닛마다 가짜 인물이나 기함을 만들지 않는다.
- 같은 부대 안에서도 지휘권 배정과 지휘 범위를 검증한다. 같은 진영 또는 같은 부대라는 이유만으로 모든 유닛을 조종할 수 있게 하지 않는다. 매뉴얼의 온라인/계급/평가/공적 우선순위 및 재배정 조건을 연결한다.
- 자기 기함, 배정받은 휘하 유닛, 다른 지휘관의 유닛, 적 유닛을 포함한 명령 승인/거부를 검증한다. 복수 유닛 명령은 각 유닛의 이동·사격·손실과 송신 결과까지 검증한다.
- 기함 손실과 휘하 유닛 손실을 구별한다. 휘하 유닛 일부 손실로 지휘관 귀환이 발생해서는 안 되며, 기함 격침 시 인물 생존/귀환과 잔존 유닛 지휘권 처리는 별도 검증한다.
- 서버 편제·저장 후 재접속·원본 클라이언트 선택/라벨/척수/명령 가능 상태가 일치해야 완료다.

현재 상태: 일반 4종의 300척 템플릿, 유닛별 수량/손실 및 DB 저장 경로는 추가됐으나 배포·실전 확인은 별개다. 기존 임시 기함 100척 데이터의 변환은 사용자 선택 대기다. 표적/공격 승인 경로는 여전히 자기 기함 1개만 허용한다. v183의 8개 객체는 8전투 유닛이며, 현재 일반 편제 300척을 적용해도 이것을 기함 지휘가 가능한 함대전 완료로 계산하지 않는다.
