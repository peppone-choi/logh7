# 총독의 행성 수비대장 임명

작성: 최병호 · 2026-10-26

제국 총독 카드 54의 임명 명령 5를 원본 선택 화면에 연결했다. 직무→담당 행성→인물→확인→실행 순서이며, 별도 텍스트 명령창을 만들지 않는다. 행성 상세 전체의 원본 배치 복원과 다른 직책의 임명/해임은 미완료다.

## 원본 화면에 필요한 데이터

정적 카드 목록의 담당 시설 분류는 행성 거점 선택 여부를 결정한다. 카드 55의 임명 상위 카드는 54이며 이 값을 세력 번호로 보내면 원본 목록에서 해당 직무가 사라진다. 시설 분류 16을 보내면 거점 선택 단계가 열린다. 총독의 실행 명령은 임명과 세율 변경만 제공한다. `evidence:client` (`004c9140`, `00579800`, `004c8c40`, `00580830`)

플레이 중 `1200`의 검색 18/28/4에 각각 `1208` 직무 공석, `120d` 담당 거점, `1202` 인물 후보를 보내고 `1201`로 마친다. 실제 인물 선택 요청은 거점 필드가 0이므로 후보 조회에 선택 거점을 강제하지 않는다. 거점 선택 행의 반환값에는 실제 거점 ID가 필요하다. 후보 클릭의 `0322→0323` 상세 조회도 연결했으며, 공개 상세는 CP·스폿·귀환지를 0으로 비공개 처리한다. `evidence:client`

## 실행과 저장

`0707`은 시간·인물·PCP·MCP·대상·카드의 u32 6개, 중첩 카드 u16, 담당/부대/거점 u32 3개를 사용한다. 요청의 CP·시간·중첩 카드는 권한으로 신뢰하지 않는다. 인증된 제국 인물의 저장된 총독 직무, 정규 제국 행성, 대상의 실제 세력·계급(원수~소령), 선임 조건, 공석, 직무 카드 용량과 대기 작업을 검사한다. 계급 범위는 [인사 매뉴얼 요약](../manual/05-personnel-operations-logistics.md), 비용 MCP 160/PCP 320 대체는 CD 명령 정의를 따른다. `evidence:manual`(임명 대상), `evidence:client`(명령·비용)

월드 액터가 CP와 `garrisonCommanderId`를 같은 월드 저장으로 확정한다. 중복 요청은 다시 결제하지 않으며 타인 교체·잘못된 권한은 거부한다. 원본 수신기는 거부/반복 응답에서도 카드를 추가하려 하므로 변경이 없는 응답의 대상 ID를 0으로 보내고, 온라인 대상에게 완전한 직무 목록을 별도 갱신한다. 대상의 최신 위치·CP를 이전 스냅샷으로 덮어쓰지 않는다. `evidence:client`(수신기 `004c5580`), `evidence:guess`(서버 보존 정책)

## 확인 범위와 남은 문제

엔진 권한·계급·공석·용량·CP, 저장 실패/재개방, 암호화 두 접속의 대상 갱신·반복 결제 방지와 관련 세율/직무/접속자 회귀 검사를 통과했다. 원본 한 개에서는 시험 사본의 총독 10000이 원래 버튼으로 인물 10001을 오딘 1049 수비대장에 임명했다. 실제 송신 인자 10001/55/0/1049, HUD MCP 1000→840, 저장 직위 10001을 대조했다. 양쪽 종료/재시작 뒤 오딘 상세의 수비대장 `Test -Guest`와 정상 CP 회복을 확인했다. 자료는 Git 제외 `work/garrison-appointment-20261026/native-11`, `native-12`에 보존한다. 일반 월드에는 시험 직무·계급을 이식하지 않았다.

원본 선택 화면의 직무 최소 계급/인물 계급 일부가 황제로 표시되고 최종 확인 문구의 대상 치환이 비어 있다. 실제 요청과 저장 대상은 맞지만 표시 완성으로 처리하지 않는다. 다른 임명/해임, 제안·지원·취임, 동맹 임명, 인물 목록 200명 초과 처리와 원본 두 개 동시 실행은 남아 있다. 행성 상세는 기존 재구성 화면이며 이 작업으로 원작 전체 UI가 복원된 것은 아니다.
