# 총독의 행성 수비대장 임명

작성: Peppone Choi · 2026-10-26

제국 총독 카드 54의 임명 명령 5를 원본 선택 화면에 연결했다. 직무→담당 행성→인물→확인→실행 순서이며, 별도 텍스트 명령창을 만들지 않는다. 행성 상세 전체의 원본 배치 복원과 다른 직책의 임명/해임은 미완료다.

후속 [상위 국가 직무와 수도 임명](#상위-국가-직무와-수도-임명)은 수도 네 직위의 임명 경로를 추가한다. 상위 직무 자체의 임명/선출·초기 원작 인물 배치와 해임은 아직 별도 미완료다.

## 원본 화면에 필요한 데이터

정적 카드 목록의 담당 시설 분류는 행성 거점 선택 여부를 결정한다. 카드 55의 임명 상위 카드는 54이며 이 값을 세력 번호로 보내면 원본 목록에서 해당 직무가 사라진다. 시설 분류 16을 보내면 거점 선택 단계가 열린다. 총독의 실행 명령은 임명과 세율 변경만 제공한다. `evidence:client` (`004c9140`, `00579800`, `004c8c40`, `00580830`)

플레이 중 `1200`의 검색 18/28/4에 각각 `1208` 직무 공석, `120d` 담당 거점, `1202` 인물 후보를 보내고 `1201`로 마친다. 실제 인물 선택 요청은 거점 필드가 0이므로 후보 조회에 선택 거점을 강제하지 않는다. 거점 선택 행의 반환값에는 실제 거점 ID가 필요하다. 후보 클릭의 `0322→0323` 상세 조회도 연결했으며, 공개 상세는 CP·스폿·귀환지를 0으로 비공개 처리한다. `evidence:client`

## 실행과 저장

`0707`은 시간·인물·PCP·MCP·대상·카드의 u32 6개, 중첩 카드 u16, 담당/부대/거점 u32 3개를 사용한다. 요청의 CP·시간·중첩 카드는 권한으로 신뢰하지 않는다. 인증된 제국 인물의 저장된 총독 직무, 정규 제국 행성, 대상의 실제 세력·계급(원수~소령), 선임 조건, 공석, 직무 카드 용량과 대기 작업을 검사한다. 계급 범위는 [인사 매뉴얼 요약](../manual/05-personnel-operations-logistics.md), 비용 MCP 160/PCP 320 대체는 CD 명령 정의를 따른다. `evidence:manual`(임명 대상), `evidence:client`(명령·비용)

월드 액터가 CP와 `garrisonCommanderId`를 같은 월드 저장으로 확정한다. 중복 요청은 다시 결제하지 않으며 타인 교체·잘못된 권한은 거부한다. 원본 수신기는 거부/반복 응답에서도 카드를 추가하려 하므로 변경이 없는 응답의 대상 ID를 0으로 보내고, 온라인 대상에게 완전한 직무 목록을 별도 갱신한다. 대상의 최신 위치·CP를 이전 스냅샷으로 덮어쓰지 않는다. `evidence:client`(수신기 `004c5580`), `evidence:guess`(서버 보존 정책)

## 확인 범위와 남은 문제

엔진 권한·계급·공석·용량·CP, 저장 실패/재개방, 암호화 두 접속의 대상 갱신·반복 결제 방지와 관련 세율/직무/접속자 회귀 검사를 통과했다. 원본 한 개에서는 시험 사본의 총독 10000이 원래 버튼으로 인물 10001을 오딘 1049 수비대장에 임명했다. 실제 송신 인자 10001/55/0/1049, HUD MCP 1000→840, 저장 직위 10001을 대조했다. 양쪽 종료/재시작 뒤 오딘 상세의 수비대장 `Test -Guest`와 정상 CP 회복을 확인했다. 자료는 Git 제외 `work/garrison-appointment-20261026/native-11`, `native-12`에 보존한다. 일반 월드에는 시험 직무·계급을 이식하지 않았다.

후속 `native-13`에서는 후보 데이터의 첫 u16이 계급임을 원본 디코더 `0055ba80`과 표시 함수 `0057a1f0`의 레코드 `+0x20` 참조로 확인해 순서를 교정했다. 실제 인물 상세의 얼굴·능력과 소령 표시를 확인하고 취소했다. 이때 남은 직무 최소 계급과 확인 대상 표시는 아래 후속 작업에서 보완했다. 다른 임명/해임, 제안·지원·취임, 동맹 임명, 인물 목록 200명 초과 처리와 원본 두 개 동시 실행은 남아 있다. 행성 상세는 기존 재구성 화면이며 이 작업으로 원작 전체 UI가 복원된 것은 아니다.

## 선택 정보와 확인 문구 보완

원본 `0057a080`은 초기화된 보조 조회의 카드 0을 읽었다. 직무 선택은 선택 행의 카드 번호, 부대/거점 선택은 주 조회 `+0x15fc`의 요청 카드 번호를 전달한 동안만 원래 표시 함수를 호출하고 보조값을 복원한다. 카드 정의의 첫 계급 값은 수치상 작은 번호가 아니라 최저 허용 계급이므로, 수비대장 네 종류를 소령 10→원수 2 순서로 교정했다. [조직표 데이터](../manual/data/org-posts.csv)의 매뉴얼 p.58/64 범위와 같다. `evidence:client`(표시 경로), `evidence:manual`(계급 범위)

제국 총독의 임명 확인창은 완료된 원본 선택 결과의 인물·거점·카드 ID를 읽어 첫 행을 채운다. 거점 이름은 실제 Unicode 정의, 인물 이름은 선택된 후보 레코드, 직무 이름은 원래 카드 명칭을 사용한다. 기존 비용·대기·소요 시간·질문과 결정/취소 동작을 유지한다. 첫 행 배치는 표시 보완 설계이며 원문 치환 엔진 전체의 복원은 아니다. `evidence:client`(선택 결과·이름·기존 창), `evidence:guess`(첫 행 배치)

`work/appointment-ui-details-20261026/native-03`, `native-04`에서 직무/거점의 최저 계급 소령 표시를 확인했다. 초기 확인창 시험은 컨트롤과 GUI 관리자를 혼동해 종료됐으며 호출을 교정했다. 최종 `native-05`는 대상·행성·직무와 다섯 줄 안내, 취소→재열기 무결제, 결정→송신 10001/55/0/1049 및 MCP 1000→840·직위 저장을 확인했다. x86 경고 오류 처리 빌드·다른 프로세스 거부/카드 경계 검사와 서버 카드/암호화 임명 회귀를 통과했다. 긴 이름의 실제 화면·부대 직위 선택과 다른 임명 명령은 미확인이다.

초기 오딘 사본의 55번 임명 시험은 일반 행성 경로의 UI 검증이며 수도 규칙을 충족한 사례가 아니다. 아래 분리 이후 수도에서는 그 경로를 차단한다.

## 수도 전용 직위 분리

조직표 p.58/64와 원본 `constmsg.dat` 카드 이름을 대조해 수도 직위를 구분했다. 일반 행성 총독·수비대장과 서로 다른 권한이며, 수도는 원본 행성 이름·그리드·종류가 모두 일치할 때만 식별한다. 같은 성계의 다른 행성은 일반 행성 규칙을 따른다. `evidence:manual`(조직표), `evidence:client`(카드 ID·명칭)

| 오딘 | 56 | 제도방위사령관 | 2 제국군 최고사령관 | 대장~원수 |

저장 형식 `LOGH7-STOCK-9`의 P행 끝 세 필드는 수도시정관·수도방위사령관·근위병총감 ID다. 버전 1~8을 읽을 때 새 필드는 0이며 기존 총독·수비대장 ID는 그대로 보존한다. 기존 수도의 일반 직위를 새 직위로 자동 승격하지 않는다. 새 수도 직위는 적합한 원래 수도·소속·정규 진영에만 허용한다. 점령 후 수도 인사제도는 미구현이므로 다른 소속의 수도에 원래 수도 직무 카드를 주지 않는다. `evidence:guess`(저장·이관·점령 처리)

직무 카드와 공개 보유자 조회 `034e/034f`, 행성 상세의 두 직위·담당자 이름을 연결했다. 일반 행성 총독의 임명 후보 조회와 `0707`, 일반 총독 세율 변경은 수도를 제외한다. 과거 저장의 수도 총독 ID만으로 CP를 쓰거나 일반 수비대장을 임명할 수 없다. 수도 직위의 실제 임명·해임과 상위 정치 직위의 저장/권한은 아직 미완료다. 수도시정관은 후속 [세율 명령](planet-tax.md#수도시정관과-복수-관할)을 연결했으며 나머지 내정은 남아 있다. 상세 화면의 내용 배치는 기존 재구성이며 원작 행성 상세 전체를 복원한 것은 아니다.

엔진 397개·저장 70개 검사, 프로토콜 카드 정의와 공개 명단/암호화 임명 회귀를 통과했다. 암호화 시험은 과거 수도 총독의 후보 목록이 비고 위조 `0707` 두 번에도 CP·직위가 보존되는지 포함한다. x86 경고 오류 처리 빌드와 카드/수도 식별 검사를 통과했다. 원본 한 개로 `work/capital-offices-20261026/native-01`의 오딘 두 직위·담당자와 같은 성계 일반 행성의 미임명, 서버·클라이언트 재시작 후 `native-02`의 하이네센 두 직위·담당자를 확인했다. 시험 위치·직위·계급은 시험 사본에만 적용했으며 이동/임명 명령의 실행 검증으로 해석하지 않는다.

두 번째 재시작 `native-03`은 하이네센의 서로 다른 담당자 `Test -Guest`·`Test -Guard`를 각각 수도시정관·수도방위지휘관에 표시해 응답이 섞이지 않는지 확인했다. 세 실행의 소유 프로세스 정리·음향 복원 오류 없음·원본 실행 파일 해시 보존을 확인했다.

## 상위 국가 직무와 수도 임명

국가 직무는 행성 총독이나 계급에서 추정하지 않고 월드에 별도로 저장한다. 원본 카드 2/제국군 최고사령관, 17/군무상서, 134/국무위원장, 161/국방위원회 방위부장을 연결한다. 각 직무 카드는 수도의 실제 황궁·군무성·최고평의회·국방위원회 시설 ID를 대상으로 전달한다. 수도가 원래 소속의 정규 진영일 때만 권한·카드를 활성화하며 점령자의 인물에게 직무를 주지 않는다. 공개 명단도 저장된 담당자와 실제 등록 인물을 대조한다. `evidence:manual`(조직표), `evidence:client`(카드·시설 번호), `evidence:guess`(저장·점령 처리)

직무 조직 분류는 `constmsg.dat` 그룹 4다. 물리 시설 분류인 그룹 73과 번호가 다르다. 국가 카드 2/17/134/161의 조직 분류는 0/3/20/23이며 수도 카드 56/57/192/193은 수도 행성 17이다. 실제 시설 종류는 각각 22/31/24/34를 사용한다. 최초 시험에서 이 구분을 혼동해 국무위원장을 전략작전국으로 표시했고, 조직 분류를 교정했다. `evidence:client`

수도 조직 17에서는 원본이 거점 선택 단계를 건너뛰고 `0707`의 거점 0을 보낸다. 수도 임명 네 종류에 한해서 이 생략을 받아 카드에 대응하는 실제 원본 이름/그리드의 수도 ID로 서버가 결정한다. 일반 수비대장의 거점 0은 계속 거부한다. 명시적인 잘못된 수도·다른 세력 거점도 허용하지 않는다. 확인창은 생략된 선택값 대신 같은 원본 거점 목록에서 수도를 찾아 표시한다. 클라이언트 현재 위치를 임명 대상으로 대신 사용하지 않는다. `evidence:client`(수도 선택 생략), `evidence:guess`(서버의 수도 결정)

저장 형식 `LOGH7-STOCK-10`은 헤더 마지막에 국가 직무 수, `N` 행에 원본 카드 번호·담당 인물 ID를 추가한다. 이전 형식 1~9는 기존 행성/함정/수도 직위와 진행값을 보존하며 국가 직무는 빈 상태로 읽는다. 알 수 없는 카드·중복·비양수 담당자·개수 불일치는 거부한다. 단순 이관으로 사용자에게 국가 권한을 지급하지 않는다.

수도 임명은 56←2, 57←17, 192←134, 193←161의 저장된 인사권을 검사한다. 서버의 직무 공석·실제 수도·소속·계급·선임·대상 등록·자기 임명 금지·16장 한도와 진행 작업을 확인하고 MCP 160(부족 시 PCP 320 전액 대용)과 새 직위를 한 번에 저장한다. 중복 실행은 다시 결제하지 않는다. 원본 직무/거점/인물 선택과 확인창을 사용하고 온라인 대상에게 완전한 직무 목록을 갱신한다. 국가 인사권자는 자기 직무에 맞는 계급이어야 하며 동맹에는 상급대장을 허용하지 않는다.
