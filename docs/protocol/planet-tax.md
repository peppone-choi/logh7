# 행성 세율 변경의 서버 연결

작성: 최병호 · 2026-10-26

현재 수도 직위 분리와 수도시정관·현재 관할 선택은 [수도시정관과 복수 관할](#수도시정관과-복수-관할)을 따른다. 아래 최초 오딘의 일반 총독 시험은 수도 규칙 완료 사례가 아니다.

## 확인한 원본 경로

CD 클라이언트의 내정 그룹은 `0x0a00`부터 15개다. 그룹 기준값 함수 `0x00438e30`, 개수 함수 `0x00438e40`, 이름표 `0x00764a10`을 대조했다. 첫 명령은 `CommandChangeTaxRate`이며 writer `0x00434880`, reader `0x00435e80`이다. 몸체는 시각 u32, 인물 ID u32, 모드 u8, PCP/MCP 각각 u32, 거점 ID u32, 세율 u8, 카드 u16, 결과 u8의 순서로 25바이트다. C++ 메모리 패딩을 전송하지 않는다. `evidence:client`

총독 카드 번호는 제국 54, 동맹 190이다. 서버는 카드 번호만 신뢰하지 않고 저장된 거점의 `governorId`, 세력, 진영과 인증 인물·연결·세션 세대를 검사한다. 기존 데이터나 신규 거점에 총독을 자동 임명하지 않는다. 저장된 직무의 카드 표시는 아래 경로에 연결했으며, 실제 임명 명령은 아직 미완료다.

### 보유 CD의 화면 생성 경로

원본 카드 클릭 처리 `0x004f58c0`은 카드 정의의 명령 ID를 읽어 관리자 `0x00c9e2e0`의 실행기 `0x004f93c0`에 넘긴다. 등록 함수 `0x0058c750`과 실제 실행 중 표를 대조하면 세율 명령 30의 생성기는 `0x00587bd0`이다. 이 함수는 기본 객체를 할당·초기화한 뒤 즉시 해제하고 항상 0을 반환한다. 따라서 이 CD 빌드에서는 카드를 지급하거나 서버 응답만 채워도 세율 조작 창이 생성되지 않는다. 패킷 직렬화/수신기와 설명 문자열의 존재를 조작 화면 구현의 존재로 해석하지 않는다. `evidence:client`

이는 세율 조작 창에 대한 결론이며 모든 행성 조회 창의 부재를 증명한 것은 아니다. 확보한 공식 추가 데이터 `G7UPD040514`는 [기존 해체 결과](../re/update-040514.md)상 텍스처 추가이며 대체 실행 파일은 없다. 사라진 후속 패치의 화면 코드까지 확인한 것은 아니다. 아래 조작 창은 원본 자산·엔진을 사용한 재구현이며, 기존 행성 조회 창 전체를 원본 화면 복원으로 완료 처리하지 않는다.

### 저장된 직무 카드와 조작 창 연결

월드 스냅샷의 같은 세션 세대·인물 ID·세력·일반 진영에 맞는 `governorId`에서 보유 카드를 계산한다. 로그인 `0323`, 이동/CP/세율 변경 `0356`, 주변 인물 데이터에 같은 카드와 담당 거점 ID를 보존한다. 기존 개인·함장 카드 2장은 유지한다. 원래 보유 상한 16장에 맞춰 추가 직무는 거점 ID 순으로 최대 14장까지만 전달한다. 카드 정의/명령 정의에는 총독 54·주지사 190과 명령 30을 연결했다. 인사 명령·제안·복수 관할지의 개별 선택·직무 변경 통지는 별도 미완료다. `evidence:guess`(초기 표시 정책), `evidence:client`(카드 레코드·명령 ID)

호환 DLL은 본인의 총독 카드 세율 항목만 새 조작 창으로 연결한다. 현재 세율을 `031e→031f`로 새로 조회하고 변경값을 0~100에서 ±1/10씩 선택한다. 다른 인물 카드나 기존 명령은 원래 처리기로 전달한다. 실행 시 서버 응답까지 추가 조작을 막으며, 성공 응답 뒤에만 저장 안내를 표시한다. 거부 시 안내와 현재값을 유지한다. 닫기/재열기는 저장되지 않은 선택을 버리고 다시 조회한다. 원본 창틀과 버튼을 사용했지만 구체적인 배치는 재구성이다. `evidence:guess`(조작 배치), `evidence:client`(기존 GUI·통신 API)

## 현재 서버 정책과 저장

현재 지원 범위는 총독 본인이 정박한 아군 거주 행성의 모드 0 세율 변경(0~100)이다. 다른 모드·제안·직무는 거부한다. **직무·위치 제약·지원 모드·성공/실패 코드 의미는 초기 설계다.** 매뉴얼의 납입률 변경과 같은 명령으로 해석하지 않는다. `evidence:guess`

비용은 MCP 160이며 대기·소요는 0G시간이다. 원본 `constmsg.dat` 그룹 0 항목 97의 설명과 그룹 18 항목 30의 명령명을 대조했다. 기존 PCP 320은 근거를 찾지 못해 넣었던 설계값이므로 이 원본 근거로 교체했다. MCP가 부족하면 기존 공통 CP 규칙에 따라 PCP 320 전액 대용만 허용하며, 두 풀을 섞어 결제하지 않는다. `evidence:client`(설명·명령명), `evidence:manual`(CP 전액 2배 대용; W p.27)

클라이언트가 보내는 시각·CP·결과는 권위 값으로 사용하지 않는다. CP 회복/기존 작업 정산 후 변경 전후 상태를 계산하고 `FileWorldStateStore.saveWorld` 한 번으로 결제와 세율을 확정한 뒤 액터의 두 메모리 상태를 공개한다. 공통 저장소가 없는 설정에서는 변경을 거부하고 결제하지 않는다. 확정 직전 I/O 실패 시 이전 상태를 유지하고 후속 쓰기를 차단한다.

같은 세율의 재요청은 결제 없이 현재 값을 반송한다. 이는 같은 값 재전송의 중복 결제 방지이며, 중간에 다른 세율로 바뀐 뒤 과거 요청까지 식별하는 영속 명령 ID 멱등성은 아니다. 응답 뒤 기존 인물 CP 변경과 행성 조건 응답을 보내 조회값을 갱신한다. 세율에 따른 징세·수입·금고·민심 효과는 아직 없다.

재고 형식은 `LOGH7-STOCK-7`이다. P 행 끝에 nullable 세율(`-` 또는 0~100)과 총독 인물 ID(미임명 0)를 추가한다. 형식 1~6은 기존 값과 함정 ID/다음 번호를 보존하며 세율 미지정·총독 0으로 읽는다. 형식 7을 읽지 못하는 구버전으로 되돌리기 전에는 별도 역이관이 필요하다.

## 검사 상태

관련 엔진 388·프로토콜 49·저장소 56·게이트웨이 96개 검사와 app 배포 빌드가 통과했다. 새 검사에서는 권한 위조 거부, 서버 CP 결제, 같은 값 중복 결제 방지, 결제/설정 동시 재개방, 저장 실패 시 두 상태 보존·후속 쓰기 차단, 공통 저장 경계 누락 시 무결제 거부, 구형 이관·손상 거부와 암호화 요청/응답을 확인했다. 원본 UI를 통한 실행과 경제 전체 완료를 뜻하지 않는다.

첫 시험은 일반 송신 함수의 선택자를 바꿔 연결하려다 세율 응답을 받지 못하고 연결 종료로 끝났다. 이후 선택자 변경을 제거하고 원본 통신 객체의 가상 함수에 명령 번호·원본 구조체를 전달한 시험은 성공했다. 이는 시험용 호출이며 총독 카드 UI 복원은 아니다. 별도 사본 데이터에서 인물 10000을 총독으로 지정했지만 플레이 중 임명 경로를 대신하지 않는다.

원본 한 개에서 오딘(1049) 세율을 20→35로 바꾸고 원본 수신기 `0x00435e80`이 시각·인물 10000·PCP 680·MCP 1000·세율 35·카드 54·결과 0을 읽는 것을 확인했다. 같은 값 재요청의 두 번째 응답도 PCP 680을 유지했고, 행성 조건 캐시와 조회 화면에 35%, HUD에 PCP 680이 표시됐다. CP 결제와 세율은 같은 활성 저장 슬롯에 기록됐고, 반대 슬롯에는 이전 CP 1000·세율 20이 남았다. **이 최초 왕복은 비용 교정 전 PCP 320 설계값으로 실행한 기록이다.** `evidence:client`

서버와 클라이언트를 모두 종료한 뒤 같은 저장소로 재기동했다. 재접속 후 활성 슬롯의 이동/재고 파일은 저장된 완성본과 바이트 단위로 같았고, 화면에서도 오딘 35%·PCP 680을 유지했다. 기존 함정 다음 ID 1201을 보존했다. 원본 해시 보존·소유 프로세스 종료·음향 정리를 확인하고 일반 서버를 복구했다. 자료는 Git 제외 `work/domestic-tax-20261026/native-05`, `native-06`과 전후 저장 사본에 둔다. 총독 임명·원래 카드 조작·전체 내정 UI, 동맹 원본 한 개와 두 원본 동시 실행은 아직 미확인이다.

MCP 160 교정 후에는 `native-07`에서 세율 35→40, MCP 1000→840과 동일 값 재요청의 MCP 840 유지를 원본 수신·화면·저장에서 확인했다. PCP는 755였으며 정상 시간 회복이 반영된 값이다. 해당 세율 결제로 PCP를 차감하지 않았다. 다시 양쪽을 종료·재기동한 `native-08`에서도 세율 40·PCP 755·MCP 840이 표시됐고 활성 이동/재고 파일은 전후 완성본과 같았다. 변경 범위의 엔진 2·저장소 4·게이트웨이 2개 검사와 app 빌드도 통과했다. 이 단락은 카드 조작 창 연결 전 시험 통신 호출의 기록이다.

### 조작 창의 실제 확인

후속 `work/governor-tax-ui-20261026/` 시험은 임명된 상태의 사본 데이터(인물 10000, 오딘 1049)를 사용했다. 메모리에서 세율 요청을 실행하는 시험 호출 없이 원본 카드 목록→총독→세율 변경→증감→실행을 실제 창 입력으로 확인했다. `native-05`에서 40→50과 MCP 1000→840, 저장 완료 안내·HUD·활성 슬롯의 같은 값을 대조했다. 이후 51을 선택하고 실행 없이 닫으면 재열기에서 50으로 돌아왔으며 추가 결제하지 않았다. CP의 정상 시간 회복은 계속된다.

변경값의 상한 100·하한 0을 넘기려 해도 범위 안에 머물렀다. `native-06`은 성공 후 저장을 백업한 뒤 시험 잔고만 0으로 둔 별도 조건이다. 50→51 실행은 거부 안내를 표시하고 연결을 유지했으며 세율 50·PCP/MCP 0을 보존했다. 이 조건을 일반 플레이 데이터에 적용하지 않았다. 검사 후 성공 저장을 복원하고 `native-07`에서 양쪽 재시작·총독 카드 재열기·현재 세율 50과 기존 게임 설정 탭을 확인했다.

프로토콜 50·게이트웨이 96개 검사와 app 빌드가 통과했다. 직무가 없는 인물은 기본 2장만 받고, 저장된 직무가 있는 인물은 담당 거점 ID가 있는 총독 카드와 CP 변경 후 보존을 암호화 왕복에서 검사했다. 동맹 주지사의 레코드 형식도 검사했지만 동맹 원본 조작·두 원본 동시 시험·전체 전술 화면은 이번 확인에 포함하지 않았다. 호환 DLL은 x86 `/W4 /WX`와 다른 EXE의 변경 거부 검사를 통과했다.

마지막 `native-08`은 시험 잔고 복원 이후 저장을 다시 손대지 않고 양쪽을 종료·재시작한 확인이다. 총독 카드에서 세율 50을 다시 조회했고 활성 이동/재고 파일은 전후 완성본과 같았다. 원본 해시·소유 프로세스 종료·음향 정리를 확인했다. [일반 서버 공통 저장소 전환](../server/world-state-storage.md#일반-로컬-서버의-전환-2026-10-26)에서도 시험 직무를 섞지 않고 기존 2장 카드와 전략 화면을 확인했다.

## 수도시정관과 복수 관할

일반 제국 행성은 54/총독, 일반 동맹 행성은 190/주지사, 하이네센은 192/수도시정관으로 세율을 설정한다. 서버는 `BaseOfficePolicy`가 계산한 해당 거점의 실제 직위 보유자와 카드 종류를 함께 검사한다. 과거 수도의 `governorId`만 가진 인물이나 수도방위지휘관 193에는 권한을 주지 않는다. 거주 가능·현재 거점·진행 작업·CP·동일 값 무결제·통합 저장 검사는 공통이다.

원본 카드 설명은 수도시정관을 수도의 최고 행정관으로 설명하고 경제·생산 통제를 포함한다. 매뉴얼 조직표 p.64는 국무위원장이 임명하는 정치가 직위로 구분한다. 그러나 원본 서버의 직무별 세율 명령 목록은 확보하지 못했다. 카드 192에 기존 명령 30과 같은 비용/검사를 연결하는 것은 명시적인 복원 설계다. 이를 원작 세율 권한의 확정 근거로 취급하지 않는다. `evidence:client`(카드 설명·명령 30), `evidence:manual`(직위·임명권), `evidence:guess`(192의 세율 권한)

세율 창은 보유 카드의 첫 관할을 고르지 않는다. 원본 위치 조회기 `004b5bf0`의 자기 인물 `+0x358` 현재 거점과 일치하는 카드/대상을 찾는다. 여러 54/190을 가진 인물도 현재 위치의 관할을 연다. 현재 거점이 없거나 일치하는 직무가 없으면 열지 않으며, 열린 뒤 거점/직무가 바뀌면 닫는다. 카드 192에는 수도시정관 이름을 표시한다. 세율 창은 기존 원본 자산을 사용한 재구성이고 전체 내정 UI 복원은 아니다. `evidence:client`(위치·카드), `evidence:guess`(현재 위치 선택)
