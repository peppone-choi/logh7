# 행성 세율 변경의 서버 연결

작성: 최병호 · 2026-10-26

## 확인한 원본 경로

CD 클라이언트의 내정 그룹은 `0x0a00`부터 15개다. 그룹 기준값 함수 `0x00438e30`, 개수 함수 `0x00438e40`, 이름표 `0x00764a10`을 대조했다. 첫 명령은 `CommandChangeTaxRate`이며 writer `0x00434880`, reader `0x00435e80`이다. 몸체는 시각 u32, 인물 ID u32, 모드 u8, PCP/MCP 각각 u32, 거점 ID u32, 세율 u8, 카드 u16, 결과 u8의 순서로 25바이트다. C++ 메모리 패딩을 전송하지 않는다. `evidence:client`

총독 카드 번호는 제국 54, 동맹 190이다. 서버는 카드 번호만 신뢰하지 않고 저장된 거점의 `governorId`, 세력, 진영과 인증 인물·연결·세션 세대를 검사한다. 기존 데이터나 신규 거점에 총독을 자동 임명하지 않는다. 실제 임명·카드 지급·원본 카드 화면 진입은 아직 연결하지 않았다.

## 현재 서버 정책과 저장

현재 지원 범위는 총독 본인이 정박한 아군 거주 행성의 모드 0 세율 변경(0~100)이다. 다른 모드·제안·직무는 거부한다. CP 320과 기존 PCP 부족 시 MCP 2배 결제 규칙을 적용한다. **이 명령의 비용·위치 제약·지원 모드·성공/실패 코드 의미는 복원 확정값이 아닌 초기 설계다.** 매뉴얼의 납입률 변경과 같은 명령으로 해석하지 않는다. `evidence:guess`

클라이언트가 보내는 시각·CP·결과는 권위 값으로 사용하지 않는다. CP 회복/기존 작업 정산 후 변경 전후 상태를 계산하고 `FileWorldStateStore.saveWorld` 한 번으로 결제와 세율을 확정한 뒤 액터의 두 메모리 상태를 공개한다. 공통 저장소가 없는 설정에서는 변경을 거부하고 결제하지 않는다. 확정 직전 I/O 실패 시 이전 상태를 유지하고 후속 쓰기를 차단한다.

같은 세율의 재요청은 결제 없이 현재 값을 반송한다. 이는 같은 값 재전송의 중복 결제 방지이며, 중간에 다른 세율로 바뀐 뒤 과거 요청까지 식별하는 영속 명령 ID 멱등성은 아니다. 응답 뒤 기존 인물 CP 변경과 행성 조건 응답을 보내 조회값을 갱신한다. 세율에 따른 징세·수입·금고·민심 효과는 아직 없다.

재고 형식은 `LOGH7-STOCK-7`이다. P 행 끝에 nullable 세율(`-` 또는 0~100)과 총독 인물 ID(미임명 0)를 추가한다. 형식 1~6은 기존 값과 함정 ID/다음 번호를 보존하며 세율 미지정·총독 0으로 읽는다. 형식 7을 읽지 못하는 구버전으로 되돌리기 전에는 별도 역이관이 필요하다.

## 검사 상태

관련 엔진 388·프로토콜 49·저장소 56·게이트웨이 96개 검사와 app 배포 빌드가 통과했다. 새 검사에서는 권한 위조 거부, 서버 CP 결제, 같은 값 중복 결제 방지, 결제/설정 동시 재개방, 저장 실패 시 두 상태 보존·후속 쓰기 차단, 공통 저장 경계 누락 시 무결제 거부, 구형 이관·손상 거부와 암호화 요청/응답을 확인했다. 원본 UI를 통한 실행과 경제 전체 완료를 뜻하지 않는다.

첫 시험은 일반 송신 함수의 선택자를 바꿔 연결하려다 세율 응답을 받지 못하고 연결 종료로 끝났다. 이후 선택자 변경을 제거하고 원본 통신 객체의 가상 함수에 명령 번호·원본 구조체를 전달한 시험은 성공했다. 이는 시험용 호출이며 총독 카드 UI 복원은 아니다. 별도 사본 데이터에서 인물 10000을 총독으로 지정했지만 플레이 중 임명 경로를 대신하지 않는다.

원본 한 개에서 오딘(1049) 세율을 20→35로 바꾸고 원본 수신기 `0x00435e80`이 시각·인물 10000·PCP 680·MCP 1000·세율 35·카드 54·결과 0을 읽는 것을 확인했다. 같은 값 재요청의 두 번째 응답도 PCP 680을 유지했고, 행성 조건 캐시와 조회 화면에 35%, HUD에 PCP 680이 표시됐다. CP 결제와 세율은 같은 활성 저장 슬롯에 기록됐고, 반대 슬롯에는 이전 CP 1000·세율 20이 남았다. `evidence:client`

서버와 클라이언트를 모두 종료한 뒤 같은 저장소로 재기동했다. 재접속 후 활성 슬롯의 이동/재고 파일은 저장된 완성본과 바이트 단위로 같았고, 화면에서도 오딘 35%·PCP 680을 유지했다. 기존 함정 다음 ID 1201을 보존했다. 원본 해시 보존·소유 프로세스 종료·음향 정리를 확인하고 일반 서버를 복구했다. 자료는 Git 제외 `work/domestic-tax-20261026/native-05`, `native-06`과 전후 저장 사본에 둔다. 총독 임명·원래 카드 조작·전체 내정 UI, 동맹 원본 한 개와 두 원본 동시 실행은 아직 미확인이다.
