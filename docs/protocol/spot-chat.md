# 스폿 채팅 연결

작성: 최병호 · 2026-10-25 · 관련: LOGH-30

같은 스폿의 대화는 매뉴얼 W p.17–18의 규칙이다. 같은 부대·같은 그리드 채팅, 전술 진영 채팅, 메신저·메일·명함 교환은 별도 기능이며 이번 연결에 포함하지 않는다. [통신 규칙](../manual/03-communication.md)을 따른다. `evidence:manual`

CD 클라이언트 `00465810`의 길이 계산과 `00465960`의 출력 경로에서 `CommandSpotChat=0f1d`의 본문은 아래 순서다. opcode를 제외한 길이는 `9+2N`이다. 메모리의 문자열은 +10에 있지만 wire에는 정렬 패딩이 없다. 수신 `004be680`→`004be6f0`은 N개의 코드 단위를 복사한 뒤 종료 NUL을 별도로 붙인다. `evidence:client`

| 본문 offset | 형식 | 의미 |
|---|---|---|
| 0 | BE32 | 게임 시각 |
| 4 | BE32 | 발신 캐릭터 ID |
| 8 | u8 | UTF-16 코드 단위 수 N, 최대 65 |
| 9 | BE16 × N | 종료 NUL 없는 메시지 |

서버는 인증·게임 입장·월드 초기화를 마친 연결만 받아 발신자 ID를 대조하고 서버 시각으로 대체한다. 빈 문장·공백만 있는 문장·제어 문자·서로게이트·길이 불일치·초과 길이는 거부한다. 동일 세대·그리드·거점·0이 아닌 스폿·방 소유자가 일치하는 온라인 접속자에게만 세력과 무관하게 전달한다. 스폿 0은 각자의 함내이므로 다른 함장에게 전달하지 않는다. 본인에게는 한 번만 반송하며 각 수신자의 기존 암호화 송신 큐를 사용한다. 대화 기록 저장은 구현하지 않았다. `evidence:guess`(검증·라우팅 정책)

코덱 검사와 두 암호화 클라이언트 시험에서 왕복, 중복 반송 방지, 다른 방·개인실 소유자·세대·그리드 분리, 이동 후 수신 중단, 발신자 위조 거부를 확인했다. 기존 입장·이동·접속 종료·재접속 검사도 통과했다.

비활성 데스크톱의 실제 CD 클라이언트 하나와 다른 세력의 암호화 합성 클라이언트 하나로 회의실에서 영문 입력·왕복 표시, 상대의 공원 이동 후 양쪽 메시지 분리, 회의실 복귀 후 답장 표시를 확인했다. 실제 창의 입력·원래 채팅 표시 경로를 사용했으며 시험 기록은 `work/spot-chat-20261025/`에 둔다. 두 원본 클라이언트 동시 실행과 한글 IME 입력은 미확인이다. 한글 문자열은 코덱 왕복에는 보존되지만 실제 채팅창에서는 글꼴/문자 변환 경로 때문에 깨져 보이는 문제가 남아 있다. 입·퇴실 시스템 문구에도 기존 `NO DATA`가 남아 있다. `evidence:client`
