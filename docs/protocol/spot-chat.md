# 스폿 채팅 연결

작성: 최병호 · 2026-10-25 · 관련: LOGH-30

같은 스폿의 대화는 매뉴얼 W p.17–18의 규칙이다. 같은 부대·같은 그리드 채팅, 전술 진영 채팅, 메신저·메일·명함 교환은 별도 기능이며 이번 연결에 포함하지 않는다. [통신 규칙](../manual/03-communication.md)을 따른다. `evidence:manual`

CD 클라이언트 `00465810`의 길이 계산과 `00465960`의 출력 경로에서 `CommandSpotChat=0f1d`의 본문은 아래 순서다. opcode를 제외한 길이는 `9+2N`이다. 메모리의 문자열은 +10에 있지만 wire에는 정렬 패딩이 없다. 수신 `004be680`→`004be6f0`은 N개의 코드 단위를 복사한 뒤 종료 NUL을 별도로 붙인다. `evidence:client`

| 본문 offset | 형식 | 의미 |
|---|---|---|
| 0 | BE32 | 게임 시각 |
| 4 | BE32 | 발신 캐릭터 ID |
| 8 | u8 | UTF-16 코드 단위 수 N, 최대 65 |
| 9 | BE16 × N | 종료 NUL 없는 메시지 |

서버는 인증·게임 입장·월드 초기화를 마친 연결만 받아 발신자 ID를 대조하고 서버 시각으로 대체한다. 빈 문장·공백만 있는 문장은 연결을 유지한 채 무시한다. 제어 문자·서로게이트·길이 불일치·초과 길이는 거부한다. 동일 세대·그리드·거점·0이 아닌 스폿·방 소유자가 일치하는 온라인 접속자에게만 세력과 무관하게 전달한다. 스폿 0은 각자의 함내이므로 다른 함장에게 전달하지 않는다. 본인에게는 한 번만 반송하며 각 수신자의 기존 암호화 송신 큐를 사용한다. 대화 기록 저장은 구현하지 않았다. `evidence:guess`(검증·라우팅 정책)

코덱 검사와 두 암호화 클라이언트 시험에서 왕복, 중복 반송 방지, 다른 방·개인실 소유자·세대·그리드 분리, 이동 후 수신 중단, 발신자 위조 거부를 확인했다. 기존 입장·이동·접속 종료·재접속 검사도 통과했다.

비활성 데스크톱의 실제 CD 클라이언트 하나와 다른 세력의 암호화 합성 클라이언트 하나로 회의실에서 영문 입력·왕복 표시, 상대의 공원 이동 후 양쪽 메시지 분리, 회의실 복귀 후 답장 표시를 확인했다. 실제 창의 입력·원래 채팅 표시 경로를 사용했으며 시험 기록은 `work/spot-chat-20261025/`에 둔다. 이때 한글 메시지의 화면 표시가 깨지는 것을 관찰했으며 아래 보완에서 수정했다. 두 원본 클라이언트 동시 실행과 한글 IME 입력은 미확인이다. 입·퇴실 시스템 문구에도 기존 `NO DATA`가 남아 있다. `evidence:client`

## 한글 수신 표시 보완 (2026-10-25)

수신 `004be6f0`, 필터 `005226f0`, 원래 UTF-16 풀의 추가 `004eabb0`까지 합성 한글 메시지가 보존되는 것을 소유 프로세스에서 확인했다. 이어지는 색상 제어 문구 추가 `005035a0`→`004eab10`은 기존 풀 전체를 ANSI CString으로 바꾼 뒤 일본어 CRT 경로 `004eaaf0`으로 되돌린다. 이 과정이 한글을 손상시켰다. `evidence:client`

호환 모듈은 확인한 `005035d3` 호출 한 곳에서 새 ANSI 조각만 CP932→UTF-16으로 변환하고 기존 `004eabb0`에 추가한다. 기존 UTF-16 내용·이름·색상 제어 코드를 유지하며 시스템 로캘이나 원본 파일은 바꾸지 않는다. 원래 글자 캐시의 Unicode 보정과 함께 사용한다. 변환 실패 시 기존 내용을 보존한다. `evidence:client`(호출·표시 경로), `evidence:guess`(실패 시 보존 정책)

관련 x86 빌드·일본어 조각/색상 제어/잘못된 바이트 검사와 다른 EXE 후킹 거부 검사를 통과했다. 수정 DLL만 설치한 비활성 데스크톱의 실제 클라이언트와 다른 세력 합성 접속으로 한글·일본어·영문 혼합 메시지 수신 표시와 실제 영문 답장을 확인했다. 진단용 Frida 추적은 수정 전 실행에만 사용했고, 수정 확인 실행에는 제품 DLL과 기존 실행기의 렌더/입력 보정만 사용했다. 기록·화면은 `work/playability-checklist-20261025/`에 둔다. IME 입력, 1만 자 초과 기록 정리, 두 원본 동시 실행은 아직 확인하지 않았다.
