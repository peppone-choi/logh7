# 부대 보충의 연결

작성: 최병호 · 2026-10-27

## 근거와 메시지

매뉴얼 병참 §7.5는 지휘관의 같은 함종 보충, 부대 창고의 정확히 같은 타입 사용, 승조원 자동 보충과 상선의 승조원 예외를 설명한다(`gin7manual.pdf`, 병참 절). 명령 표의 MCP는 160이며 대기·소요는 0이다. 원본 명령 이름은 constmsg 그룹 18의 64다. `evidence:manual` `evidence:client`

원본 `00552610`/`00556b10`의 `0c05` 본문은 시각·인물(u32), 모드(u8), PCP·MCP·거점·부대(u32), 종류(u8), 보충 함종 수(u8, 최대 99)와 각 함종(u16)·함정 ID 수(u8, 최대 99)·ID(u32) 목록이다. 이후 승조원 이동 수(u8, 최대 24)와 `(kind:u16, grade:u8, units:i16)`, 물자 이동(i32), 결과 함선/병력 목록, 결과 물자·승조원 상한·물자 상한(u32)이 온다. 배열이 비어 있는 요청은 opcode 포함 48바이트다. 요청의 CP·이동 승조원·결과 편성·상한은 서버의 상태로 신뢰하지 않는다. `evidence:client`

보충 화살표는 검색 34의 `1200`을 보내며, 함종은 요청 오프셋 23의 u16이다. 원본 `0055f1f0`/`0055f580`은 `1207`의 u16 개수(최대 600)와 `(id:u32, kind:u8, destroyed:u16)`를 읽는다. 인증된 지휘관의 아군 부대에서 해당 함종의 손실 유닛만 반환하고 `1200→1207→1201`을 마친다. `evidence:client`

## 구현

모드 0은 비용·편성 저장 없이 미리보기를 반환하고 모드 1은 현재 서버 상태로 다시 검증해 확정한다. 한 함종의 중복 없는 실제 부대 ID만 허용한다. 창고의 같은 함종에서 부족한 척수만 꺼내며, 유닛 ID와 기존 숙련도는 보존한다. 포장을 해제하고 남은 함선은 창고에 별도로 보존한다. 기존 할당/재편성 예약과 공유 창고가 겹치면 거부한다. CP·함정 생존 척수·창고 잔여 척수·승조원·군수물자를 같은 월드 커밋으로 저장한 뒤 공개한다. 저장 실패 시 이전 상태를 유지하고 쓰기를 차단한다.

복원 설계는 다음과 같다. 창고의 낮은 숙련도부터 같은 함종을 사용하되 현역 숙련도는 바꾸지 않는다. 승조원 필요량은 생존 척수에 비례해 유닛마다 올림하며, 창고에서 가능한 만큼 자동 보충하고 필요량이 있는데 승조원 총량이 0이면 거부한다. 군수물자의 양수 적재와 음수 반환은 부대/창고 양쪽 잔고와 기존 적재 상한 안에서 허용한다. 무변경은 무과금이다. 개별 함선 전투 손실·승조원 효율의 원작 공식으로 단정하지 않는다. `evidence:guess`

`LOGH7-STOCK-13`은 현역 레코드의 `id.kind.grade.boats`와 창고의 포장되지 않은 함선 `kind.grade.boats`를 저장한다. 12 이하의 기존 3필드 현역 ID는 원래 서버가 저장하던 온전한 유닛으로 읽는다. 13에서는 생존 척수 누락을 거부해 손실이 조용히 복구되지 않도록 한다. 손실 유닛을 재편성으로 반환할 때에도 실제 잔여 척수만 창고에 들어간다. 구버전 프로그램으로 되돌릴 때는 새 저장 형식을 읽을 수 없으므로 해당 배포 전 백업을 함께 사용한다.

## 확인과 남은 범위

엔진 438개·프로토콜 89개·저장 83개·인접 병참 게이트웨이 15개 검사가 실패/오류/건너뜀 없이 통과했다. 물자·척수 보존, 창고 잔여 척수 재사용, 위조 결과 무시, 잘린 배열/범위 거부, 미리보기 무저장, 재전송 무과금, 파일 재개방과 통합 커밋 실패 보존을 포함한다. 호환 모듈의 x86 /WX 빌드·가드 검사도 통과했다.

원본 한 개의 동맹 수송부대 카드→보충→전함 행/화살표→손실 유닛 641 선택→결정→확정에서 `0c05` 모드 0/1을 확인했다. 현역 전함 890→900척, 부대 창고 600→590척(온전한 유닛 1 + 개별 함선 290), 승조원 6→12유닛/창고 100→94, MCP 1000→840을 확인했다. 선택 전 검색이 없어서 끊기던 경로는 위 `1207`로 연결했다. `evidence:client`

원본 재시작 후 재조회와 마지막 수량 라벨 수정은 확인 중이다. 선택창의 `NO DATA` 제목/안내, 수량 단위·우측 합계 배치, 원본 물자 적재/반환 조작은 미완료다. 물자 적재/반환은 암호화 접속·규칙 검사까지만 확인했다. 창고에 남은 개별 함선의 재편성/행성 할당 반환과 편집창을 열어 둔 전체 시간의 예약, 실제 전술 손실에서 보충까지의 연결도 남아 있다. 위 실행으로 전체 보충이나 병참을 완료 처리하지 않는다. 실행 자료는 Git 제외 `work/outfit-supplement-20261027/`다.
