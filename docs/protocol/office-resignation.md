# 원본 카드의 사임 연결

작성: 최병호 · 2026-10-26

원본 카드의 명령 7과 `CommandCardResignation`(`0709`)을 연결한다. 해임(명령 6, `0708`)과는 별도이며 해임은 아직 제공하지 않는다.

## 송수신과 처리

원본 직렬화기 `0043b960`·디코더 `0043e020`과 실제 근위병총감 카드의 송신을 대조했다. 요청은 opcode 뒤 시각·인물·PCP·MCP·카드 종류·이동 스폿의 `u32` 여섯 개와 이동 인물 수 `u8`로, 전체 27바이트다. 거점/부대 ID는 포함하지 않는다. 현재 지원하는 요청은 이동 스폿과 인물 수가 모두 0인 경우다. 응답은 일반 세션 메시지의 결과 필드와 같은 본문을 사용하며 서버가 확정한 PCP/MCP를 반환한다. `evidence:client`

서버는 인증된 접속·세션 세대·본인·진영과 실제 저장된 직위를 검사한다. 국가 직무 2/17/134/161, 부대 지휘관 39/44/47/50/175/180/183/186, 일반 통치자·수비대장 52/54/55/188/190/191, 수도 직위 56/57/192/193을 지원한다. 같은 종류의 직위가 둘 이상이면 요청만으로 담당 대상을 식별할 수 없으므로 무결제로 거부한다. 함장·개인 카드의 사임은 지원하지 않는다.

MCP 80을 결제하고 부족하면 PCP 160 전체 대체 결제를 적용한다. 원본 확인창의 비용 표시와 매뉴얼 W p.72를 따른다. 이동/급유 대기와 CP 정지 중에는 거부한다. 직위 해제와 CP는 월드 저장 한 번으로 확정한 뒤 현재 인물·카드와 공개 보유자 명단에 반영한다. 저장 실패에는 둘 다 발표하지 않는다. 재전송은 이미 직위가 없으면 거부하며 재결제하지 않는다. `evidence:manual`(비용), `evidence:guess`(중복 직위·병행 작업·원자 저장 정책)

확인창은 원래 직무 이름을 연결해 사임 대상을 표시하며 기존 비용·결정/취소를 유지한다. 화면 배치나 별도 행성 정보 UI를 복원한 변경은 아니다.

## 확인 결과와 한계

- 엔진 407개·프로토콜 69개·영속화 76개·게이트웨이 124개 검사에서 실패/오류 0. 기존 카드 명령 개수 기대값을 수정한 뒤 프로토콜 검사를 다시 통과했다. 새 검사는 22종 직위의 해제, 다른 직위 보존, 재전송·권한·CP·중복 대상 거부, 암호화 두 접속의 공개 명단, 저장 실패와 재개방을 포함한다.
- x86 `/W4 /WX` 빌드와 다른 EXE 후킹 거부 검사를 통과했다.
- 비활성 데스크톱의 원본 한 개에서 실제 임명 결과를 복사한 별도 시험 월드의 근위병총감으로 확인→취소(직위·MCP 1000 유지), 다시 확인→결정(MCP 920), 카드 제거를 확인했다. 서버와 클라이언트 모두 재시작한 뒤 사임 카드가 돌아오지 않았다. 재접속 MCP 995는 정상 시간 회복이다. 해당 재접속 실행에서 행성 상세의 공석 표시는 확인하지 않았다.
- 실행·캡처는 Git 제외 `work/office-removal-20261026/`에 보존했다. 원본 해시 보존·프로세스 종료·작업 프로세스 0·음향 복원을 확인했고, 일반 월드는 시험 임명 없이 runtime-51로 다시 실행했다.

동일 종류의 복수 직위 선택 규칙, 개인실 퇴거/이동 인물 처리, 다른 21종의 실제 원본 입력, 해임과 전체 인사 수명주기는 미완료다. 이 범위를 원래 사임 기능 전체의 완성으로 체크하지 않는다.
