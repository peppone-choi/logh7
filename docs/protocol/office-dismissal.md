# 원본 카드의 해임 연결

작성: Peppone Choi · 2026-10-27

원본 명령 6의 `CommandCardDismisal`(`0708`)을 연결한다. 비용 MCP 160과 즉시 실행은 매뉴얼 W p.72 및 CD 명령 정의를 따른다. 본인 직무를 내려놓는 [사임](office-resignation.md)과 별도이며, 저장된 임명권으로 타인의 직무를 해제한다. `evidence:manual`

## 원본 요청과 선택 화면

기존 해석 `work/office-removal-20261026/G7MTClient.exe.codec2.decomp.txt`의 직렬화기 `0043b4f0`, 필드 출력 `0043b6c0`, 실제 송신을 대조했다. 요청은 opcode 뒤 시각·인물·PCP·MCP·대상 인물·카드의 u32 여섯 개, 이동 스폿 u32, 이동 인물 수 u8와 인물 목록이다. 현재는 클라이언트가 이동 효과를 제공하지 않는 31바이트 요청만 받는다. 응답에는 서버 시각·결제 후 잔액을 넣고 거부/반복에는 대상 ID를 0으로 보내 원본 수신기의 직무 제거 부작용을 막는다. `evidence:client`

실제 원본은 직무 선택 뒤 `1200` 검색 5·flags 80·선택 카드·현재 권한 카드로 담당자를 조회한다. 검색 18의 첫 직무 목록 요청은 임명과 바이트가 같고 명령 종류가 없다. 따라서 첫 목록은 임명 가능한 공석과 해임 가능한 담당 직무의 합집합을 반환하며, 직무별 수량은 두 경로의 최댓값이다. 임명 검색 4/거점/부대와 해임 검색 5, 최종 실행은 각 정책으로 다시 제한한다. 공석 없는 직무도 해임 선택이 가능하다. 첫 목록을 명령별 공석/현원으로 정확히 나누는 것은 원본 프로토콜만으로 불가능하며 현재 수량을 전체 공석 통계로 사용하지 않는다. `evidence:client`(동일 요청·검색 5), `evidence:guess`(공통 목록 복원 정책)

공유 인물 선택창은 명령 6에서만 해임 대상·현재 담당자·해임 조건으로 바꾼다. 확인 단계 모드도 6이며, 완료된 원본 선택 변수에서 인물과 직무 이름을 가져와 첫 줄에 표시한다. 기존 비용·대기·소요 시간·결정/취소는 유지한다. 원본 확인창이 함대 ID를 제공하지 않으므로 인물·직무를 표시하며 서버가 같은 종류의 복수 직위를 거부한다.

## 실행과 영속화

지원 범위는 양 세력 함대 10직무, 수도 4직위, 제국 일반 행성 수비대장이다. [조직표 기반 임명](garrison-appointment.md)의 저장된 국가 직무 또는 실제 함대사령관, 일반 행성의 실제 총독을 검사한다. 인증 접속·세대·본인·진영·현재 담당자·권한 계급·우호 정규 거점·대기 작업·CP를 서버에서 검증한다. 대상 CP는 결제하지 않으며 MCP 부족 시 PCP 320 전체 대체 결제를 적용한다. `evidence:guess`(복원 정책)

요청에 거점/함대 ID가 없으므로 대상이 같은 종류의 직무를 여러 곳에서 맡으면 임의 해제하지 않고 거부한다. 후보 목록에서도 이러한 대상을 제외한다. 참모 해임은 해당 인물 한 명만 제거하고 다른 참모·사령관·부관을 보존한다. 해임자는 해당 직위의 임명권이 있어야 하며 직무 이름이나 계급만으로 권한을 부여하지 않는다.

월드 액터가 비용과 직무를 한 번의 통합 저장으로 확정한 뒤 발표한다. 저장 실패 시 둘 다 발표하지 않으며 저장 장애 상태로 전환한다. 반복 요청은 더 이상 담당자가 아니므로 거부하고 재결제하지 않는다. 온라인 대상에게 전체 직무 목록과 현재 기항지 소속을 갱신하며 대상의 최신 위치·CP를 덮어쓰지 않는다. 기존 STOCK-12를 사용하며 새 저장 형식은 추가하지 않는다.

## 확인 결과와 남은 범위

- 엔진: 함대 10직무와 수도/일반 행성 직위의 실제 권한·개별 제거·다른 직위 보존·반복·CP/PCP 대체·권한 위조·중복 직위·공석 없는 참모진·점령 거점 거부를 확인했다.
- 프로토콜 전체 검사와 x86 DLL `/W4 /WX`·다른 EXE 후킹 거부 검사를 통과했다. 명령 목록에 해임을 추가하며 기존 국가 직무의 명령 개수 기대값도 갱신했다.
- 암호화 두 접속: 검색 5의 현재 참모, 실행/반복, 공개 명단 제거·온라인 대상 카드/소속 0·대상 CP 보존을 확인했다. 기존 함대 임명 검사도 통과했다.
- 통합 저장: 일반 수비대장·수도 근위병총감·함대 참모의 비용/직위 동시 확정, 저장 전환 실패 시 미발표·재요청 거부, 저장소 재개방 후 일치와 다른 담당자 보존을 확인했다.
- 실제 원본 한 개와 localhost 합성 상대: `work/office-dismissal-20261027/native-04`에서 동맹 사령장관→사령관/Admiral 선택·해임 제목/확인창 인물·직무 표시·결정 MCP 1000→840, 요청 대상 10001/카드 175를 확인했다. 온라인 합성 대상은 소속 133→0과 전체 직무 갱신을 받았다. 양쪽 재시작 후 `native-05`에서 대상의 사령관 카드 제거·소속 0·대상 MCP 1000을 확인했다.
- `native-03`의 취소 전후 MCP 1000 유지·해임 요청 없음도 대조했다. 이 실행은 인물 선택 제목 보완을 확인했고, 확인창 모드 교정은 최종 `native-04`에서 확인했다. 초기 `native-01`의 미지원 검색 5 접속 종료는 실패 재현이며 완료 증거가 아니다.

다른 14직위의 개별 원본 화면, 국가 상위 직무 자체의 임명/해임·선출, 일반 통치자/다른 부대장 임명권, 복수 직위 식별 UI, 개인실 퇴거/동행 인물 이동은 미완료다. 두 원본 클라이언트 동시 시험과 대규모 후보 목록도 남아 있다. 이 연결을 전체 인사 수명주기 완료로 체크하지 않는다.
