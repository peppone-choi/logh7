# 같은 그리드 채팅과 한글 송신

작성자: Peppone Choi · 2026-10-27

## 원본 경로와 수신 범위

CD 클라이언트의 길이 검사 `00465430`, 직렬화 `00465570`, 송신 `004b5600`, 수신 `004be660`은 `0f1c`를 처리한다. 같은 스폿의 `0f1d`와 다르다. 명령 코드 뒤에는 시간 u32, 인물 ID u32, 채널 u8, 길이 u8, NUL 없는 UTF-16BE 본문이 온다. 길이는 0–65 코드 단위이며 원본 입력 위젯의 설정 상한은 64다. `evidence:client`

채팅 창 생성기 `005159e0`의 버튼은 전체·함대·동진영 순서다. 전략 UI `00516bf0`의 전송값은 각각 0·2·1이고, 함대 버튼은 부대 소속이 없으면 사용할 수 없다. `evidence:client`

서버는 초기 월드 전송을 마친 인증 인물의 현재 위치와 소속으로 대상을 정한다. 모든 채널은 같은 세션 세대·같은 그리드에 한정한다. 0은 그 안의 전체, 1은 같은 진영, 2는 같은 진영의 같은 양수 부대 ID다. 미소속 ID 0끼리는 함대 채널을 공유하지 않는다. 보낸 사람에게는 자신의 암호화 큐로 한 번 반송한다. 시간은 서버 값으로 바꾸고 인물 위조·잘못된 채널/길이/문자는 거부한다. 빈 문구는 전송하지 않는다. `evidence:guess`(대체 서버 정책)

[매뉴얼 통신 규칙](../manual/03-communication.md)은 같은 스폿, 같은 그리드의 같은 부대, 전술 중 같은 진영을 설명한다. CD에 있는 전체/동진영 버튼을 전략 화면에서 허용하는 위 정책 전체를 매뉴얼 규칙으로 확정하지 않는다. 2004년 12월 이후의 8채널 기능도 별도 미완료다.

## 한글 변환

전략 채팅 전송은 UTF-16 편집값을 ANSI CString으로 만든 뒤 일본어 CRT 변환으로 되돌린다. `00516e3b`(그리드), `00516e5a`(스폿)의 두 호출을 현재 Windows ACP의 strict 변환으로 바꿔 ACP 949 한글을 보존한다. 수신은 기존 Unicode 풀 보완을 사용한다. `evidence:client`

채널 버튼도 UTF-16 리터럴을 MFC의 ANSI 문자열로 바꾼 뒤 `0051603f`에서 일본어로 해석한다. CP949에서 원문 일부가 이미 `?`로 유실되므로 같은 ACP 변환 결과와 세 리터럴을 대응시켜 전체·함대·동진영으로 표시한다. 다른 문구에는 일반 ACP 변환을 사용한다. EXE 해시와 각 호출 위치의 원바이트 검사는 유지한다. `evidence:client`(원래 경로) / `evidence:guess`(한국어 대응)

## 확인과 한계

- 프로토콜 경계·잘못된 길이/채널/Unicode, 현재 소속에 따른 전체/진영/함대 필터, 다른 그리드/세대 분리, 이동/탈퇴/접속 종료, 인물 위조 검사를 통과했다. 암호화된 두 합성 접속의 한글 왕복·단일 반송·빈 값 처리·후속 통신 검사와 기존 스폿 채팅 회귀 검사도 통과했다.
- x86 호환 모듈 빌드와 다른 EXE의 설치 거부 검사를 통과했다.
- 비활성 데스크톱의 실제 CD 클라이언트 하나와 같은 진영의 합성 상대 하나로 확인했다. 실제 입력란에서 전체 채널의 `한글 왕복 ABC 日本`, 동진영 채널의 `동진영 채팅 확인`을 Enter로 보내고 상대가 받은 UTF-16 코드 단위를 원문과 대조했다. 본인 반송과 상대의 `한글 답장 확인` 표시, 채널 버튼 한국어 표시, 전송 뒤 접속 유지를 확인했다.
- 입력값은 [IME 구성요소 시험](../l10n/native-input.md)의 Windows IMM 컨텍스트/이벤트 드라이버로 만들었다. 송신 변환·패킷·서버·수신 표시를 시험 훅으로 대체하지 않았다. 실제 자모 키 조합·후보창·조합 확정 Enter/전송 Enter 분리는 여전히 미확인이다.

기록은 `work/grid-chat-20261027/`의 `native-02`, `probe-02.log`, `peer-03.log`, `reply-03.png`, `faction-03.png`다. 첫 상대 로그의 비 ASCII 출력 인코딩 문제는 후속 로그에서 코드 단위의 ASCII 16진수 출력으로 보완했다. 원본 해시 불변·소유 클라이언트 종료·오디오 복구도 확인했다.

함대 채널의 실제 원본 조작, 두 원본 동시 실행, 다른 진영의 서로 다른 스폿에서 전체 채팅을 받을 때 발신자 이름 캐시, 전술 전환과 8채널 UI, 모든 입력칸과 실제 스폿 한글 송신은 완료 범위에 포함하지 않는다.
